# 大范围重构：勘测与验证

## 何时使用

出现以下任一情况时使用：

- 任务**范围很大**（跨多个包／多个文档体系／整个子系统），一次改不完；
- 成果**大部分是判断**（哪些留、哪些删、该怎么分），而不是写码；
- ⭐ 需要开发者**反复回答同一类问题**（"这个要不要""那个算不算"）⇒ 已经开始"一步三问"；
- ⭐ 任何**"判定"要落到不可逆的地方**（删文件、改历史文本、改门禁判据）。

⛔ **不适用**：单点修复、单一局部改动、行为可被现成电池直接验的活。

---

## 核心原则（一句话）

> ⭐ **质量不取决于"AI 多聪明"，而取决于两件事：**
> **① 开发者的意图被完整取到 ② 错误被另一个会话独立抓出来。**
> ⇒ 这两件都**不依赖开发者持续在线**，所以能被制度化。

---

## 一、⭐ 把"开发者的问题"当一等输入（本技能的**最高杠杆**）

### 为什么

开发者观察出的问题，**承载着文档与代码里没有的设计意图**。
⇒ **一个问题提出后，就是一份不可再生的资产**；丢了它 = 丢了意图。

⚠️ **但也因此**：⛔ **不许把"开发者的口吻"和"AI 的推断"混在一起记**。
混起来 = 制造假边界（本项目已实测：AI 把自己的模型写成裁定，被引用了几轮才被当面否掉）。

### 做法：出**问题账**（`docs/QUESTIONS_LEDGER.md`）

每当你（开发者）**提出一个问题**，就登记一行：

| 字段 | 内容 |
|---|---|
| `Q-###` | 稳定编号 |
| **原话** | ⭐ **逐字**（⛔ 不许改写成我的理解） |
| **我的解读** | ⭐ **必须单独一栏**，并标注"这是我的解读，⛔ 不是你的意思" |
| **现状** | 已答 / 待答 / ⛔ **答不了（为什么）** |
| **落到了哪** | 设计文档 / 裁定 / 技能 / 台账 / `无` |
| **它属于哪一类** | 见下 |

**四类**（分类的目的：让"问题"能路由到正确的出口）：

| 类 | 特征 | 出口 |
|---|---|---|
| **意图型** | "我想要 X 变成什么样" | → 设计文档（标 `构想`） |
| **判断型** | "X 该不该 Y" | → 裁定点（⛔ 必须你拍） |
| **边界型** | "X 和 Y 的界线在哪" | → 设计文档 ＋ `GLOSSARY` 词条 |
| **担忧型** | "我怕 X 会出问题" | → ⭐ **风险登记**（＝一条将来要复算的判据） |

⭐ **"答不了的"必须显式登记** —— 它是**当前体系的边界**，也是最有价值的产出之一
（本项目实例：`跨包的设计该住哪` 我一开始答不出，登记后它变成了整个设计体系的核心问题）。

### 硬规则

1. ⛔ **原话与解读必须分栏**（同一条记录里）。
2. ⛔ **不许把"解读"升格为规则** —— 要升格必须**开发者明说**。
3. ⭐ 每次大任务的**起点** = 重读问题账里"待答 / 答不了"的那些（它们常常就是下一批活）。

---

## 二、⭐ 开发者不在场时的协议（防"懈怠 ⇒ 降质"）

> ⛔ **这一节是本技能最要紧的一节**：它防的不是"AI 偷懒"，而是**"AI 替你决定"**。

### 三条资格判据（**任一满足**才可以继续做）

1. ⭐ **可逆** —— 做完能干净撤回（新文件、生成物、只读勘测、可 `git revert` 的改动）
2. ⭐ **可机械判定** —— 对错由**命令的读数**决定，⛔ 不由我的判断决定
3. ⭐ **可自证** —— 交付物**自带一条验证命令**和"通过长什么样"

### ⛔ 三条禁令（**你不在场时一律不做**）

1. ⛔ **不替你做选择**（裁定）
2. ⛔ **不删任何东西**（文件、条目、历史文本）
3. ⛔ **不改任何已有门禁的判据**

### ⭐ 每个裁定点必须带**默认值**

给你回话时，**不要只给选项**，而是：

```
裁定点：<一句话>
候选：甲 … / 乙 …
代价：甲 = … · 乙 = …
我建议：甲
⭐ 默认（你不回话时会发生什么）：<具体动作，且必须是可逆的那个>
```

⚠️ 依据（本项目已实测）：**"只给选项"会逼你每次都必须回话**；
带**默认值**时，你不回话 ⇒ 系统**停在安全值上继续推进可逆的部分**，⛔ 不空转、⛔ 也不乱动。

## 三、⭐ 勘测的五条纪律（这轮实测**每条都抓到过真错**）

| # | 纪律 | 本轮它抓到了什么 |
|---|---|---|
| 1 | ⭐ **凡数字必须能指向一次"当场复算"**，⛔ 不指向"我记得" | 我引了一篇**已被取代的论文版本**当依据，并据此定了"根文件 15–40 行"这把尺子 |
| 2 | ⭐ **"缺乏 X"这类断言，先读最新那一份** | 我把 `D-556`…`D-567` 误判为"编号被引用但无定义"（grep 口径太窄） |
| 3 | ⭐ **区分「测量 / 推断 / 未核实」三种标记**，不许混 | 我把自己两条"自证"写成了实测 —— 复核时**拿不出当场证据**，只能降级 |
| 4 | ⭐ **作者 ≠ 复阅者** | 独立会话从**同一批原始件**出发，抓出**我三个数错**、**6 条我漏掉的危险件**、**2 个不可复现的断言** |
| 5 | ⭐ **勘测命令本身要"反向验一次"**：拿一个**你已知答案**的输入跑它，或者**换一种口径再算一遍**，两边对不上就先怀疑命令 | ⛔ **我编出了一个不存在的地基**：`awk '/^## D-/'` 只认 `##`，而 `D-167..D-498` 这 **332 条**标题用的是 `###` ⇒ 静默跳过 332 条，造出「`D-166` 罩 **17,437 行 = 62%**」这个假数，而我拿它当"施工第 0 步地基"写进了定稿草案。真值 **124 行** |

⭐ **第 4 条要有牙齿**：复核会话必须
㈠ **看不到原作者的推理**（只拿原始件）㈡ **自己重建口径**（⛔ 不接受现成清单）㈢ **只能说"验真/证伪/没核"**，⛔ 不许只复述。

### ⛔ 第 5 条的展开：**"硬编码钉法"搬进数据分析**（这是独立失效模式，⛔ 不是门禁那个的重复）

「门禁硬编码路径 ⇒ 搬了目录之后 matches 0 files ⇒ **静默变绿**」—— 这条全项目都知道了。
但**同一族的第二个变体没人防**：

| | 门禁里的硬编码 | ⛔ **勘测/分析里的硬编码** |
|---|---|---|
| 症状 | 断言没执行却报绿 | 命令跑得通、有输出、**数字自洽** |
| 可发现性 | ⭐ 还算好：至少会打印 `matches 0 files` / `pass=0` | ⛔ **更难**：没有任何异常信号，你就是拿到一个**像真的的数** |
| 后果 | 边界形同虚设 | ⛔ **假前提被写进"定稿草案"，变成后续所有施工的地基** |
| 防法 | 人口下限 / 断言自证 | ⭐ **反向验一次**：换口径复算、或拿已知答案的输入试跑 |

**本轮完整链条（值得记形状）**：
```
硬编码 `^## D-`  →  静默跳过 332 条  →  一个自洽的假数（17,437 行 / 62%）
   →  写进勘测件（11,820，也是错的，错法不同）
   →  复核会话**用另一条同样只认 `##` 的命令**去"证实"它 ⇒ 两边都错、互相背书
   →  进入定稿草案 §A-1，被列为"施工第 0 步地基"
   →  ⭐ 只有"开工时真的去复算第一刀"才把它挖出来
```
⚠️ **注意最后两行**：复核**没能**拦住它 —— 因为复核者复用的是同一个错误假设（都以为决策标题是 `##`）。
⇒ ⭐ **对抗性复核的盲区**：它擅长抓**推理错**，抓不住**双方共有的口径错**。
⇒ 唯一可靠的兜底 = **施工时对第一条读数做一次实算**，⛔ 别信"草案里已经写死了"。

## 四、流程（大任务的固定骨架）

```
开发者提问（Q-### 入账）
   ↓
① 只读勘测   ← ⛔ 零改动。产出：读数 + 边界 + 未查清单
   ↓
② 出草案     ← 明确标"待裁"；每个裁定点带默认值
   ↓
③ ⭐ 对抗性复核（另一个会话，看不到①②的推理）
   ↓
④ 按复核结论改草案 → 才动手
   ↓
⑤ 交付时自带验收命令（"你自己怎么确认它对"）
```

⚠️ **第 ③ 步必须默认执行**，⛔ 不是"有空才做"。
**本轮证据**：若跳过第 ③ 步，会拿一个**55% 准确率**的分堆结果去**改 2,700 行历史文本**。

## 五、大重构特有的三个坑（本轮实测）

| 坑 | 症状 | 防法 |
|---|---|---|
| **读数会腐烂** | 同一个数在几小时内从 `0` 变成 `28`（仓外环境件被重置） | ⭐ 数字**写进文档时同时写口径**；引用前**重跑** |
| **"净增 0"变成不做事的借口** | 预算额满 ⇒ 为了加一行而硬塞进一个既存标题，结果名字是从行数压力里挤出来的（`AGENTS.md` 里的"准入尺子"就是活样本） | ⭐ 判据换成"**删了会不会做错**"，⛔ 不用行数 |
| **支线无限张开** | 每个新发现都直接挤进主队列 | ⭐ **入口闸**：新条目必须回答"它怎么降低『从改一行到知道对不对』这个数"，答不出 ⇒ **挂账** |

---

## 六、边界（⛔ 本技能**不能**做什么）

1. ⛔ **不能替你产生问题** —— 技能只是**接住**你的问题，⛔ 不假装能观察出设计意图
2. ⛔ **不能替你裁定** —— 它给你**更好的选项和默认值**，不给结论
3. ⛔ **不能保证"没你在场也全对"** —— 它只能保证**不在你不在场时乱动**
4. ⛔ **不是规则** —— 本技能里没有一条是"必须遵守的规范"。
   它**不挂在任何门禁上**，**删掉它不会让任何东西失败**（⛔ 故意如此）。
   它的有效性**只来自两点**：① 让开发者**少回话** ② 让错误**被另一个会话抓住**。
