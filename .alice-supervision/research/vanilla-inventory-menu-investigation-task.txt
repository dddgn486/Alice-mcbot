# 原版 InventoryMenu（玩家背包菜单）源码深度调研

## 调研目标

Alice 的 BotInventoryMenu 本质是"查看一个玩家实体（Bot）的 36 普通槽 + 4 装备槽 + 主手/副手背包"。最贴近的成熟实现是 Minecraft 原版 `InventoryMenu`（玩家自身背包菜单）和 `PlayerInventoryScreen`（inventory.png 背景）。本调研深入这些**原版源码**，彻底搞清槽位布局、quickMoveStack、clicked、以及 inventory.png 背景渲染的正确实现，让 Alice 直接复用其结构而非自创。

## 问题背景

**已连续 3 次尝试失败**：
- `f0ef6fc`：用 generic_54 纹理 + 自定义 4x9 坐标 → 槽位与背景错位、装备槽未渲染
- `f4bf79a`：改自绘纯色面板 → 面板不显示、拿取物品消失
- `25b1daa`：修复 renderBackground 时序 + quickMoveStack 返回 original → **拿取物品仍消失**、新增"放入显示两倍"、布局混乱（"Bot"标题截断、"物品"标签同色、槽位稀疏错位）

**用户报告**（2026-08-23 03:08 截图 `/mnt/d/JAVA_projects/alice/.alice-supervision/client-tests/f0ef6fc-bot-inventory-gui/evidence/放入物品前*.png`、`放入物品后.png`）：
- 从 bot 拿取物品立刻消失（核心交互失败）
- 放入 bot 物品栏时物品显示成两倍
- GUI 文字与背景同色（标题/标签不可读）
- 槽位格子分布稀疏错位，无标准背包布局

**当前实现**（`BotInventoryMenu.java`，25b1daa）：
- 自绘面板 + 自定义槽位坐标（armor y=8..62、offhand x=77 y=62、main y=84..、hotbar y=142，玩家槽 y=180/238）
- `quickMoveStack` 参考 ChestMenu（original.copy、moveItemStackTo、slot.set）
- `BotInventoryScreen` 用 `graphics.fill` 自绘面板（imageHeight=274）

## 关键问题

1. **为何拿取物品仍消失？** quickMoveStack 虽参考 ChestMenu 语义，但 Alice 的 Bot Slot 绑定的是 `bot.getInventory()`（Inventory，非 Container）。原版 `PlayerInventoryMenu` 的 Slot 也绑定 Inventory，为何能正常？差别在哪（Slot 子类？`getItemSlot` 复制？`InventoryMenu` 用 `Slot` 还是自定义子类？）
2. **为何放入显示两倍？** moveItemStackTo 的 source/dest 若都是同一个 Inventory 对象（bot 的）会复制；但 Alice 用 bot + player 两个不同 Inventory，理论上不该两倍。是客户端渲染问题（槽位被注册两次？）还是服务端移动逻辑（moveItemStackTo 重复）？
3. **布局为何混乱？** 自绘面板 + 自定义坐标是否与 vanilla inventory.png 布局冲突？标题/标签渲染为何截断/同色？
4. **正确做法**：Alice 是否应该**完全复用原版 `InventoryMenu` 的结构**（它本来就是"玩家背包"的权威实现），仅把数据源换成 bot 的 Inventory？给一个直接可用的方案。
