## 用户批准的 P0 功能

### P0-A Forge GameTest 分层

在 Alice 已配置的 `gameTestServer` 基础上，新增最小、可重复、服务端自动化的调试 fixture：

1. FakePlayer/BotPlayer 物理事实：
   - `isPushable` / `canCollideWith` / AABB
   - 推挤或伤害前后的 `deltaMovement`、health、`hasImpulse`
2. FakeConnection recipient packet 事实：
   - 不只断言 bot 自己的 connection
   - 断言真实观察者是否收到允许类型的同步包
3. GUI 未来重启前的纯函数契约：
   - viewIndex → logical slot → underlying inventory slot
   - snapshot revision/fingerprint stale rejection

GameTest 只证明服务端状态，不能替代 Windows 客户端物理、GUI、渲染验收。

### P0-B `minecraft-modding-mcp` 开发期静态源码/映射校验

- 候选：`adhi-jp/minecraft-modding-mcp`，MIT，固定检查点 `2c673ad`
- 仅开发机/Agent 工具，读取 Alice 的实际 ForgeGradle/Parchment 缓存
- 仅用于源码、mapping、Jar、Mixin/AT 静态校验
- 不加入 Alice mod runtime，不放发布 jar，不开放不受控远程 endpoint

### P0-C 结构化双端诊断日志与 packet correlation

仅开发期、只读诊断：统一 schema 关联：
- server state（bot UUID/entity id/tick/position/velocity/task）
- recipient packet（packet simple name/recipient UUID/direction）
- client-visible evidence reference（由 Windows 测试报告记录）

默认 packet 类型白名单，采样/限额；不得记录玩家文本、全量 NBT 或完整 inventory 数据。目标是形成“服务端状态 + recipient packet + 客户端可见证据”的可证伪闭环。
