## 背景（P1-S1 已确认的事实）

- dsh-mcp-client 插件已随 DSH 安装（`@deepseek-ai/dsh-mcp-client@0.1.1-rc.2`，MIT）
- 从 profile patch 即可引用（flat fallback 符号链接 `profiles/node_modules/@deepseek-ai/dsh-mcp-client` → DSH 安装内，require.resolve 已实测成功）——**无需修改 DSH checkout 或 profile node_modules**
- 工具命名规则：`mcp__<serverName>__<rawName>`（+SHA-256 规范化）
- transport：stdio（env scrubbing）/ streamable-http
- 当前 3082/3083/3081 均无 MCP 条目；`alice-bus-lab` 是"隔离 lab profile + disabled 条目"的现成实验模板
- **接线点存在但行为未实测** → 本任务即 V-B dry-run 实测

## 任务目标（V-B）

在**新建独立 lab profile**（不得触碰 alice-bus 3083 / alice-bus-lab 3082 / web 3081）中挂载一个**最小 stdio MCP server**，实测：

1. 工具是否以 `mcp__<serverName>__<rawName>` 出现在该 profile 会话工具清单；
2. 卸载（`disabled: true` 或删除条目）后工具清单是否恢复、无残留后台进程/localhost 监听；
3. 全程不触碰现有三个 profile 配置与部署端口；
4. 按规划 §3.1 判定标准给出最终等级：可行（隔离 profile） / 部分可行 / 不可行。

## 执行方法（严格限定）

1. **新建隔离 profile**：克隆 `alice-bus-lab` 模板或新建 `alice-mcp-lab`（独立 storage、独立端口如 3090，本地仅 127.0.0.1）。**绝不修改** `alice-bus`(3083)、`alice-bus-lab`(3082)、`web`(3081) 的任何文件。
2. **挂载最小 stdio server**：官方 `@modelcontextprotocol/server-everything`（只读部分）或 echo 型 stdio server；`serverName` 示例 `gitlab`（或 `mcp-test`），配置参考 dsh-mcp-client README 第 9-30 行（`- id: mcp-xxx / name: '@deepseek-ai/dsh-mcp-client' / config: {transport: stdio, command, serverName}`）。
3. **观察**：启动隔离 profile → 检查会话工具清单是否出现 `mcp__<serverName>__<rawName>` 形式的工具 → 尝试调用 1 个只读工具（如 echo/ping 类）→ 记录返回。
4. **卸载与回滚**：`disabled: true` 或删除条目 → 工具清单恢复原样、无残留进程/监听（`ss -ltnp` 检查 3090 及 spawn 子进程）→ 关闭 profile → 清理临时文件。
5. **记录**：全程记录 启动命令、profile 名/端口、patch 条目、工具清单快照（before/after）、调用返回、卸载后检查、日志关键行。

## 禁止事项（硬性）

- **绝不修改** DSH checkout（`/home/fb486/.nvm/.../@deepseek-ai/dsh/`）、`alice-bus`/`alice-bus-lab`/`web` 三个 profile 的任何配置、3082/3083/3081 端口与运行实例。
- 不挂载真实 Git MCP server（那是 P1-S2，本任务只验证挂载机制，用最小 echo/everything server）。
- **零 env 注入**：stdio 配置不注入任何 API key/token/敏感路径（README 示例的 token 属反例，禁止照抄）。
- 不下载/安装任何工具超出官方 server-everything 或 echo 型最小 server（仅用于 dry-run，不进入任何 profile 的长期配置）。
- 挂载失败/异常时**立即停止并如实报告**，不强行重试到改配置。

## 停止条件（触发即停，判定不可行）

- 挂载必须修改 DSH checkout 或任一现有 profile node_modules → 停，判定不可行。
- 需要重启/变更 3083 环境或影响现有端口 → 停。
- 证据显示挂载会读取项目外敏感路径 → 停。
- 卸载后工具清单未恢复、残留进程/监听 → 停，报告并给出清理证据。
