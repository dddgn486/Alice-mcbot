# MCP 服务器与开发工具深度调查任务

- 任务类型：深度调查（联网 + 工具评估）
- 提出人：用户
- 日期：2026-08-24
- 优先级：高（立即派发）

## 调查目标

评估是否有现成工具（MCP 服务器、调试工具、测试框架等）可以改善 Alice 项目的开发效率和测试质量。

## 必须回答的问题

### 1. MCP 服务器（minecraft-mod-mcp 或其他）
- **MCP 服务器是什么**？（Minecraft Coder Pack / Model Context Protocol / 其他？）
- **适用于 Forge 1.20.1 开发吗**？
- **核心功能**：
  - 反编译/反混淆（查看 Minecraft/Forge 源码）
  - 运行时调试（断点/变量查看）
  - 热重载（代码改动无需重启）
  - 测试框架（自动化测试）
  - 其他功能
- **如何集成到 Alice 项目**？
- **收益评估**：能解决当前哪些问题？
  - FakePlayer 物理调试（查看 `Entity.push()` / `LivingEntity.hurt()` 调用链）
  - GUI 调试（查看 `AbstractContainerMenu` 的 slot 状态）
  - 客户端/服务端同步调试（查看 Packet 发送/接收）
- **成本评估**：配置复杂度、学习曲线、维护成本

### 2. Forge 开发工具生态
- **Mixins 调试工具**（查看 Mixin 注入点、运行时字节码）
- **Packet 监视工具**（实时查看客户端/服务端包交互）
- **GUI 调试工具**（查看 Container Menu 的 slot 状态）
- **Entity 可视化工具**（实时查看 Entity 位置/速度/碰撞箱）

### 3. 测试框架
- **Minecraft 单元测试框架**（是否有成熟的 mod 测试框架？）
- **客户端自动化测试**（是否能自动化 GUI/物理测试？）
- **Fixture 模式改进**（Alice 当前 selftest 是否有更好的替代？）

### 4. 开发辅助工具
- **代码生成工具**（如 DataGen for recipes/tags/models）
- **性能分析工具**（Spark / JProfiler / 其他）
- **日志增强工具**（结构化日志/过滤/搜索）

### 5. 其他工具（开放式调查）
- 除了 Skill / MCP / 上述工具，还有哪些工具能帮助：
  - 减少调试时间（当前问题：FakePlayer 物理失效、GUI 失败）
  - 提高测试覆盖率（当前问题：服务端 PASS 但客户端 FAIL）
  - 改善开发体验（当前问题：多轮试错、回退测试）

## 外部调研要求

必须使用 `web_search`，至少查询：
1. `minecraft mod development MCP server Forge 1.20.1`
2. `Forge mod debugging tools packet inspector GUI debugger`
3. `Minecraft mod unit testing framework automation`
4. `FakePlayer physics debugging Forge 1.20.1`
5. `Minecraft entity collision debugging tools`

优先参考：
- Forge 官方文档（https://docs.minecraftforge.net）
- CurseForge / Modrinth 的开发者工具 mod
- GitHub 上的 Forge 开发辅助项目
- Minecraft 开发者社区（Reddit r/feedthebeast / Discord）

## 输出要求

1. **工具清单**：每个工具的名称、用途、适用场景、集成方式
2. **收益评估**：能解决 Alice 当前哪些具体问题（FakePlayer 物理/GUI 失败/同步问题）
3. **成本评估**：配置复杂度（简单/中等/复杂）、学习曲线（天/周/月）、维护成本
4. **优先级排序**：哪些工具应该立即接入、哪些可选、哪些不推荐
5. **集成方案**：如何集成到 Alice 项目（Gradle 配置/IDE 插件/运行参数）
6. **风险与限制**：工具的已知问题、不适用场景

## 禁止事项

- 不修改代码、计划、HANDOVER 或客户端证据
- 不运行 Alice 实现测试
- 不把调研结论直接转成开发授权
- 不推荐过时/不维护的工具（检查最后更新时间）

## 证据标准

- 必须引用工具的官方文档或 GitHub 仓库
- 必须检查工具对 Forge 1.20.1 的支持状态
- 必须对比至少 2-3 个同类工具（如 Packet 监视工具：X vs Y vs Z）
- 外部案例需验证版本一致性（不能拿 1.12.2 的工具说适用 1.20.1）
