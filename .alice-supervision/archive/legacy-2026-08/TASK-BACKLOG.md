## 🐛 **紧急问题修复**

### ✅ P0 - 自动伐木卡死问题（已修复 + 清障集成）
**问题描述**:  
自动伐木遇到问题原木时，不会放弃整棵树，一直重试

**日志证据**:
1. **PathExecutor 卡住**：`路径执行失败: 卡住 81 tick`
2. **高原木挖不到**：`stand_search_limit(所有候选站位未完成搜索)`
3. **视线受阻**：`mine 失败(视线受阻): 保持站位，等待清障`
4. **玩家反馈**：
   ```
   <Dev> 卡住了
   <Dev> 他遇到了第二层就是树叶的树要先挖树叶，才哇得到第一个木头
   <Dev> 帮忙打掉树叶就开始动了
   ```

**根因分析**:
- ContinuousLumberTask 对单个原木失败的处理不当
- **没有清障逻辑**（MineTask 有，但 ContinuousLumberTask 没有）
- 没有"整棵树失败"的判断逻辑

**解决方案（已完成）**:
- [x] 添加单个原木失败计数器 `currentLogFailures`
- [x] 连续失败 3 次，标记整棵树为无效
- [x] 添加树木黑名单 `invalidTrees`（basePos）
- [x] 跳过黑名单中的树，扫描下一棵
- [x] **集成 MineTask 的清障逻辑**（核心修复）
  - 添加 `findDirectBlocker()` - 查找视线障碍物
  - 添加 `raycastBlock()` - 射线检测
  - 添加 `isHardFailure()` - 判断不可恢复的失败
  - 视线受阻时自动清障（最多 2 层）
  - 清障完成后继续挖原目标

**修改内容**:
1. 新增字段：
   - `invalidTrees` - 无效树木黑名单
   - `currentTreeBasePos` - 当前树基座
   - `originalTarget` - 原始目标（清障时保存）
   - `currentLogFailures` - 失败计数
   - `clearDepth` - 清障深度
   - `MAX_CLEAR_DEPTH = 2` - 最大清障深度
   - `MAX_CLEAR_REACH = 4.5D` - 最大清障距离

2. 砍伐阶段改进：
   - 检测硬失败（unbreakable/lava/protected）→ 跳过
   - 检测视线受阻 → 查找障碍物 → 清障
   - 清障完成 → 恢复挖原目标
   - 清障失败或达上限 → 增加失败计数
   - 失败 3 次 → 放弃整棵树

3. 清障流程：
   ```
   视线受阻 → findDirectBlocker()
            → 找到障碍物 → 安全检查
            → 通过 → clearDepth++
            → 记录 originalTarget
            → 挖障碍物
            → 完成 → 恢复挖 originalTarget
   ```

**预估时间**: 1 小时  
**实际时间**: 1.5 小时（含清障集成）  
**优先级**: 🔥 P0  
**状态**: ✅ 已完成（待测试）

### 🔥 P1 - 掉落物拾取是瞬移
**问题描述**:  
当前掉落物拾取使用 `item.playerTouch(bot)` 直接瞬移拾取

**当前实现**:
```java
// ContinuousLumberTask.java
level.getEntitiesOfClass(ItemEntity.class, collectArea)
    .forEach(item -> {
        if (bot.distanceToSqr(item) < 4.0) {
            item.playerTouch(bot);  // ← 瞬移拾取
        }
    });
```

**需要的功能**:
- [ ] Bot 主动移动到掉落物位置
- [ ] 使用 A* 寻路到掉落物
- [ ] 支持多个掉落物的优先级排序（最近的优先）
- [ ] 拾取失败时跳过

**解决方案**:
1. 创建 `ItemCollectorTask` 独立任务
2. 使用 PathExecutor 移动到掉落物
3. 到达后触发拾取

**预估时间**: 2-3 小时  
**优先级**: 🔥 P1
