## 使用方式

一次完整客户端会话连续测试 A1-A9；不为每个场景重启客户端或复制日志：

```text
.alice-supervision/client-tests/49be37e-a1-1/evidence/
  evidence-report.md
  latest.log
  debug.log
  A1-permission-command/
    evidence-report.md
    A1-command-output.png
  A2-normal-transfer/
    evidence-report.md
    A2-source-before.png
    A2-destination-after.png
```

根目录 `evidence-report.md`、`latest.log`、`debug.log` 是本轮唯一的总表单与完整日志。总表单（测试日期、Windows Git SHA、环境、request UUID、item/count、总体结果、用户总体决定）只填写一次；场景目录只填写本场景“是/否”观察并放置专用截图；不同场景截图不得混放。开始测试前，用真实截图直接覆盖同名的零字节 `.png` 占位文件；审核时空占位文件不算证据。

## 简化场景矩阵

| ID | 场景目录 | 最少动作 | 核心观察 | 最少证据 |
|---|---|---|---|---|
| A1 | `evidence/A1-permission-command/` | 用权限 2 执行一次合法命令，再执行一次非法输入 | 权限/参数 gate，拒绝时库存不变 | 场景表单、`A1-command-output.png` |
| A2 | `evidence/A2-normal-transfer/` | 执行一次完整单批转移 | source 减少 N、destination 增加 N、无自动重试 | 场景表单、前后箱子截图各一张 |
| A3 | `evidence/A3-in-transit/` | 在 source leg 后、destination leg 前观察一次 | status 为 `IN_TRANSIT_BOT`，location 为 `BOT_INVENTORY`，Bot 持有 N | 场景表单、Bot/在途截图一张 |
| A4 | `evidence/A4-capacity-rejection/` | 让 Bot 或目标箱无法容纳完整数量后执行命令 | `capacity_rejected`，source delta 为 0 | 场景表单、源箱前后截图各一张 |
| A5 | `evidence/A5-destination-conflict/` | 转移中改变目标箱一次 | `simulation_conflict` 或 discrepancy；不自动重试，余量位置可解释 | 场景表单、目标/Bot结果截图一张 |
| A6 | `evidence/A6-hazard/` | 转移移动阶段触发一次危险中断 | `SUSPENDED`、稳定 survival code、正确 location；不自动恢复 | 场景表单 |
| A7 | `evidence/A7-restart/` | 在途时停止并重启一次服务端 | `SUSPENDED/manual_takeover_required`；不自动继续写入 | 场景表单；共用完整日志 |
| A8 | `evidence/A8-abort/` | 分别 abort 未抽取请求和在途请求 | 未抽取可 `ABORTED`；在途保持 `SUSPENDED/BOT_INVENTORY` 且不改库存 | 场景表单、在途 abort 后截图 |
| A9 | `evidence/A9-chest-gui/` | 打开一次普通原版箱子 GUI | GUI 保持原版，无 Alice 拦截或额外写入 | 场景表单、GUI 截图一张 |

## 共用停止条件

出现无法解释的物品数量变化、自动 retry/resume/finish-insert、受保护任务被替换、错误端点写入、GUI 拦截、崩溃或卡死时立即停止。保留该场景目录、完整日志和世界副本，不重试已发生变异的请求。

所有需要填写的字段（测试日期、Windows Git SHA、环境、item/count、request UUID、各场景结果汇总、异常、用户总体决定）只填写在 `evidence/evidence-report.md`，不在此文件重复填写。
