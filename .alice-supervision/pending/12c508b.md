## Objective

为 A1.1 转移测试增加一个独立的游戏内实体测试物品入口：手持 `alice:transfer_endpoint_selector`，右键点击容器=选择转移目标（destination），Shift+右键=选择源容器（source）；选择只写入服务端内存草稿；转移仍由显式命令 `/alice transfer-selection submit <item> <count>` 发起并复用既有 `BotManager.assignTransfer` 同一 admission。目的是消除测试员反复输入长坐标的负担，不改变任何转移语义。

## User-Approved Decisions

1. 物品命名：`alice:transfer_endpoint_selector`，贴图引用 `minecraft:item/stick`（木棍）。原因：用户批准「指南针/木棍」二选一，而 `compass_00` 已被既有 `soft_path_probe_selector` 占用，必须避免工具贴图冲突；已核对既有工具贴图占用（diamond_shovel/interface_scanner、diamond_hoe/road_planner、golden_axe/soft_move_selector、compass_00/soft_path_probe_selector、diamond_axe/target_selector）。
2. 右键映射：右键=destination；Shift+右键=source。
3. 提交命令：`/alice transfer-selection submit <item> <count>`，另含只读 `status` 与 `clear` 子命令。
4. item/count：由命令提供，物品 NBT 不携带；但 `/alice transfer-selection submit` 中 **item 与 count 均可省略**，使用默认值：
   - 省略 item：默认取源容器内按槽位顺序的第一种可转移物品；该物品必须满足 A1.1 约束（注册的原版 `namespace:item`、默认无 NBT/components），否则返回 `default_item_unavailable` 并要求显式指定。
   - 省略 count：默认取该物品在源容器内的总数（该物品种类全部移走）；显式 count 仍为正整数并保持 A1.1 校验。
   - 默认值仅存在于 `transfer-selection` 便利路径；`/alice transfer-test` 保持显式 `namespace:item` + positive count 不变。默认 item/count 不写入物品 NBT。
5. 草稿策略：服务端内存、按玩家 UUID、2,400 ticks 超时自动失效；提供 `status`/`clear`；非持久，重启即失效；提交成功后自动清除。
6. 权限：`useOn` 服务端分支 `hasPermissions(2)` + 提交命令挂在 `requires(hasPermission(2))` 下；物品仅通过原版 `/give`（受 permission 2 约束）发放；不做 owner/admin/ACL。

## Required Architecture

1. 选择是测试输入便利层：草稿不构成预留、不构成权威事实、不写 ledger；世界漂移由既有机制兜底（提交时 `TransferRequest` 构造校验 + primitive 每次写入前重验 + fresh pre）。

4. 草稿 source/destination 第二次选择时校验 same-endpoint（同坐标拒绝、不覆盖）与 cross-dimension（拒绝）；提交时构造器兜底。
