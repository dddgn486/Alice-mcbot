### F3. 门禁的「警告」档没有统一机制 —— 新门禁极易写成"红"

**[✅ 开发者决策：采纳]**（2026-10-05）

#### 问题核心

申请逐字：`run_gate()` 把**任何非零退出码都记 FAIL**，而 **WARN（退出码 2）只在 3 个专用函数里**

本轮申请作者第一版新门禁就踩了：挂 `run_gate` ⇒ 警告变红

#### 外部系统的做法

| 系统 | 警告的实现 |
|---|---|
| **Linux Kernel `checkpatch.pl`** | 退出码 0（通过/警告），退出码 1（错误） ⇒ ⚠️ **警告不影响退出码** |
| **Rust `cargo clippy`** | 警告打印但退出 0，`-D warnings` 升级成错误（退出 1） |
| **Python `flake8`** | 警告与错误**不区分**（都是退出 1） ⇒ 靠 `--exit-zero` 强制退出 0 |
| **Chromium PRESUBMIT** | `results.warnings.append(...)` vs `results.errors.append(...)` ⇒ 统一机制 |

⇒ **主流：退出码 0（通过+警告） vs 1（错误），或者统一的 warning/error 收集器**

#### 我的建议

✅ **`run_gate` 支持退出码 2 = WARN**

**理由**：
1. **本仓已经在 3 处用退出码 2**（`run_headless_battery` 等）
2. **统一入口** ⇒ 新门禁不用记"要警告就别挂 `run_gate`"
3. **向后兼容**：存量门禁退出 0/1 不变，只新增 2 的处理

**实操**：
```bash
# check-all.sh 的 run_gate()
run_gate() {
    # ...
    "$@"
    local exit_code=$?
    if [ $exit_code -eq 0 ]; then
        ((pass++))
    elif [ $exit_code -eq 2 ]; then
        ((warning++))
    else
        ((failed++))
    fi
}
```

⚠️ **风险**：存量门禁如果有"偶然退出 2"的（bug 或非标用法），会被误读成警告

**缓解**：逐个检查存量 67 个 `check-*` 脚本，grep `exit 2`
