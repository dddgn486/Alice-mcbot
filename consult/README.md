# 咨询通道（`consult/`）

> ⛔ **本通道没有决策权** —— 它只**收问题**、**收回执**；**真正的裁定永远归开发者**。
> ⭐ **本文件是通道的自述**，⛔ **不参与配对**（它不是一次咨询）。

---

## 一 · 这是什么（用户 2026-10-04 逐字）

> ①「现在我要给项目一个**特殊通道**，把**重难点问题和关键决策问题**等通过文档记录下来，
>    在这个通道里**接受外来技术顾问的建议**，**未收到回执，绝对不能擅自解决相关问题**」
> ②「通道的载体就是**在仓库新加一个目录**，一个子目录放**现状问题文档**，一个子目录放**回执**，
>    **带编号**，**两边必须成对出现**，才能算完成一次咨询」
> ③「这个咨询流程**只能我自己手动让你触发**」
> ④「只要**提交出咨询请求**，就**必须等咨询完成才能继续工作**」
> ⑤「**咨询没有决策权**，但是咨询实际流程是我和顾问**人工交互**的，所以**顾问会标记哪些是开发者决策的**」

⇒ ⭐ **一句话**：**这里放"答不了、且不该由 AI 自己拍的问题"**，⛔ **不放裁定**。

---

## 二 · 形状（⭐ 目录就是协议）

```
consult/
  README.md                        ← 本文件（通道自述，⛔ 不参与配对）
  request/                         ← ① 现状问题文档（**提出方 = 主工作流**）
    <编号>-<短标题>.md
  receipt/                         ← ② 回执（**提出方 = 技术顾问**，经开发者人工转达）
    <编号>-<短标题>.md
```

| 规则 | 值 | 谁的令 |
|---|---|---|
| **编号** | ⭐ **主编号 = 纯序号** `001`／`002`…（⛔ 不挂字母前缀 —— 实测 `A-`/`C-`/`R-`/`K-`/`N-`/`F-`/`S-`/`T-` **全部已被占用**） | 用户 2026-10-04 选「纯序号」 |
| ⭐ **子编号** | ⭐ **可选**：`004.1`／`004.2`…（⛔ **只许 `.` ＋ 数字**，⛔ 不许 `004b` 那种字母写法 —— 一词一义） | ⭐ 用户 2026-10-06 令「**允许用子编号**」 |
| **配对键** | ⭐ **主编号**（⚠️ 键 ⛔ 不含子编号） | 用户令 ② ＋ 2026-10-06 令 |
| **文件名** | `<主编号>[.<子编号>]-<短标题>.md` —— ⭐ **无子编号的那一件**必须**两边同名**；⭐ **带子编号的回执，标题自由** | 用户 2026-10-04「两边同名」＋ 2026-10-06 令 |
| ⭐⭐ **一个申请 ↔ 多个回执** | ⭐ **允许**（⚠️ **主编号必须相同**；⭐ 子编号 = 同一咨询的**第几轮**） | ⭐ 用户 2026-10-06 逐字：「马上修改下门禁，**允许一个咨询申请能对应多个咨询回执**，但是**主编号必须相同**，**允许用子编号**」 |
| **新增咨询** | ⛔ **只能由开发者手动触发**（AI ⛔ 不得自行发起） | 用户令 ③ |
| **提交后** | ⛔ **必须等咨询完成才能继续工作**（＝ `check-consult-pairs` **红**） | 用户令 ④ |

## 三 · ⛔⛔ 硬规则：**未收到回执，绝对不能擅自解决相关问题**

⭐ **它的机械形态 = 门禁 `tools/check-consult-pairs.sh`（挂 `check-all`）**：

| 状态 | 门禁 | 含义 |
|---|---|---|
| 有 `request/001-x.md`，**没有**任何 `receipt/001…` | ⛔ **红** | ⭐ **提交即停工** —— 这一轮不许往下走 |
| ⭐ `request/001-x.md` ＋ `receipt/001-x.md`（**无子编号那件两边同名**） | ✅ 绿 | ⭐ **完成一次咨询** |
| ⭐⭐ `request/001-x.md` ＋ `receipt/001.1-y.md` ＋ `receipt/001.2-z.md` | ✅ **绿** | ⭐ **一个申请 ↔ 多个回执**（⚠️ 主编号必须相同；带子编号的标题自由） |
| 只有回执、没有问题（主编号在申请侧不存在） | ⛔ 红 | 孤儿回执 |
| 同侧「**主编号 ＋ 子编号**」重复 | ⛔ 红 | ⭐ 键是这两者（⚠️ 同主编号**多件回执是允许的**） |
| **无子编号**的回执与申请**标题不同** | ⛔ 红 | ⭐ 用户令「两边同名」保留的那一半 |
| 件名**不带编号**（不匹配形状） | ⛔ 红 | ⭐ 用户令 ② 逐字「**带编号**」 |
| 两侧任一目录缺失 | ⛔ 红 | 通道被搬走／改名 ⇒ **响亮失败** |

⚠️ ⭐ **门禁判不了的那一半（如实说）**：它**看不出来**"有没有人趁回执没到就偷偷把问题解决了"。
⇒ 那一半靠**纪律**（本条 ＋ `AGENTS.md` 的准入规矩），⛔ **不靠门禁** —— ⛔ **别把这条读成"有门禁就万无一失"**。

## 四 · 一次咨询的完整流程

```
① 开发者手动触发            ⛔ AI 不得自行发起
        ↓
② AI 写 consult/request/NNN-<短标题>.md
   ⭐ 内容 = 现状（附可复算命令）＋ 要顾问答的问题（⛔ 不含 AI 的结论）
        ↓
③ ⛔ 提交 ⇒ check-consult-pairs 变红 ⇒ 停工（⛔ 不许推进相关事情）
        ↓
④ 开发者 ↔ 技术顾问 人工交互
        ↓
⑤ 顾问写回执 ⇒ 落到 consult/receipt/NNN-<同名>.md
   ⭐ 回执里**必须标记哪些条目属于「开发者决策」**
        ↓
⑥ 成对 ⇒ 门禁转绿 ⇒ 恢复工作
        ↓
⑦ ⭐ 「开发者决策」那些条目 **回到开发者裁定**（⛔ 咨询不裁）
```

---

## 五 · 回执的填写要求（⭐ 让它可机械判 ＋ 不越权）

1. ⭐ **必须标记**：本次回执里**哪些条目属于「开发者决策」**（⇒ 回开发者裁定，⛔ 咨询不裁）；
2. ⭐ **必须给"依据什么"**（外部系统的做法／本仓已有实践／推演），⛔ 不许只给结论；
3. ⚠️ **答不了的显式写"答不了"**（⛔ 不许略过 —— 本仓最贵那族错是**静默消失**）；
4. ⚠️ **回执不进仓时**：原件位置必须自报「**⛔ 不可复算**」（门禁 `check-e4-offrepo` 会查）。
