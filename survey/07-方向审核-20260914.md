## 3. ★★ 模组适配没有终点线（本次审核最重要的一条）

### 3.1 事实

| 项 | 值 |
|---|---|
| 目标整合包 | **ATM9 = 435 个模组**（`survey/03`） |
| 已适配 | **Mekanism**（S0→S5 全走完）、**Thermal**（S0→S2） |
| 队列中 | Create、ExtendedCrafting（**已在客户端 `mods/` 且静默读不出**） |
| 单模组边际成本（`MOD_ADAPTER_PROTOCOL.md` §6 实测） | 「填表 + 换 1 行目标 + 换 1 个电源造法」 |

### 3.2 判断：**边际成本很便宜，但它是「每模组」成本，而分母是 435**

按当前节奏（数天 1–2 个模组），"把科技模组适配完"是**几个月 + 数千元**，
而且**没有天然停止点** —— 因为**每适配一个模组都像一个可验收、可收口的闭环**。

> ⚠️ **这与台账自我生成是同一个陷阱，只是换了个维度**：
> 从一个"**永远有货**"的收口清单，换成一个"**永远有下一个**"的适配队列。

### 3.3 解法已在蓝图 §1.2 里（且用户自己的实验刚好证明了它）

**蓝图 §1.2「玩家定义的『模拟 AE』」原文**：

> 目标**不是**让 bot 自动理解或搭建任意流水线，而是让玩家把现有半自动流水线**登记**成可执行生产单元，
> Alice 负责按订单**搬运、投料、等待、收产物**和处理可预见异常。

**这条路线是模组无关的。** 登记一条流水线只需要：

- 输入端点 / 输出端点 / 缓存端点
- **插入 / 提取**（标准 capability 就够 ⇒ **C1/C2 级别**）
- 完成判据

**机器自己会干活，Alice 不需要理解它。**

而当前的 **3-B 线**（`MACHINE_ROUTE` / `EXECUTABLE` / `MachineMap`）是**另一条**：
Alice **理解**机器配方并**自己选路线**。这条更强，但**必须逐模组做**。

### 3.4 两条路线的成本曲线对比

| | **§1.2 登记流水线** | **3-B 机器理解** |
|---|---|---|
| 模组相关性 | **无关** | **逐模组** |
| 需要的兼容级别 | **C1/C2** | **C4** |
| 覆盖 ATM9 | **玩家登记什么就覆盖什么** | 需逐个适配 |
| 对应蓝图阶段 | **D** | **E** |
| 成本曲线 | **常数** | **线性 × 435** |

### 3.5 ★ 建议：把模组适配从「覆盖率驱动」改成「需求驱动」

> **规则：只为实际存档里真正用到的东西做适配，不做"这个模组很有名所以适配一下"。**

**理由（回到用户的真实目标）**：

- **工厂是用户自己建的** —— 那是这个品类的乐趣所在，不需要 Alice 替他想
- Alice 该做的是**枯燥那部分**：搬运、投料、收产物、挖矿、伐木
- 这些**登记流水线（§1.2）就够了**，不需要机器级理解
- 机器级理解（3-B）是「Alice 自动建产线」的前置 ⇒ 那是**阶段 F（AE 助理）的终局**，还很远

**⇒ 这条规则直接把"砸钱"变成有界的：开销上限 = 用户实际玩到哪儿。**

> ⚠️ **时效性**：本建议**在 Create/EC 之前**采纳才有效。
> 一旦进入队列，刹车的心理成本会显著上升。
