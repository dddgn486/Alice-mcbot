## §0 一句话

> **把「控制面」搬上云，把「测试面」留在本地。**
> 云端只跑 **DSH agent + 编译**（≈2 核 8 G 够）；无头电池与真人客户端**留在本地**。
> 云端要跑测试时，**用 git 当通知通道**（push 一个 tag），本地一个**笨脚本**拉包、跑、回传证据。

⭐⭐ **最重要的判断**：这样切分，云端**从 16 G 降到 8 G**，而且**测试面一行都不用改**
（`headless-battery.sh` 要的客户端存档 / 上游模组 / 服务端安装，本地**本来就有**）。

## §4 一期：DSH 上云（**部署手册**）

> ✅ **已核实的事实**：DSH = `@deepseek-ai/dsh`（npm **公开包**，`bin: dsh → lib/bin.js`，`latest = 0.1.5-rc.2`，
> 另有 `next` / `alpha` 通道；共 25 个版本）。
> 📋 **用户口述的现状**：`dsh web --port 3081`（GUI）+ `dsh --profile alice-bus --port 3082/3083`；
> 会话在 `~/.dsh/sessions/*`；配置 `~/.dsh/settings.yaml`。
> ⚠️ **未核实**：安装/启动/端口绑定行为（**本方案未在真机上跑过任何一步**）。

### 4.1 前置检查（**每条都有判据**）

| # | 步骤 | 判据 | 状态 |
|---|---|---|---|
| 1 | 非 root 用户 | `whoami` ≠ root | ⚠️ 建议（会话目录权限） |
| 2 | Node 版本 | `node -v` ⇒ **≥ 22.15** | ⚠️ **硬要求**：`tools/dsh-session-log.mjs` 用 `zlib.zstdDecompressSync`（✅ 源文件注明确写）；本机 Node 18 **不够** |
| 3 | npm 可用 | `npm -v` | — |
| 4 | 磁盘 | `df -h` ⇒ 一期 ≥50 G 可用 | — |
| 5 | ⭐ **能 push** | `ssh -T git@github.com` 或 `ssh -p 443 -T git@ssh.github.com` ⇒ 见到账号名 | ⭐ **先验这个**（换机器后密钥要重配） |

### 4.2 安装

```bash
npm i -g @deepseek-ai/dsh
dsh --version      # 判据：能打出 0.1.5-rc.x 或更新
```
⚠️ **未核实**：`engines` 字段为空 ⇒ **Node 版本要求从包元数据推不出来**，只能按安装说明或实跑确认。

### 4.3 ⭐ 迁移 `~/.dsh/`（**最容易漏、漏了就"空配置"**）

`~/.dsh/` 里有**两样必须在**：
- **`settings.yaml`** —— profile 定义（`alice-bus` 等）+ `contextWindow`（`AGENTS.md` 明确写了它在
  `llm-deepseek.models[] → deepseek-flash → contextWindow`）
- **`sessions/`** —— 会话史（`<cwd-slug>/<session-id>/session.v3.jsonl.zstd`）

**搬运路线（选一）**：
1. 从 WSL 直接 `scp -r ~/.dsh user@server:~/.dsh`（**最简单**）
2. 打 tar 后经 git/网盘中转（跨机不方便直连时）

**判据**：`ls ~/.dsh/settings.yaml` 存在；随便起一个会话后 `~/.dsh/sessions/` 下出现目录。

⚠️ ⚠️ **`settings.yaml` 里很可能有 API key** ⇒ 见 §8（轮换 + 权限 + 不进 git）。
✅ **已核实**：`~/.dsh` **不进 git**（本机 `.gitignore` 里有 `dsh` 相关行）。
📋 用户裁定：**改 `contextWindow` 后必须重启 `dsh web`**（`dsh-settings` 不监听文件）。

### 4.4 启动与保活

```bash
dsh web --port 3081                 # 前台试跑，先确认能起
```
**试跑判据**：能起、无报错、浏览器能打开。

⚠️ **未核实（部署时必查）**：`dsh web` **默认绑 `127.0.0.1` 还是 `0.0.0.0`？有没有 bind 参数？**
⇒ 决定要不要写反向代理，以及能不能直接暴露。**先查 `dsh web --help`**。

**保活**：systemd unit（⚠️ 下面这份是**骨架，未在真机验证**；路径/用户按实际改）：

```ini
[Unit]
Description=DSH web
After=network.target

[Service]
Type=simple
User=<非root用户>
WorkingDirectory=/home/<用户>
ExecStart=/usr/bin/env dsh web --port 3081
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

**判据**：`systemctl status dsh` ⇒ active；`systemctl restart dsh` 后浏览器仍能连。

⚠️ **未核实**：`dsh web` 是否需要在特定 `WorkingDirectory` 下启动（workspace 与会话 slug 相关）。

### 4.5 反代与鉴权

⚠️ **不要直接暴露 3081**。建议 **Caddy**（自动 HTTPS 最省事）：

```
alice.example.com {
    reverse_proxy 127.0.0.1:3081
    basicauth { <用户名> <bcrypt哈希> }
}
```

**判据**：从外部浏览器能打开且**要求登录**；`curl` 不带凭据 ⇒ 401。

✅ **已核实（结构层）**：`dsh-web-app` 自述含 **"frontend dist serving"** ⇒ **`dsh web` 自己 serve 前端**，
所以只需要代理一个端口。⚠️ 但**是否吃 `Host` 头 / 是否要 `--host` 参数，未核实**。

### 4.6 仓库与密钥

```bash
git clone git@github.com:dddgn486/Alice-mcbot.git
cd Alice-mcbot
ssh-keygen -t ed25519 -N "" -C "alice-cloud" -f ~/.ssh/id_ed25519   # 若这台机器还没有
git config core.sshCommand "ssh -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes"   # ✅ 本机已验证必要时
```
⚠️ **ssh 默认只看 `~/.ssh`**（✅ 本机踩过：它在找 `/root/.ssh`）⇒ 密钥不在默认路径时必须配 `core.sshCommand`。

**判据**：`git push` 成功（建议推一个无害 commit 或空分支验证）。

### 4.7 编译能力

```bash
./gradlew compileJava --no-daemon
bash tools/check-all.sh
```
⚠️ **首次会下 Forge / MC 全套依赖（数 GB）** ⇒ 预留时间与磁盘。
**判据**：`check-all.sh` 打出 **pass / warning / failed** 计数（CI 上因无上游模组 jar 会有 WARN，属预期）。

✅ **已核实**：`.github/workflows/build.yml` **已在 ubuntu-latest 上跑 JDK 17 + `tools/check-all.sh` + build**
⇒ **"编译上云"这件事本身已被证明可行**，要补的是"云上也能跑 agent"。

## §6 二期：测试面（**备选，先别做**）

### 6.1 为什么留本地

✅ **已核实**：`tools/headless-battery.sh` 需要
① `CLIENT_ROOT`（客户端实例）② ⭐ **`CLIENT_SAVE`（客户端存档）→ 拷成 `run/world-pristine`**
③ 客户端那套上游模组 jar ④ `SERVER_DIR`（Forge 生产服务端安装）。
**这些本地全都有** ⇒ 搬上去是**自找麻烦**。

### 6.2 ⚠️ 世界母本（**这是二期唯一真障碍**）

脚本头注释自述：**5 个 CORE 步依赖该世界"已存在的绝对坐标地形"** ⇒ 换世界 ⇒ **假红**。
⇒ **世界母本必须唯一**，设备只消费、不生产。**谁权威？待用户定**（📋 用户：二期再说）。
建议形态：**随 artifact 发布一份 `world-pristine`**（或单独发）。

### 6.3 云 ⇄ 本地的通知通道（⭐ 用 git，不用 webhook）

```
云端 agent 改代码 → 编译 → push + 打 tag（如 test/<sha>）
                              ↓
本地笨脚本轮询（cron/systemd timer）：
  发现有没跑过的 tag → 下载 jar → 校验 sha256 → 装 mods（轮转备份）
  → 跑 headless-battery.sh core → 收证据 → 提交/上传 → 记下该 tag 已处理
                              ↓
云端下次读 git 就看到结果
```
**选 git 的理由**：**本地不需要公网 IP、不需要穿透、不开端口**（两台 PC 在家里，这是唯一不折腾的路）。
⚠️ `dsh-webhook` 确实能"用 webhook 起会话"，但那是**云端被触发**的方向，**反向用不了**。

### 6.4 ⭐ 为什么三期可能不需要

**二期做完，CORE 就是无人化的**；真人客户端只用于 `WINDOWS_CLIENT` 级验收 ⇒ **本来就只有两台 PC、次数很少**。
⇒ 手动跑一次脚本完全可以接受 ⇒ **不需要设备发现、不需要多平台抽象**。

## §7 多设备接入

### 7.1 结构（✅ 已核实）

`dsh-web-app` 自述含 **"frontend dist serving"** ⇒ **`dsh web` = 服务端跑 agent + 浏览器只是壳**。
⇒ ⭐ **"数据记忆全在云端、多设备无缝切换"结构上成立**：从 PC-A 关掉、PC-B 打开 = 同一个会话。

### 7.2 ⚠️ 但必须当纪律写下来：**一次只有一个设备写入**

> 会话是**单个 zstd JSONL 追加写**。两个前端**同时**对同一会话说话 = **两个写者**。

📋 用户口径：「我肯定一次只用一个设备写入」——**自然成立，但要作为纪律明确**：切换设备前先关掉/断开那一台。

⚠️ **未核实**：并发写入语义。**建议一期就顺手验掉**（成本极低）：
> 两个浏览器同时开同一会话、各发一句 ⇒ 查 `~/.dsh/sessions/.../session.v3.jsonl.zstd`
> 是否乱序 / 丢事件（用 `node tools/dsh-session-log.mjs --list` + `--grep`）。

## §12 零期：Codespaces 免费验证（**推荐先做这个**）

✅ **已核实（官方文档）**：
- 每个 codespace = **Docker 容器 + GitHub 的 VM**，Ubuntu Linux，最小 **2 核 / 8 G / 32 G**
- 个人账号免费额度：**120 core-hours / 月 + 15 GB-month** ⇒ **2 核机器 = 每月 60 小时**
- 超量后 2 核 **$0.18/h**、4 核 $0.36/h；存储 $0.07/GB-month
- ⭐ **只在实际运行时计费**（停止后不算计算费，但存储照算）
- ⭐ **支持端口转发**（`https://<name>-<port>.app.github.dev`，可设 private / org / public）

**为什么适合当零期**：
1. **规格正好是你要的那一档**（2 核 8 G）
2. ⭐ **端口转发天然解决多设备**（不用买机器、不用配反代、不用搞鉴权）
3. **免费** ⇒ 先回答"这个切分顺不顺"

⚠️ **三个不匹配**：
① 它是**开发工作台，不是常驻服务器**（不活跃会被自动停；超期会自动删除 —— ⚠️ **默认值未核实**）⇒ `~/.dsh/sessions` 会跟着容器走；
