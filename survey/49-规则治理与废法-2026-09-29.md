## ⚠️ §1 先纠正一个前提（**它会改变结论**）

用户原话把 `AGENTS.md` 当"庞大的文本文件"。**实测不是**：

**庞大的是隔壁那些**（实测，`find` + `wc`）：

| 载体 | 量 | 类型 |
|---|---|---|

| ⭐ **`AI_DECISIONS.md`** | ⭐ **545 个决策编号 / 651 个标题 / 26,595 行** | 散文裁定 ← **真正的大头** |

| `tools/check-*.sh\|py` | **35 道** | 可执行 |

⇒ ⭐ **结论（这是本报告第一个纠正）**：
> **病名不是"某个文件膨胀"，是「规则没有归口」—— 同一个"规则"概念散在至少 6 个载体里，且没有任何一处能回答"总共有多少条、哪些还活着"。**

⚠️ **这个纠正很重要**：如果按"`AGENTS.md` 太大"去治，**治错了对象**（它才 142 行，而且已经被检查③ 管住了）。

### 1.1 ⭐⭐ 顺手撞到的实证：**同一个数有三个值**（完美例证 §0 的论点）

```bash
grep -n "决策\*\*编号\*\*数" docs/DECISIONS_INDEX.md   # ⇒ 文件自述 545
awk -F'|' 'NR>=33 && NR<=569 && /^\| \*\*D-/{n++} END{print n}' docs/DECISIONS_INDEX.md   # ⇒ 主表 535

```

⚠️ **`545` / `535` / `508` —— 三个数都"能自证"，都能从同一份文件里跑出来。**
⇒ ⭐⭐ **这正是 §0 说的"没有归口"的直接后果**：连"有多少条规则"都没有唯一答案。

## §2 ⭐⭐⭐ 你要的机制**已经存在**（`tools/redline-gates.py`）

主工作流在 2026-09-21（`G3`）和 2026-09-28（`G3-b`）已经建了它，**做的基本就是你说的那件事**。

### 2.1 检查① · 结构：每条红线只有**三种合法状态**

| 状态 | 意思 |
|---|---|
| `[gate: <脚本>]` | 有可执行检查（⚠️ 脚本**必须真实存在**，否则是**假指针** ⇒ 红） |
| `[未门禁: <原因>；复核触发: <条件>]` | 诚实声明没检查，但**必须带复核触发** |
| ❌ **什么都没有** | **判红** |

⭐ 它自己写了反模式（逐字）：「**别把「未门禁」当免死金牌** —— 没有 `复核触发:` 的 `[未门禁: …]` 一律判红」。

### 2.2 检查③ · 准入锁：**这就是"散文收敛器"**

`2026-09-28 用户原话`（文件里留档）：「**在这个文件里只有被判定高确定性方案，且要经过我显式同意，才能写入**」
＋ 当场质问：「**tm 怎么 `AGENTS.md` 也有散文规则**」。

三条硬约束（逐字照抄）：
1. **新增**一条既无任何标记、又不在基线的条目 ⇒ **红**；
2. 基线条目**静默消失** ⇒ **红**（红线不许无声删除）；
3. ⭐ **`散文条目=<n>/<总数>` 每次打印**（可见读数，不判红）—— **让这个数只许降，且不必靠人记得**。

两种合法写入方式（都**在 diff 里可见**）：① 带 `[用户确认: YYYY-MM-DD]`；② 或同步更新 `BASELINE_PROSE` 基线。

⇒ ⭐⭐⭐ **第 3 条就是你要的答案的内核**：「**不必靠人记得**」——它把"散文只许减"变成了**每次都会打印的数**。

### 2.3 ⚠️ 但它的覆盖面 = **`AGENTS.md` 的架构边界那一段**

```python
SECTION = "## 不可悄悄改变的架构边界"
```

⇒ ⚠️ **实测读数**：`条目=24（有标记=7 散文=17）· 红线=7 有门禁=5 未门禁=2`。
⇒ ⚠️⚠️ **而项目还有 545 个决策编号（651 个标题）**，**完全不受这套约束**。
⇒ ⭐ **所以真正的差距是：机制只有 24 个格子（且只管住 7 条），而规则有 545 条。**

## §4 ⭐⭐⭐ 废法怎么落地（三条，**都能变成检查**）

### 4.1 ⭐⭐ 检查①③ 的机制**扩面**（照抄现有做法，⛔ 不发明新机制）

把"三态 + 准入锁"从 `AGENTS.md` 一段**扩到全部散文规则**（`AI_DECISIONS.md` 的每条 `D`）。

| 维度 | 做法 |
|---|---|

| **基线** | ⛔ **不追溯旧账**；按基线记账，**只许减不许增**（这是检查③ 已有的做法） |
| **读数** | 照抄检查③：**每次打印 `散文条目=<n>/<总数>`**，让数只许降 |
| ⚠️ **现成先例** | `D-519`/`D-533` 的落地形态都是"**写成检查 + 打印读数**" ⇒ 这条路项目走过 |

### 4.2 ⭐⭐⭐ 「死规则探测」—— **原料今天就摆着**

`DECISIONS_INDEX.md` **已经在统计**引用热度（`src` / `tools` / `其它` 三列，附录表）。

```bash
awk -F'|' 'NR>=597 && /^\| \*\*D-/{gsub(/^ +| +$/,"",$2); gsub(/^ +| +$/,"",$3);
  if(($2+0)==0 && ($3+0)==0) n++} END{print n}' docs/DECISIONS_INDEX.md
# ⇒ 198（附录表共 508 行）
```

⇒ ⭐⭐ **`src` 与 `tools` 引用都为 0 的决策 = 198 条。**
⚠️ **基数要说清**：`DECISIONS_INDEX.md` 自述 **545** 条、**主表 535 行**、**附录表 508 行**（§1.1）
⇒ ⭐ **所以准确表述是"附录表 508 行里有 198 行零引用（≈39%）"** —— ⚠️ **不写"占 545 的百分之多少"**（那会假装三个数是一致的）。

⇒ ⛔ **不能直接判死**，但**正好是"废法候选池"**：

### 5.2 ⭐ 所以正确的目标**不是消灭散文**，是给每条散文一个**归宿**

| 散文的类型 | 归宿 | 判据 |
|---|---|---|
| **能判定的** | ⇒ **变成检查**，散文删掉 | 能写出"什么情况变红" |
| **不能判定但有价值**（政策 / 方法论） | ⇒ **保留**，但**必须带 `复核触发 + 到期`** | 检查① 已在做 |
| ⭐ **不给任何理由的** | ⇒ **红** | 检查① 已在做 |
| **描述项目规划的**（用户 ③：还有用） | ⇒ 归 `plans/`，⚠️ **带到期日**（它天然会过期） | 本报告 §7.3 提 |

⇒ ⭐ **一句话**：**"不能判定"不是问题，"没有归宿"才是问题。**

## §6 ⭐ 检查脚本的归口（用户 ④：「乱七八糟，没有统一管理」）

### 6.1 实测现状

- `tools/check-*.sh|py` = **35 道**
- 而 **82 条具名规则全挤在 `kernel-predicates.py` 一个文件里**（`grep -rhoE '\brule_[a-z0-9_]+' tools/*.py | sort -u | wc -l`）
- `AGENTS.md` 里 **5 处 `[gate: …]`**，⚠️ **其中 4 处带"（部分：…）"的限定语** ⇒ 说明**没有一道脚本完整守住一条边界**

### 6.2 ⭐ 建议方向：**不按"文件"组织，按"被谁管"组织**（双向可查）

| 方向 | 今天 | 建议 |
|---|---|---|
| 边界 → 脚本 | ✅ 有（`AGENTS.md` 的 `[gate:]`） | 保留 |
| ⭐ **脚本 → 边界** | ❌ **没有** | 每道脚本**声明它守哪条红线 / 哪个 `D`** |
| ⭐ **规则 → 归属** | ❌ 没有 | `kernel-predicates.py` 的 82 条，**每条**写它属于哪个 `D` |

⇒ ⭐ **收益**：任何一条规则被问"你还成立吗"，**能反查到它在守什么**；反之任何一条边界被问"谁在守"，**能列出脚本**。
⚠️ 而今天 `F4-P1`/`J5-P1`/`S6-P1` 这种代号，**要 grep 两次才能从 `src` 找到规则本体**（`survey/44 §1.1` 实测）。

### 6.3 ⚠️ 一个已知的假绿风险（项目自己记过）

`check-all.sh` 的注释逐字：「**把字面量换成常量后 `D-329` 规则静默变绿**」。
⇒ ⚠️⚔️ **与 §6.2 的建议直接相关**：脚本若靠**字面量**找规则，任何改写都会**静默失效**。
⇒ ⭐ **所以"脚本 → 边界"的声明应当是结构化的（而非字符串匹配）**，否则新加的映射本身会成为下一个假绿源。
⚠️ 先例：`D-537`（`MiningPlan` 改名 `ReachPlan`）实测算出了一个 **`\b` 正则** 的静默失效 ⇒ **项目已经有过一次同族实测**。
