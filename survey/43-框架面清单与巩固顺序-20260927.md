## §1 什么叫"框架面"（判据）

> **改了它 ⇒ 别的层要跟着改。**

| | 例子 | 波及面 |
|---|---|---|
| ⭐ **框架面** | 分层 / 契约字段 / 依赖方向 / 命名归属 | ⚠️ **跨层** |
| 局部改动 | 一个包内加个类 | 自己 |

⇒ ⭐ **判据的用处：它决定"这次改动要不要走裁定"。**（见 `§6`）

## §3 ⚠️⚠️ 为什么"写了文档"不够 —— `D-080` 是活反例

📋 **`D-080` 写得很清楚**（2026-09-10，用户同意）：
> 「新增 `Job implements Task`（**不扩展 `Task` 契约**，L2 已验收保持不动）」
> 「**永久删除**（旧伐木的六份重复）：…… **两套 `Phase` 状态机与记账**」

❌ **但没有任何门禁**：
```bash
LC_ALL=C grep -rn "不扩展\|Task 契约" tools/*.py tools/*.sh   # ⇒ 0 命中
```

⚠️ **实证后果**：
- `FishboneJob` **完全不引 `D-080`**（搜 `D-080` / `JOB_LAYER_DESIGN` ⇒ **0 命中**）
- **而它内部有 8 个相位**（`PREPARE`/`EXCAVATE`/`SPUR_RETURN`/`IN_PLACE_APPROACH`/`IN_PLACE`/`COLLECT`/`RETURN`/`DONE`）

⇒ ⭐⭐ **这就是"改了又改"的完整机理**：

```
框架约定写在文档里 → 文档不会红 → 下一代（或下一轮）不知道 → 重犯 → 再写一次文档 → ……
```

⇒ ⭐ **项目自己早就给过答案** —— `survey/12 §3` 第四条纪律：
> **门禁不是散文，门禁要能红。**

**⇒ 所以"一步一步往外巩固"的正确读法是：不是往文档里加内容，是每巩固一层就多一项检查。**
