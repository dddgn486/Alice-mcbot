## §2 第二层 · 工作站与合成

> ⚠️ **这一节是最要紧的**：第二层**已经在推进**（仓库里已有四份承载文档），
> 但下列约束**只存在于勘测侧笔记**，全仓 0 命中（`survey/41 §1` 是复算记录）。

### 2.1 ⭐⭐ 定位类约束

- ⭐⭐ **点击模拟「不是后门，是正门」**（⚠️ 勘测侧判断，用户未裁）
  - `INTERACTION_LAYERS_COMPARISON.md`：**A 路线**（capability 直写）**可能绕过模组意图**（安全/领地/统计钩子挂 GUI 上）、
    **被拒绝时可能无声成功**；**B 路线**（菜单/点击）**天然被模组拦、天然可归因**。
  - 📎 **实证**：`D-323`（FTB 拦下的破坏被记成 `done`+`COMPLETED`）。
  - ⭐ 它是 `survey/14 §3.4`「档 3」的**执行机制**，**不是新野心**。
  - ⭐ 魔法模组的特殊性：**不是"适配难"，是"根本没接口"**（没有 `IItemHandler`）⇒ A 路线**无路可走**。
- ⭐ **"替代 AE"这个问法要驳回**（`D-266 ②`）：**"AI 自主设计产线"永不进蓝图**。
  正确关系 = 「**AE 的外挂：互补不是替代**」（`D-266 ①`），**价值随玩家进度递增**。
  - ⚠️ 结构理由：AE 的核心是**「网络」**（跨距离/瞬时/无实体/不加载区块）；bot 是**物理实体** ⇒ 结构上不可能替代。
- ⭐⭐ **CC:Tweaked 的教训：抄接口形状，别抄社区模式**（⚠️ 勘测侧判断）
  - CC 真正伟大的不是"能自动化"，是**定义了一套"如何暴露能力"的协议**：**可查询** · **调用者不需要知道实现** · **接口小到作者愿意实现**。
  - ⚠️ **但它的成功靠装机量飞轮**（整合包几乎都塞 CC）⇒ **Alice 没有这个飞轮。**

### 2.2 ⭐⭐ 形态类约束

- ⭐⭐ **编排，不是编程**（⚠️ 勘测侧主张，⏳ `Q-24` 未裁）
  | | 图形化**编程** | 可视化**编排** |
  |---|---|---|
  | 图元 | 变量/循环/条件/函数 | **Alice 已有的动作** |
  | 玩家在做 | 写程序 | **排活儿** |
  | 会不会烂 | ⭐ **必然** | 不会（**原语有界**） |
  - ⇒ **正确的图形化 = 可视化地编辑一张 `TaskSpec` 队列**：不需要发明语言、不需要解释器、**不扩大授权面**。
  - ⇒ ⚠️ 气动工艺之所以乱：**它想做通用编程** —— 通用编程的复杂度不会因为"画出来"而消失。
  - ⭐ **顺序：先原语接口，后图形化**（原语没定型就画界面 = 每次改接口都要重画）。
  - ⭐ **决定成败的不是编排，是调试**：可视化工具死在"它为什么不干活" ⇒ **接口必须自带"为什么没做"的解释**。
- ⭐⭐ **中间容器 = bot 专属方块 + 工作站"第四个口"**（📋 用户定，⏳ `Q-27` 未裁）
  - 用户理由：「更好管理」；本鱼补的结构性理由：**自己的方块 ⇒ A 路线正当**（`bot` 存取**不需要开菜单**），
    且 ⭐ **它把 bot 的工作记忆外化到世界里 ⇒ 中断/重启后东西还在 ⇒ 任务可恢复性天然变强**。
  - ⚠️ **必须钉死的四条**：① **别变成无限仓库**（容量 + `WriteBudget`）② **玩家得能看见**（"不可交互" ≠ "不可查看"）
    ③ **野外放置会永久留下**（`D-398` 区外不回收）④ **归属与寻址**（多 bot/多任务 ⇒ "谁的、哪个任务的"）。
  - ⭐ **必须自动清空搬回仓库**（📋 用户定）：本质是**恢复不变量**，不是卫生习惯。
    ⚠️ 四条约束：**不抢**（本任务还要用的不搬）· **不误搬**（玩家手放的要能区分）·
    **中断残留**（任务崩了 ⇒ 下次启动清理）· **持续写授权**（登记 requester + 走 `WriteBudget`）。
- ⭐⭐ **排序粒度 = 最小分叉点，不是整条路线**（📋 用户定，⏳ `Q-28` 未裁）
  - 用户原话：「**强制玩家排序**，并且**保留默认排序**；这个排序**不是排序整个路线**，
    而是排序**最小分叉路**——也就是对这个中间物品的制作保留排序」。
  - ⭐ 理由：**按路线排会爆炸**（分叉数相乘）；**按分叉点排可复用**（"铁锭的优先序"定一次，所有用到铁的继承）。
  - ⚠️ **对"强制"加一个条件**（勘测侧建议）：
    ```
    平手 / 差异不可忽略              ⇒ 强制（不给"随便"选项）
    能自动收敛（唯一可行 / 差距大）  ⇒ 不要麻烦玩家
    ```
    理由：否则 **"强制"与"计划卡是呈现不是中断"打架** —— 玩家为少点几下随便选，排序就没意义了。
  - ⚠️ **"保留默认排序"的用法**：首次按成本排 ⇒ 计划卡**强制确认或调整一次** ⇒ 之后同物品复用、不再问
    （同 `PermissionGate`「**超时 = 拒绝**」精神：**不接受沉默**）。
- ⭐ **计划卡 = 呈现，不是中断**（📋 用户更正）
  - ⚠️ **不是"四次询问玩家"**，而是**计划卡的生成过程**：多个决策点**一次塞进同一张卡**
    ⇒ **天然解决"问 N 次"**，不需要另设计询问策略。
- ⭐ **最后不是"剩一条线"，是"两条都可以"**（📋 用户更正）
  - 规划期：**排出优先级列表**（不是砍到 1 条）；执行期：**开跑前看哪条前提先满足** ⇒ 用哪条。
  - ⚠️ 判据是"材料够不够" ⇒ **材料检查发生在执行起点，不在规划期** ⇒ 计划卡要同时列两条 + 各自材料需求。
  - ⭐ 白捡的好处：两条路线**参数不同** ⇒ 循环检测**不会误判成"同一条目重试"**。
  - 📋 用户口径：「**优先是哪个材料够用哪个，玩家自己承担材料**」。

### 2.3 ⭐⭐ 配方与偏好类约束

- ⭐ **黑名单为主，白名单当替补**（📋 用户口径）
  - ⚠️ **黑名单的条目必须「可判定」**：具体 id/tag ✅ · "超过阈值 X 的" ✅（若阈值可算）· "别用昂贵的" ❌（若无人定义）。
  - ⭐⭐ **黑名单必须能「报空」** —— 约束把候选吃光 ⇒ **如实报"你的约束把所有路线排除了"**，
    **不许偷偷放宽**（同 `D-323`：静默违背玩家意图）。
    📎 副产品：**这让"NL 够不够用"变成可验证**（LLM 理解错 ⇒ 大概率报空 ⇒ 玩家看得见）。
  - **白名单的真相**：它是**另一把尺子**（默认封闭）⇒ 整合包更新后新东西自动被排除 ⇒ 适合严格控制，不适合日常。
- ⭐ **"昂贵由玩家定"**（📋 用户口径；⚠️ 勘测侧已**撤回**自己上一轮的"可复算成本模型"= 过度设计）
  - ✅ 与 `D-329 ②` 一致：「价值/优先模型 = **A「用户给」**」。
- ⭐ **NL 的边界**：够用 = 偏好/禁忌/口味；不够用 = 精确数值。
  ⇒ 链路固定：`NL → LLM 解析 → 结构化条目 → 确定性层校验 → 落盘`；
  ⚠️ **LLM 的输出必须是结构化的，不能是"一段更长的自然语言"**。
  ⇒ ✅ 与 `D-351` 三层一致（知识库只读/本地配置 typed/记忆库 typed）+ 纪律：**LLM 只能提议**·**记忆永不携带权限**。
- ⭐ **"可配置项"别做成"配方树配置"** —— 那是编程，会重演气动工艺。
  ⇒ ⭐ **降维洞察**：大部分分支是**等价的** ⇒ **不需要"选对"，只需要"别选错"** ⇒ 玩家提供**约束**，不是**答案**。
  ⇒ 形态：**硬约束 / 软偏好 / 禁用** 三层 + **有界候选给 LLM 选**（流程同 `CandidateMenu`）。
- ⭐ **"每次都让玩家选吗"的答案：不是。配置一次 + 例外才问**
  （⚠️ 与 `survey/14` 的「路线选择交玩家」**不矛盾** —— **"交玩家" ≠ "每次都问"**）。
- ⭐⭐ **DAG 合并：一个中间产物被多个父节点需要 ⇒ "做一次，5 铁"，不是"先 2 铁再做 3 铁"**（⚠️ 勘测侧，⏳ `Q-26`）
  - ⇒ **总材料必须按合并后的算**；**"制作顺序"是拓扑排序，不是线性序列**。
  - ⭐ **这是整条流程里唯一"算错就直接坏事"的点。**
- ⚠️⚠️ **KubeJS：配方图必须运行时构建**（`survey/03` 原文）
  - 逐字：「配方与标签在**启动期被脚本改写**。任何'**写死配方/写死产出**'的假设都是**错的**」⇒ **硬约束**。
  - 另一分叉源：**Polymorph**（一个配方多产出，玩家在 UI 里选）。
- ⭐ **三个老大难：探测便宜，处理才贵**（📋 用户分法 = "先找出来、怎么处理放一边"）
  - 递归配方（**环检测**）· 自增配方（产出 ∈ 输入）· 概率配方（有概率字段）
  - ⚠️ 概率那条**项目已经碰过**：`MOD_ADAPTER_PROTOCOL` 记 Thermal **146/670** 条声明 `chance`，
    取值 **0.05~12.5 不在 `[0,1]`** ⇒ 现有做法是**只声明"上游给了概率信息"、不解释数值**。
  - ⭐ **这三类恰好是 AE 做不到的那一层** ⇒ **是 `D-266`「AE 外挂」定位的甜点区**。
- ⭐ **格雷特殊在哪**：成本是**多维的**（电压/产量/副产/时间/能量/污染/回收）⇒ 其他模组成本接近**单维**
  ⇒ **"可配置项"对格雷必要、对别的可选**。
  ⚠️ 但仍守 `D-266 ②`：**适配格雷 ≠ 让 bot 设计格雷产线**。
