## 3. 🔴 静默失效陷阱：`Mode` 的写授权兼职是**运行时**的

**跨层唯一消费者实测**（对上设计讨论 `§4` 前言的断言）：

```
action/MineBlockRunner.java:207-212
    PathRequest request = plan.mode() == MiningPlan.Mode.TUNNEL
            || plan.mode() == MiningPlan.Mode.ENTER_TARGET
            ? PathRequest.miningApproach(...)   // ← 含 BREAK_*/PILLAR/FALL/DOWNWARD/PLACE_STEP
            : PathRequest.of(...);              // ← 纯通行
```

⇒ ⭐⭐ **`MiningPlan.Mode` 不是"规划模式记录"，它是"执行期写授权"的物理载体**（`D-076` 红线的最后一处）。
`§4` 前言说的"**授权从规划器重挂到目标不是免费的**"，**具体所指就是这 6 行**。

⚠️⚠️ **陷阱的形状**：`§4.3` 甲 的措辞是「`MiningPlan` 保留但 **`Mode` 收窄/换语义**（把"写授权"从枚举里剥出来）」——
若只**收窄字段**而**保留** `TUNNEL`/`ENTER_TARGET` 两个常量（或反过来：保留枚举、不再生产那两个值），
⇒ `plan.mode()` **永远不等于** `TUNNEL`/`ENTER_TARGET` ⇒ **三元恒走 `PathRequest.of`（纯通行）** ⇒
**破坏能力被静默拿掉**，而症状会表现为"**站不到站位**"（`no_reachable_standing_point`），**不是**"权限被拒"。
⇒ 编译器**不报错**（枚举值还在）· 现有门禁**不报错**（`check-policy-matrix` 管的是"工厂↔词表"，不是"值还会不会被生产"）。

**⇒ 侦察建议（供裁，⛔ 不是裁定）**：下一刀必须**同刀**做两件 ——
① 在 `MineBlockRunner` 把"要不要破坏"改成**显式声明**（⛔ 不再由 `Mode` 值推）；
② 补一条**可红**的判据：`Mode.TUNNEL`/`ENTER_TARGET` **要么被删、要么必须有生产点**（照 `J5-P1`「声明字段必须有消费者」的同族形态，`D-478` `P10` 已裁该方向）。

## 4. `DS-7`（清障丢弃）的前置 —— 实测

`adjacentApproach`（`K2` 甲）用的**就是**这个集合（`PathRequest` javadoc 逐字：「与 `miningApproach` **逐字相同**」）。

- ⇒ ⭐ 「清障」正是**对"A 腿纯通行"的补偿**（`BlockerClearPlanner` docstring：树冠包住最上 1~2 根原木）

⇒ **结论**：`DS-7` 的前置 = 「**把"到位"统一交给含破坏能力的 Goal 搜索**」= **`③`（`K2` 接线）**。
⇒ ⇒ **清障丢弃可以进 改革 ① 主体，但硬前置 = 排在 `③` 之后**（顺带满足 `D-011`「不能未经验证直接删除」）。
⚠️ **不是**"必须先造新能力"——`BREAK_AND_*` 今天就在白名单里，缺的是**接线**。这是本次侦察对 `D-519` 那个开口的回答。
