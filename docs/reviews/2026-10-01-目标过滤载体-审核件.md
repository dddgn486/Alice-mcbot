## §2 逐个成员（逐字签名 ＋ 我的读数）

### §2.1 `job/JobDeclaration`（record，**作业的全部外部输入**，`D-080`）

```java
public record JobDeclaration(Kind kind, int quota, BlockPos center, int radius, int maxTicks,
                             TagKey<Item> productTag,
                             com.dddgn.alice.job.mine.MineIntent intent,
                             java.util.List<String> kindQuotas)
```
| 字段 | 语义 | ⭐ 我的读数 |
|---|---|---|
| `kind` | `COLLECT_ITEMS` / `HARVEST_UNITS` = **完成判据** | 与"目标"无关，是"算不算完成" |
| `quota` | 完成配额（物品数/单位数） | ⭐ **硬上限** |
| `center` ＋ `radius` | **作业范围** | ⭐ **这是唯一的"空间"输入** —— 一个圆 |
| `intent: MineIntent` | ⭐ **"在哪挖"的声明式输入** | ⭐ **意图维的载体**（见 §2.2） |
| `kindQuotas` | 种类分配（`"<键>=<数量>"`） | 对 `quota` 的细分，⛔ 不推迟配额判定 |
| `maxTicks` / `productTag` | 时间上限 / 产物标签 | — |

⭐ **关键：它里面没有"目标清单"** —— 只有"范围 + 意图 + 配额"。目标清单由 `CandidateSource` **每次算**。

### §2.2 `job/mine/MineIntent`（record）

```java
public record MineIntent(BlockPos areaCenter, int halfExtentXZ, int yMin, int yMax) {
    public static final String OUTSIDE = "outside_work_area";
    public String refusalFor(BlockPos pos);   // null = 在意图内
}
```
⭐ **它的 javadoc 是全仓最要紧的一段**（`D-329`，用户 2026-09-20），逐字：
> ⚠️⭐ **意图是"搜索偏好"，不是"可挖承诺"**（用户 2026-09-20 点出的陷阱）：一个符合意图的作业区里
> **完全可能有一部分目标实际不可挖**（被保护、不可破、视线不可达）。⇒ 本类的 `refusalFor` 只负责
> 回答"**在不在作业区里**"，**绝不**替授权面/破坏面下结论；区内的候选照样要过
> `ZoneAuthority.candidateRefusal` + `BlockInteraction.breakable`，而且**它们自己的理由码必须保住**
> （不许被 `outside_work_area` 顶替）——否则"不可挖"就会被伪装成"不在计划里"。

### §2.4 `job/CandidateSet`（record）⭐ 核心

```java
public record CandidateSet(List<Candidate> viable, List<String> rejected) {
    public static CandidateSet empty();
    public boolean isEmpty();          // ⚠️ 只看 viable
}
```
| 栏 | 谁填 | 语义 |
|---|---|---|
| `viable` | ⭐ **候选源** | 可作业 |
| `rejected` | ⭐ **候选源** | `List<String>`，形如 `tree@12,64,8:no_stand` |

⚠️ **`rejected` 是"字符串列表"，不是结构化记录** —— ⇒ ⭐ **码与锚点靠 `lastIndexOf(':')` 拆**
（`RegionLumberJob.permissionBlock:835` 就是这么拆的）。
⚠️ **`isEmpty()` 只看 `viable`** ⇒ ⭐ **"全是 `rejected`"与"真的没东西"在这里**不可区分**。

## §4 ⭐⭐ 关键实测：两个实现的**形状不一致**（本审核件最要紧的一条）

**`MineCandidateSource` 已经有"两道"** —— 而且它的 javadoc 把理由写得很清楚：

```java
// MineCandidateSource#viabilityRefusal 的 javadoc 逐字：
// ⭐ 为什么必须能被**重复**调用（这次改动的真教训）：候选**位置**是"扫描那一刻"的快照，
//    但**可破坏性/授权是当时的世界事实** —— 预算、权限、方块本身都可能已经变了。
//    …这份快照会**过期**（实测 mine_budget：预算被压到 0，第一格用尽预算后，剩下 5 格在旧版里
//    当场变成 `:unbreakable` ⇒ 归因 `write_budget_exhausted`；不重验的快照则让它们继续"可选"…）
// ⚠️ 这是 D-348 同一条纪律的另一面：**别把代理判据当世界事实**。
```
它的**检查顺序**（`D-392`，有实测依据）：
```
① ZoneAuthority.candidateRefusal（权限）
② WriteBudget.breakAllowed（预算）  ← 保住 mine_budget 的 write_budget_exhausted 归因
③ BlockInteraction.breakRefusal（具体码：already_air / fluid_block / unbreakable_block / …）
```

**`LumberCandidateSource` 只有"一道"** —— 全文件 `candidateRefusal` 出现次数 = **1**（`:71`，在 `candidates()` 里），
⛔ **没有 `viabilityRefusal` 等价物，也就没有"决策前复检"**。

⇒ ⭐⭐ **结论（对你那句"两边可能都要"的直接回答）**：
> **"检查否决"与"执行兜底"这两道，`MineCandidateSource` ＋ `BlockInteraction` 已经都有；
> ⛔ 缺的是把同一形状**推广到 lumber**（今天 lumber 只在生成期过滤一次）。**
> ⇒ **不是新造机制，是"把一个已有实现推广"** —— 成本比预想低得多。

⚠️ 而且两条候选源**共同**缺一件事：**权限拒绝的结果没有独立的落点**
（lumber 塞进 `rejected`；mine 塞进复检的派生集）⇒ ⭐ **这正是 §5 三栏要解决的。**

## §6 三栏提案的具体形状（承接草案 `§10.2.3`）

```java
public record CandidateSet(List<Candidate> viable,      // ⭐ job 层填：意图内、未尝试
                           List<String>   rejected,      // ⭐ job 层填：作业做不到 / 意图外
                           List<Denied>   denied) {      // ⭐ 授权面填：意图内、授权已拒（带码）
    public record Denied(Candidate candidate, String code, String detail) {}
}
```
⭐ **一处形状选择要你裁**：`denied` 的元素是 **`Candidate`**（结构化）还是 **`String`**（与 `rejected` 同形）？
- 我荐 **结构化 `Denied(candidate, code, detail)`** —— 理由：⭐ **下游（`standing`/`deficit`/决策层/LLM 报告）
  必须能机械地拿到 `anchor` 与 `code`**，⛔ 不该再靠 `lastIndexOf(':')` 拆字符串
  （`RegionLumberJob.permissionBlock:835` 今天就是这么猜的）。

⭐ **下游三条使用规则**（这是三栏的**全部**收益所在）：
1. `standing = viable.size() + denied.size()`（⛔ 不再只数 `viable`）⇒ `deficit` 不虚高；
2. `viable.isEmpty() && !denied.isEmpty()` ⇒ ⭐ **直接就是"没权限"那句话**（⛔ 不再需要 `permissionBlock()` 猜 + `D-344` 两条顺序约束）；
3. `DecisionTrace.select` 行加 `denied=[…]` ⇒ ⭐ 决策层与 LLM **同时看到"想挖什么"与"不被允许挖什么"**。
