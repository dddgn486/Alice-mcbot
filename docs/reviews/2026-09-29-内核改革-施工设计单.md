## §4 乙 · 新 goal 形状

### 4a 同列形状（`GoalTwoBlocks` ＋ 深化）
- 到达判据逐字照 `GoalTwoBlocks.isInGoal`：`x == tx && (y == ty || y == ty - 1) && z == tz`；
- **深化**：加 `|| y == ty - k`（`k = 2 … K`），`K` 由**触及推导**（`eye(y−k) → 矿中心 ≈ k − 1.1 ≤ reach` ⇒ `K ≈ 5`），⛔ 不照抄 Baritone 的 `2`（`reference/baritone-1.20.1/.../MineProcess.java:302-311` 的 `GoalThreeBlocks` 是手写死的）；
- **参考对照**：`MineProcess.java:260-300`（`coalesce` 七分支）· `:117-121`（原地挖只取同列且只往上）。
> ⚠️ **命名落地（2026-09-29，`1-0a`）**：类名 = **`pathing/core/search/GoalColumnBlocks`**，⛔ **不叫 `GoalTwoBlocks`** ——
> 那个名字在参照树里已存在（`reference/baritone-1.20.1/src/api/java/baritone/api/pathing/goals/GoalTwoBlocks.java`），
> 而**裸文件名**的 `文件:行` 引用会被 `ref-integrity` 的"同名候选取最大行数"**静默核销**（台账 `O32` §5①）。
> 到达判据逐字照本节；`depth` 由 `GoalColumnBlocks.maxDepthForReach(reach)` 推导（`reach = 4.5` ⇒ `K = 5`）。

### 4b 侧面形状（`O29` `C-6`：**本单边定边裁**）
- **推荐：留**。`GoalAdjacent` 的到达判据（`GoalAdjacent.java:115-129`：曼哈顿 ≤1、不站目标、不站上方）**是纯算术**，正是"站到旁边就地挖"的**正确载体**；⛔ 但**改名/改语义**（它今天的 javadoc 逐字写「新到达集 = Baritone 自己的 `GoalAdjacent`」—— 那句要改成"**侧面兜底形状**"，并说明 Baritone 挖掘侧从不含侧面）。
