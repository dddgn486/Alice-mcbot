# P4「tick 负载预算」门禁（尺子线）

**出处**：`docs/OPEN_ITEMS_LEDGER.md §11 C 段 P4`　**验证等级**：`IMPLEMENTED` + `COMPILES`（门禁 PASS）；无客户端/真人证据

## 做了什么

新增门禁规则 **`rule_tick_load_budget_declared`**（`tools/kernel-predicates.py`，输出标签 `[P4·tick负载预算]`）：
**全仓所有毫秒常量必须"声明 + 有界 + 有复核触发"**，而不是只钉台账点名的那几个点。

- 已有能力不重复：`rule_search_budget_is_tick_aware`（守 `CorePathPlanner.DEFAULT_MAX_MILLIS`）、
  `rule_tick_search_account_enforced`（每 tick 搜索总账）保持不变；本规则补的是**人口口径**。
- 复用同一处上限 `SEARCH_BUDGET_CEILING_MILLIS = 60`（一个 tick 的量级，`D-369 §六` 真机 87 次撞线定下的值）。

### 断言（改任一处 ⇒ 红）

| # | 断言 |
|---|---|
| ① | 扫描人口 ≥ `TICK_BUDGET_SITES_MIN = 4` ⇒ 解析崩塌 / 常量被改名藏起来时**不许静默通过** |
| ② | 超过 60 ms 的常量必须有登记，否则红并报出"≈ 单次可独占 N 个 tick" |
| ③ | 登记表**双向**：登记项必须真的存在、数值必须与代码一致（改值不清登记 ⇒ 红） |
| ④ | 每条登记理由 ≥20 字**且必须写出「复核触发」**（没有复核条件的豁免 = 永久豁免） |

### 人口（可见，实测）

```
[P4·tick负载预算] 人口=7 个毫秒常量（额度 4 / 登记豁免 3）
```

⭐ **规则当场抓到台账都没点名的第 4 个常量**：`SearchTickBudget.EXPENSIVE_SEARCH_MILLIS = 100` ——
它是"一次搜索算不算烧预算"的**分类阈值**（A1 主判据的计量口径），不是执行额度。
台账 `P4` 原文只点名了 3 个（`DEFAULT_MAX_MILLIS_PER_TICK=400`、`ESCAPE_MAX_MILLIS=100`、`PRECHECK_MAX_MILLIS=20`）
⇒ 人口扫描的价值就在这里：**毫秒常量没有暗处**。

## 注入臂实录（判据 = 注入即红）

| 臂 | 注入 | 结果 |
|---|---|---|
| ① | `SearchTickBudget` 里新增 `P4_INJECT_MAX_MILLIS = 500L` | **FAIL** ✓（未登记） |
| ② | `DEFAULT_MAX_MILLIS_PER_TICK` 400 → 250（不动登记表） | **FAIL** ✓（登记表写 400、代码实际 250） |
| ③ | `ESCAPE_MAX_MILLIS` 改名 `ESCAPE_BUDGET_MILLIS` | **FAIL** ✓（既缺登记、又使登记失配 —— 两条同时触发） |
| ④ | 去掉 `ESCAPE_MAX_MILLIS` 豁免理由里的「复核触发」 | **FAIL** ✓（理由不合格） |

每条注入后立即还原；还原后基线回到 `KERNEL_PREDICATE_CHECK_RESULT PASS`（人口 7 不变）。

## 有意**不做**的事（诚实边界）

**没有**把 `DEFAULT_MAX_MILLIS_PER_TICK` 从 400 收到 ≤60 —— 那是**内核行为变更**（搜索切片被切短 ⇒ 重规划次数变多 ⇒
可能翻 CORE 判决），不属于"尺子线"，且用户已裁定"忽略上次客户端测试结论" ⇒ 不能拿那次测试的观测当改动理由。
⇒ 登记为**后续项 `P4′`**（见台账 §11 C 段），复核触发已写在豁免理由里：
下一次收口客户端测试若仍见 `Can't keep up` ⇒ 下调到 ≤60 并复跑 CORE 逐步 diff。
