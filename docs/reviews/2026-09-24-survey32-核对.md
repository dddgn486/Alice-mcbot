## §3 ⭐ 本次核对的头号发现：`Can't keep up` 的归属被读错（且 vanilla 阈值语义被算错）

### 3.1 事实（可当场复算）

**① 行位置（硬证据，与阈值语义无关）**

`run/headless-logs/20260924-140303-single_tick_budget_bench.log` 的**唯一**一条告警是：

```
:189 [14:02:57] [TickBench] cell config=PROD(400/1/32) load=LEGACY(13×无时间上限) wall=761ms …
:190 [14:02:57] [minecraft/MinecraftServer]: Can't keep up! … Running 2198ms or 43 ticks behind
:196 [14:02:57] [TickBench] cell config=TIGHTENED(60/1/32) load=MINING …
…
:321 [14:03:02] [TickBench] cell config=UNGATED(0/0/0) load=LEGACY(13×无时间上限) wall=2578ms …
```

⇒ 告警出现在**闸门开着的 `PROD` 三格之后**，比**任何一个 `UNGATED` 格早 5 秒** ⇒ **它在时间上不可能来自 `UNGATED/LEGACY` 那格**。

**② 三次运行全部同形**（`tick_budget_bench` 当天跑了 3 次，报告只引了第 3 次）：

| 运行 | 告警值 | 告警位置 | 紧邻其后的格 | `UNGATED/LEGACY`（更晚） |
|---|---|---|---|---|
| `…135848…`（旧版负载名 `HEAVY`/`CHEAP`） | 2360 ms / 47 ticks | `PROD/CHEAP` **之后** | `TIGHTENED/HEAVY` | **2675 ms** |
| `…140135…` | 2169 ms / 43 ticks | `PROD/LEGACY` **之后** | `TIGHTENED/MINING` | 2466 ms |
| `…140303…`（报告引用的那次） | 2198 ms / 43 ticks | `PROD/LEGACY` **之后** | `TIGHTENED/MINING` | 2575/2578 ms |

⇒ **三次都在闸门开着的格子之后、都在 `UNGATED` 之前**；告警值几乎不随 `UNGATED` 格的大小变化（2466–2680 ms）。

**③ `UNGATED/LEGACY` 那次是 `wall=2578ms / account=2575ms`** —— 报告（及 `D-429`、台账 `P4′` 行）引的是 **`wall`**，而其余八格引的都是 **`account`**（例：`PROD/MINING` 引 402 而不是 `wall=409`）⇒ **同一张表里两种口径混用**（差 3 ms，不影响结论，但读者会以为 2578 与 2575 是两个不同读数；`SUMMARY` 印的是 `undated_legacy_ms=2575`）。

### 3.2 vanilla 阈值语义（本轮**读字节码**核实，不是"系统常识"）

`net/minecraft/server/MinecraftServer.class`（Forge 1.20.1 映射版 `client.jar`）里那条 `ldc_w "Can't keep up! …"` 的分支是：

```
l1 = Util.getNanos() - this.ah          // 距"检查点"的累计时长
if (l1 > 2000ms  &&  (this.ah - this.ae) >= 15000ms) {
    ticksBehind = l1 / 50;
    LOGGER.warn("Can't keep up! … Running {}ms or {} ticks behind", l1, ticksBehind);
    this.ah += ticksBehind * 50;        // 上报后把检查点前移 = 计数清零
    this.ae  = this.ah;                 // 记录本次上报时刻
}
```

⇒ 三条**源码级事实**（此前 `卡顿根因分析.md` :37 只敢标"系统常识级判断"，现已可升级）：

1. **累计量、不是单 tick 量**：`l1` 是"距检查点的累计落后"，**不是某一 tick 的耗时**；
2. **两次上报至少隔 15 秒**（`(ah − ae) ≥ 15000 ms`）⇒ 它**天生是被限流的**；
3. **上报后检查点前移**（`ah += ticksBehind*50`）⇒ 计数归零。

### 3.3 ⇒ 因此有三处措辞必须更正

| 位置 | 原文 | 更正 |
