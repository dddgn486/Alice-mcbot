# T3 步骤 A：探针的「可见性」—— 它此前结构上看不见任何新模组

> 日期 2026-09-14 ｜ 前置：`docs/reviews/2026-09-14-T3-B3a-读取器vanilla优先与探针确定性.md`（§4 已把抽样改成确定性）
> 验证：`bash tools/check-all.sh` + `bash tools/headless-battery.sh core` ⇒ `verdict=PASS`、`(30/30 skipped=0) ticks=3303 → PASS`
> 等级：**`SERVER_TESTED`（无头基线）**。不碰渲染/物理/GUI ⇒ **不得**记成 `WINDOWS_CLIENT`。

---

## 1. 一句话

`MachineProbe` 的枚举来源是 **`MachineMap` 自己**（`adoptedNamespaces()` 遍历表行），而"运行时有、表里没有"
的守卫 `unmapped` **又只遍历那个被表过滤过的集合** ⇒ 对**任何还没登记过的模组，它是结构性失明的**。
修法 = 枚举来源换成**配方注册表**；采样范围**保持只限已登记命名空间**。

---

## 2. 缺陷（代码级事实）

```java
adoptedNamespaces()      // = MachineMap.rows() 里出现过的命名空间
for (recipe : getRecipes()) {
    if (adopted.contains(ns)) byType.put(...)   // ← 未登记的模组**连枚举都进不去**
}
for (typeId : byType.keySet()) if (MachineMap.forType(typeId) == null) unmapped.add(typeId);  // ← 域就是被过滤过的集合
```

⇒ **"表里一行都没有"与"这个模组根本不存在"在输出上完全同形**。而这恰好是 T3 要处理的对象：
`create` / `ExtendedCrafting`（以及 `refinedstorage` / `sophisticated*`）**此刻就装在无头生产服务端里**，
而修前的读数是 `namespaces=[mekanism, thermal]` + `unmapped=[]` —— **一个字都不说**。

---

## 3. 修法（最小面）

| 改动 | 内容 |
|---|---|
| 枚举来源 | 由**表**改为**配方注册表**：遍历全部"非原版工作站"配方类型，建 `allTypes`（`TreeSet`，有序）+ 每命名空间的 `types` / `type_recipes` 计数 |
| `unmapped` 遍历域 | `byType.keySet()`（已登记）→ **`allTypes`（全部）** |
| 采样范围 | **不变**（仍只采已登记命名空间）—— "能不能接"与"采样多少条"是两件事，不为一个模组撑长一轮 |
| 新读数 | `unmapped_total=N`；`unregistered_ns=[ns=types(rows=0,recipes=M),…]`；**逐未登记命名空间一条 warn 行**（含该命名空间的**全部类型 id**） |
| 日志卫生 | `unmapped` 在 SUMMARY / info 行**限长 24 条**并带真实总数（完整清单由逐命名空间行承载）⇒ 不因模组变多而撑爆一行 |

`unmapped` 仍是 **warn-only，不判红**：模组集可变，"我们有 0 行"是**待办**而不是**错误**。

## 5. 这一步买到什么（对 T3 的直接后果）

1. **"接第 3 个模组"的工作量第一次是实测值，不再是估计**：要接 Create 就是 **15 个类型 / 506 条配方**，
   ExtendedCrafting **4 个类型 / 25 条配方** ⇒ 按 `MOD_ADAPTER_PROTOCOL` §"多模组后不允许只登记几行"，
   合计 **19 行** `MachineMap` + 每行方块/菜单/能力 + `tools/machine-map.py` 的 `UPSTREAMS` 一段。
2. **M-4 的前置问题（"怎么摸到 EC 的机器类型"）自动解决**：EC 的机器类型就是
   `extendedcrafting:{compressor, ender_crafter, flux_crafter}`（`table` 是工作台、非机器），
   现在有了 id 清单即可定点取样。
3. **一个反面事实也被记下**：`refinedstorage` / `sophisticated*` / `oreexcavation` / `cofh_core`
   **没有任何"非原版工作站"配方类型**（它们没出现在未登记清单里）⇒ 它们不需要 `MachineMap` 行。
   **注意这是"当前模组集下的观测"，不是对这几个模组的永久断言。**

## 6. 未做 / 风险

- **仍未采样未登记命名空间**（有意）：`unmapped` 只报"有这些类型"，**不报它们的输入/输出形状**。
  要看形状（M-4 / B3b 需要）得再做一步定点采样 —— 那是下一个增量，不是本步。
- `unmapped` 的 19 项**不是错误**，是待办；**没有**升级为判红（升级会每次都红，属于"用断言盖住事实"）。
- 本步**没有**动 `MachineMap` / 读取器 / 判据 / 准入 —— 纯枚举与报告面。
- 证据全部来自**无头生产服务端**（模组集与客户端同构，但**不等于**客户端）：不覆盖渲染/物理/GUI/同步。
