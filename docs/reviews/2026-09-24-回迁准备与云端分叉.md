## §4 本次踩到/登记的坑

- **43**：**云端仓库的"未推送 0"可能是假的**（引用过期）。判据要写"**相对 GitHub 上那个 master**"，
  即 `git fetch` 后再看 `@{u}..HEAD`；或直接以"GitHub 上有、本机没有"为准（本机 `git fetch` 是必做步骤）。
- **44**：⭐ **同一个会话 id 在两端各自长过**（分叉）⇒ **不能按 id 合并**，也不能塞回 `~/.dsh/sessions/`；
  正确做法是**当归档读**（`--file` + `transcript`）。
- **45**：⚠️ **`rput` 这种"base64 套 base64"的传文件方式有硬上限**：Linux 单个参数上限 **128 KB**
  （`MAX_ARG_STRLEN`）。实测：84 KB 的计划文件 → 内层 base64 112 KB → 外层再 base64 **150 KB** ⇒
  `gh: Argument list too long`（外层 `gh` 直接失败，现象像"连不上云端"）。**修**：结构化文件一律走 `gh codespace cp`。
- **46**：⭐ **"切在哪一字节"必须切在 zstd 帧起点上**：阶梯给的偏移是 1 MiB 的整数倍，**不一定**是帧边界
  ⇒ 预览/解码会以"首个魔数不在偏移 0"失败。`pack` 已改成"从 `≥offset` 的第一个魔数起切"，并把 `start` 记进 manifest，
  由 `rebuild` 用 `本机[0,start)` 补前缀 ⇒ 还原仍是**逐字节**的（sha256 已证）。
