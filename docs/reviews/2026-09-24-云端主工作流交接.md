## 云端主会话 API 失败：根因与修复（2026-09-24，用户报障后排查）

**现象**：云端打开迁移过去的主会话（`session-c83b9b33-…`），发言报 `api 请求失败`；**其它会话正常**。
**会话里的证据**：`assistant/attempt` → `finish{kind:error, code:TRANSPORT}`，消息
`DeepSeek API stream from https://api.deepseek.com failed`，重试 3 次（14:49–14:50，多次间隔 <1s ⇒ **快速失败**，非超时）。

**逐步排除**（都实测）：余额充足（云端 `is_available:true` 41.80 CNY）· 凭据与出网正常（同容器 curl 两个端点皆 200）·
迁移无损（44,317 帧全可解）· 请求体积不是主因（云端实测 1.27 MB / 35 万 token ✓ 与 2.91 MB 带图 ✓ 均 HTTP 200、TTFB <1.5s）。

**两个真因（都修了）**：
1. **云端 settings 缺模型配置**：只有 `ui-onboarding` + `agent-default-model`，**没有 `llm-deepseek` 段**
   ⇒ 没有 `contextWindow: 512000`、`imagePixelBudget`、`imageMaxBytes`（本地有）⇒ 请求构造/预算与本地不同。
   **修**：**只**追加 `llm-deepseek` + `generation` 两段（备份 `settings.yaml.bak-pre-partial`）—— 用户授权"先迁移部分 settings"。
2. ⭐ **附件对象没迁**：迁移时只搬了 `~/.dsh/sessions/`，**漏了 `~/.dsh/attachments/`**。主会话引用 **35 个图片内容块（289 哈希）**，
   而云端附件目录是**空的** ⇒ 引用不到对象 ⇒ 构造请求时坏掉。小会话无图片 ⇒ 因此"只有这条会话有事"。
   **修**：补迁 `attachments/`（179 对象 / 52 MB / 18s，两端一致）。

**验收（用户确认）**：云端主工作流**正常启动、记忆正常、启动协议检查完成** ✓。

**可复用教训（已同步进 `CLOUD_MIGRATION.md` §9-36）**：迁移 DSH 会话时，**`sessions/` 与 `attachments/` 必须成对迁移**；
只搬 `sessions/` 会在"含图片的历史会话"上表现成 API stream 失败，而小会话完全正常 —— 极具误导性。
