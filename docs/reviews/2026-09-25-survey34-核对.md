## §2 勘测侧补引的两处事实：我复核后**采纳为更准的根因表述**

### 2.1 A1 的真根因 = 判据两个来源（不是顺序）

- `FishboneJob.java:527`（跳过判据）：`bodyPassable` = 脚位 **且** 头位可穿；
- `FishboneJob.java:647-649`（露头矿判据）：**明写**改用单格 `canWalkThrough`，并记录了"第一版用 `bodyPassable` 实测当场红"。
- ⇒ **同一文件、同一问题（"这格是通的吗"）两份判据**；A1 是**第三次**撞同一件事（`:647` 一次 + A1 一次 + 本轮再次）。
- ⇒ **采纳**：修法是**判据唯一化**（由形状层出唯一一份"单元完成"判据：脚位可穿 ∧ 头位可穿 ∧ 地板在），
  不是再加一条"先挖头位"的顺序规则。我草案 §1.1 的第二条 ⇒ **改判为"表现"**。

### 2.2 `MiningPlanner` 内部确实并存两套能力集

`:303`/`:391` 用 `miningApproach`（`D-366b` 后含 `PILLAR/FALL/DOWNWARD/BREAK_*/PLACE_STEP`）、`:367` 用 `of`（纯通行）
⇒ 不是"内核不会走"，是**同一个类里两条路径两套能力**，而弱的那条在否决（本轮实证：同 tick 走位 `REACHED` / 挖掘站位 `unreachable`）。

### 3.2 ❌ 异议：`I5`（通道格/支撑格防破坏）**不该**落在 `ZoneAuthority`

| # | 依据 |
|---|---|
| 1 | ✅ **元凶是同一个作业自己的两条写路径**：本轮 A1 的破坏来自 `by=fishbone:BULK_EDIT`（追簇）与 `by=collect-drops:…:PATH_ACCESS`（捡东西走近路），**同属一个作业作用域**（`[WriteBudget] SUMMARY scope=5aeecd8c#89:FishboneJob`）⇒ **授权/归属类闸门分不开"我的矿"与"我的地板"，两者都合法地属于"我"** |
| 2 | ✅ `ZoneAuthority` 的粒度是**区域封套**（`TaskZoneRegistry.java:77`，2D、无 Y）⇒ 表达不了"某条通道的地板格集合"，且通道在**采集区**（`D-372`：区外不记账） |
| 3 | ✅ `WritePolicyMatrix` 的维度是「区域归属（EXTERNAL/WORKSPACE）× 任务类别 → 义务/授权/理由」，且**本轮刻意 EXTERNAL ≡ WORKSPACE**（`workspace_equiv` 断言守着）⇒ 加"通道保护"会让这个等式失衡，等于引入第三种归属 |

**我建议的落点（沿用勘测侧要的"形态"，只换"来源"）**：
把"通道必需格（行走层 + 净空 + 支撑格）"做成**当前作业形状（`L2`）**给出的判据，
在**已有的候选过滤点**消费（对照 `job/lumber/LumberCandidateSource.java:71`、`job/mine/MineCandidateSource.java:449` 的现有形态）
⇒ **一个判据多处消费、不新造机制**，但**来源是作业形状，不是保护区登记**。

### 3.3 细化：`P0.5` 的注入点已经存在（`MiningProfile`）

- ✅ `task/mining/MiningProfile.java:30-40`：`record MiningProfile(boolean standableOnly, int maxGainSteps, int gainBlockBudget, int clearBudget, boolean restoreOwnPlacements)`
  + 预设 `STANDABLE_ONLY` / `TUNNEL_ALLOWED`（**默认即现状**，注释逐字"默认即现状"）。
- ⇒ **最小形态**：该 record 增 1 个"接近能力"字段（默认 = `of` 纯通行 = 今天行为不变），
  鱼骨那处调用点传 `withPlacement`；`MiningPlanner` 只需把 `:367` 的工厂换成"问 profile 要" ⇒ **1 个字段 + 2 处代码 + 1 处调用**。
- ⇒ 比勘测侧"给 `MineTask`/`MiningPlanner` 收一个 capability 参数"**更小且更符合既有结构**（消费者本来就是靠 profile 声明策略）。

### 3.4 ⭐ 新增依赖（勘测侧未提，但会直接影响 `P0.5`）：**必须与 `C8` 尾款同片**

- ✅ 已登记事实：`docs/plans/2026-09-21-鱼骨挖矿计划.md:167` 的 `C8` = **大矿洞三条上限**；而
  `FishboneTemplate.java:24-28` 逐字说明 `maxGapLength` / `bridgeBlockBudget` / `oreQuota` / `oreTarget`
  **故意仍不声明**（"消费者在切片 2 第二步与切片 4 才出现"）；`OPEN_ITEMS_LEDGER.md` 行 `1.4a` 与 `HANDOVER.md:1019`
  （「③ 切片 2 尾款【1 轮，按需】：追簇/`oreQuota`、大矿洞三条上限」）都记着这是**未做的尾款**。
- ⚠️ **推论（重要）**：今天"搭路"没有按 `C8` 约束 —— `withPlacement` 的预算形态是**每次走位**的
  `placeBudget() = max(8, advanceCells/10)`（A14），而 `C8` 要的是**单段悬空 ≤ `maxGapLength`（4）+ 作业累计 ≤ `bridgeBlockBudget`（16）**。
  ⇒ 若 `P0.5` **单独**把宽权限给了挖掘接近，就等于**把 `C8` 的红臂情形（无限搭）合法化**。
- ⇒ **建议：`P0.5` 与 `C8` 尾款同片**，并在同一片里把两套预算口径**对账**（A14 的"每次走位"vs `C8` 的"作业累计"）。

### 3.5 接受：`L3` 缓 / `parkour` 不排 / `road/` 词表不借（+ 一条补强）
