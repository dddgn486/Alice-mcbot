## §1 结论（一句话）

`Z1` 让账本**在区外不记账**，于是"**用账本证明我没写世界 / 没留我方方块**"的那一族判据在野外

## §3 口径（`WorldModLedger.Closure`）

```
inZone        保护区内待收 TEMP（= D-398 意义上的义务）
wildInLedger  仍在账本里的区外条目（旧存档遗留 / 先记账后 unclaim；dropStale 会销 ⇒ 要在它之前读）
recordedSince 窗口内**真正记进账本**的放置次数
wildSkippedSince 窗口内被跳过的区外放置次数
```

- `Closure` **自己不下判决**（不判"空是不是问题"）—— 它只保证调用方与读日志的人**看得见人口**。
- `closure(...)` **架在已有两个视图之上**（`inZone` = `pendingTemporaryProtected`；
  `wildInLedger` = 裸视图 − 区内视图）⇒ **不复制**保护区判据，与 `pendingTemporaryProtected` 不可能漂移。
- 人口差值必须取**窗口起点基线**（`populationBaseline(...)`）：否则会静默退化成"自服务器启动累计"，
  读起来像"本步"、其实是全局（门禁第 ⑦ 臂就钉这一条）。
- `describe()` 只在**账本空**时展开解释是哪一种空（三种分支见 `Closure#describe`）。

## §5 门禁与**八条注入臂**（每条都实测变红，基线绿）

规则三条硬约束：① 闭合点只许用 `closure(...)`（不许裸 `pendingTemporary(`/`pendingForOwner(`）；
② 区内判据只有一个出处（`pendingTemporaryProtected` → `ProtectionZones.isProtected`）；
③ 空集必须可见（无条件人口行 + `recorded` 计数器 + 窗口基线）。

| 臂 | 注入 | 实测门禁输出 |
|---|---|---|
| ①a | 电池 `endStep` 退回裸 `pendingTemporary(` | 2 条（"还在用裸视图" + "没有用 closure 做闭合读数"） |
| ①b | 编排器退回 `pendingForOwner(` | 2 条（跨 scope 口径 + 与电池不同源） |
| ② | `pendingTemporaryProtected` 不再问 `ProtectionZones` | 1 条（保护区判据被绕开） |
| ③ | 去掉电池的**无条件**人口行 + 每轮汇总调用 | 2 条 |
| ④ | 生产侧（`clearTask` + `assignRestore`）退回裸视图 | 3 条 |
| ⑤ | `RestoreCheckItem` 退回裸视图 | 1 条 |
| ⑥ | 去掉 `recorded++` | 1 条（会把"写了又收干净"误报成"压根没写"） |
| ⑦ | 电池改传 `Population.ZERO`（基线退化成全局） | 1 条 |

> ⚠️ **臂③ 第一版没红**（本会话第 7 次"判据太弱"）：`endStep` 的**泄漏判红分支**里也用了
> `closure.describe()`，于是"删掉无条件人口行"仍满足判据。改成**同时钉人口行标记与数据**才红。
