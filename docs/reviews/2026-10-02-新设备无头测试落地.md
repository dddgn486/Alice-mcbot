### 1.1 ⚠️ Windows OpenSSH 的 shell 怪癖（必须知道，否则命令会被拆坏）

- 默认 shell = **Windows PowerShell 5.1**；
- ⛔ `ssh host 'a; b'` 这种"参数式"传命令会被**拆错**（实测把 `hostname; whoami` 拆成 `hostname -s` 与别的，报 `sethostname:` 错）；
- ✅ **正解 = 从 stdin 喂脚本**：`printf '...\n' | ssh host powershell -NoProfile -Command -`
  （`ssh host powershell -NoProfile -Command -` 中 `-Command -` 读 stdin）；
- ⚠️ 中文路径/中文输出：脚本里**用码点构造**中文名最稳，例如「新的世界」= `[char]0x65b0 + [char]0x7684 + [char]0x4e16 + [char]0x754c`
  （直接传中文会被按 GBK 解码搞坏）；读输出前 `[Console]::OutputEncoding=[Text.Encoding]::UTF8`。

## §9 ⭐⭐ 两个 `dsh web` 必须分清 ＋ 令牌每次重启都换

| | **本地（设备）** | **云端（codespace）** |
|---|---|---|
| 是谁 | **管家**（`alice-client` preset） | **助手 + 主工作流**（两个会话都在那） |
| 端口 | `127.0.0.1:`**`3081`** | 云端 3081 → 隧道映射到本机 **`3181`** |
| 启动 | `alice-web.cmd`（＝`dsh web --no-open`，前台） | `client-agent.cmd`… 不，走 `tools/codespace-tunnel.ps1 -Open` |
| 关闭 | **Ctrl+C**（前台）／`-WebStop` | 关 codespace（`gh codespace stop`），云端 `dsh web` 随之停 |

**桌面快捷方式（新设备，按端口命名以防混）**：`DSH local steward 3081.lnk` · `DSH cloud 3181.lnk`。

### §9.1 「最朴素的启动」（用户要求：`dsh` 带一堆参数启动经常一堆问题）

- ✅ 用：`dsh web --no-open`（**只有一个参数**，其余走默认；前台跑 ⇒ Ctrl+C 就是关闭）。
- ⛔ 实测反例（**本机 Windows 侧**）：`dsh web` 直接起不来 ——
  `cannot resolve profile bundle "@dsh-external/dsh-client-ui-skin-maid-atelier" … run 'dsh plugin --profile web install'`。
  即 `web` profile 挂的**第三方皮肤包没装** ⇒ 整个 profile 解不开。**这正是"参数/插件一多就出事"的真身之一**。
  （新设备的 `web` profile 干净：`profiles/` 只有 `headless` + `node_modules` ⇒ 起得来。）

### §9.2 令牌：**没法固定，但不必手动刷**

- **事实**：令牌是 `dsh web` **每次启动现生成**的一次性令牌，落在服务日志里（云端 `~/dsh-web.log`）；
  `dsh web --help` 只有 `host/port/no-open/trusted-host`，`settings.yaml` 里**无 token/auth 项**
  ⇒ **没有受支持的"固定令牌"办法**（不编）。
- **处置**：`tools/codespace-tunnel.ps1` **已经自动处理**：ssh 上云端
  `grep -o 'token=[A-Za-z0-9_-]*' ~/dsh-web.log | tail -1` ⇒ 拼 `http://127.0.0.1:3181/?token=<新令牌>` 并 `-Open`。
  ⇒ 用户体验 = **双击 `DSH cloud 3181`**。
- ⚠️ **后果**：云端重启后，**原来开着的标签页会 401** —— 不是坏了，是令牌换了，重开一次即可。

## §10 ⚠️ 反复骗到我的一个坑：**ssh 传给 Windows PowerShell 的脚本里不许放中文**

- **现象**：中文经 `ssh … powershell -Command -` 传过去，被按 **GBK** 解码 ⇒ 字符串被拆坏 ⇒
  报**莫名其妙**的解析错（本轮被咬两次：一次 `UnexpectedToken`、一次 `字符串缺少终止符: "。`）。
- **正解**：远程脚本**全 ASCII**；确实要中文（路径/文件名）就用**码点构造**（§1.1），
  或先把脚本写成文件再 `-File` 执行（文件带 BOM 就不会被 GBK 解）。
- ⭐ 这条值得记：**报错位置和真因无关**是它的特征 —— 看到"引号/括号没闭合"而肉眼看着明明闭合，先怀疑编码。

## §11 通道重定设计（2026-10-02 深夜，实测后定稿）

### 11.1 根因：**火绒（Huorong）** —— 这一整轮"神秘失败"的总根源

用户 2026-10-02 03:0x 亲眼看到火绒拦截了一个 ps 文件 ⇒ 顺着查出：

### 11.3 云端开机钩子：`postStartCommand`

- `devcontainer.json` 加 `"postStartCommand": "bash .devcontainer/post-start.sh || true"`
- `.devcontainer/post-start.sh`：建信箱 → 起 `dsh web`（已在跑则不动）→ 抓令牌 →
  用 **`git hash-object` + `mktree` + `commit-tree`** 把 `entry.txt` 做成**一次只含这一个文件的提交**
  推到 `steward/entry`（⇒ **不碰工作树**，钩子不会顺手把别的改动带进去）→ 再把
  `ENTRY_FORWARD_URL=` 打进容器日志（`gh codespace logs` 是第二条纯 API 兜底）。
- ⚠️ 全程 `set +e`、失败只记一行、最后 `exit 0` —— **开机钩子挂掉会让 codespace 起不来**，比"没发布地址"严重。
- **实测坑**：启动阶段**没有登录 shell 的 git 凭据** ⇒ `git push origin` 失败、分支不出现
  （手动跑同一脚本却成功）⇒ 改为显式用容器自带的 `GITHUB_TOKEN` 拼 push URL。
- **实测坑 2（未修完）**：`Available` 之后 `dsh web` **有时没被起起来**（pid 空、`steward-entry.txt` mtime 未更新）
  ⇒ 设备会**静默**读到**上一轮**的过期令牌。⇒ 待办：钩子里"确认 dsh web 真起来了"要带重试+失败留痕，
  且抓不到令牌时**保留旧条目标注"陈旧"**，别让设备静默拿到过期令牌。

### 11.4 ⭐ 为什么 UI 必须是**回环入口**（`CLOUD_MIGRATION §9-24` 源码级）

`dsh-client-ui-settings/lib/client.js:1345` = `persistence = ctx.remote.$host.isLoopback ? "host" : "memory"`

## §13 收尾：入口分支的"推力/拉力"两个静默失效（2026-10-02 03:2x）

### 13.1 推力侧：`non-fast-forward` 被 `2>/dev/null` 吞掉

云端钩子报 `WARN: git push failed - entry not published`，**看不到原因**（stderr 被吞）。
把 stderr 放出来才看到真因 = **non-fast-forward**（父提交对不上）。
⇒ 该分支语义 = **只存最新一条**（唯一写者是云端钩子，设备只读）⇒ **`git push --force` 才是正确语义**。

### 13.2 拉力侧：⭐ 普通 `git fetch` **拒绝**更新被强推过的追踪引用

修好推力侧之后，我在本机 `git fetch github steward/entry` 再读 —— **读到的还是旧令牌**
（`0nNcKSD4…`），而云端活令牌是 `NvD014Jz…`。
根因：**普通 fetch 对"非快进"的追踪引用更新会拒绝**（与 push 的保护同源）。
⇒ **拉力侧必须** `git fetch --force origin "refs/heads/<branch>:refs/remotes/origin/<branch>"`。
⚠️ 这个坑**正好在设备路径上**：`alice-cloud.ps1` 原来那句普通 fetch ⇒ **永远读到上一轮的令牌**
⇒ 用户打开就 401，而且**不报错**（最典型的静默失效）。已修 `07aaae18`。

**验证**：改后设备侧读到 `NvD014JzGWZGJIrMk8iDxTU54dsjtfYXsjgeQeknyIM`，
与云端活令牌**逐字一致** ✅。

### 13.3 我这一节又犯的两个错（记账）

1. **Python 替换没匹配上却打印"已成功"**：锚点带尾随空格 ⇒ 字符串没匹配 ⇒ 但 `print("已加 --force")`
   无条件执行 ⇒ 云端连跑三遍仍在报 non-fast-forward，我一度以为"改了没用"。
   ⇒ **纪律：替换必须 `assert` 锚点存在，成功信息只在 assert 之后打印。**（本轮犯了两次）
2. **把 `GITHUB_TOKEN` 的值打印进了对话**（`ghu_…`）。它是 Codespaces 的**临时**令牌
   （codespace 停止即失效、作用域限于该 codespace），但仍是**泄露**。
   ⇒ **纪律：任何 `echo $TOKEN` 式的调试输出必须写成 `${TOKEN:+yes}`（只说有没有，不说值）。**
