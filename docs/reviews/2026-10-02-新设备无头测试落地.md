### 1.1 ⚠️ Windows OpenSSH 的 shell 怪癖（必须知道，否则命令会被拆坏）

- 默认 shell = **Windows PowerShell 5.1**；
- ⛔ `ssh host 'a; b'` 这种"参数式"传命令会被**拆错**（实测把 `hostname; whoami` 拆成 `hostname -s` 与别的，报 `sethostname:` 错）；
- ✅ **正解 = 从 stdin 喂脚本**：`printf '...\n' | ssh host powershell -NoProfile -Command -`
  （`ssh host powershell -NoProfile -Command -` 中 `-Command -` 读 stdin）；
- ⚠️ 中文路径/中文输出：脚本里**用码点构造**中文名最稳，例如「新的世界」= `[char]0x65b0 + [char]0x7684 + [char]0x4e16 + [char]0x754c`
  （直接传中文会被按 GBK 解码搞坏）；读输出前 `[Console]::OutputEncoding=[Text.Encoding]::UTF8`。

## §3 ⭐ Windows 原生驱动 `tools/client-agent/run-headless.ps1`

**为什么新写**：`tools/headless-battery.sh` 是 bash（`pgrep/mkdir/cp/seq`）⇒ 没装 WSL 的设备跑不了。
真机制只有一行（`headless-battery.sh:371`）：

```
java -Xmx3G -Dalice.headless.battery=<MODE> @user_jvm_args.txt @libraries/.../{unix|win}_args.txt nogui
```

判决落在 `<服务端目录>/headless-result.txt`（另两份 = stdout 与 `logs/latest.log`）。
驱动把这套**原样**搬到 PowerShell（`unix_args.txt` → **`win_args.txt`**），退出码与 bash 版**逐字一致**
（0=PASS 1=FAIL 2=DEGRADED 3=没等到判决 4=起不来 5=脚本自身）。

## §4 ⭐⭐ 首跑抓到的真缺陷（**全是"静默失败"**，逐个实测修掉）

| # | 缺陷 | 症状（实测） | 修法 |
|---|---|---|---|
| 1 | **Java 不读 `HTTP_PROXY`** | Forge 安装器停在 `DownloadUtils.downloadLibrary`、反复超时；`& java …` 里设的 `HTTP_PROXY` 环境变量**对 Java 无效** | 设 `JAVA_TOOL_OPTIONS=-Dhttp(s).proxyHost/Port`；实测 stderr 出现 `Picked up JAVA_TOOL_OPTIONS:` 后立刻越过 |
| 2 | PowerShell 传 `--installServer` 被解析坏 | `Unrecognized option: --installServer` / `Could not create the Java Virtual Machine` | 改 `Start-Process -ArgumentList @("-jar",$jar,"--installServer") -Wait` |
| 3 | `Copy-Item -Path` **漏名字带 `[` `]` 的模组** | `[JEI物品管理器] …` / `[FTB 区块] …` 等 **4 个 jar 静默没进服务端**（20 → 15） | 一律 `-LiteralPath`（`[` `]` 在 `-Path` 里是**通配符字符类**） |
| 4 | **漏了客户端专属模组名单** | `jecharacters` 在专用服务端 `NoClassDefFoundError: net/minecraft/client/searchtree/SuffixArray` ⇒ `Failed to complete lifecycle event CONSTRUCT` ⇒ 服务端 **12 s 退出、永远等不到判决** | 按 `headless-battery.sh:128` `CLIENT_ONLY_DEFAULT` **逐字**补 3 条（拼音搜索 / JEI / Xaero 地图） |
| 5 | Alice jar 只认仓库产物 | 新设备不构建 ⇒ 没有 Alice mod ⇒ 电池不会跑 | 仓库 `build/libs` 没有时**回退用客户端 mods 那份**（用户定的分工：**测试机只跑测试，jar 由本机构建后传**） |
| 6 | Java 版本策略 | 自动挑**最高的**（21） | 改为**优先恰好 17**（MC 1.20.1 的目标版本；本机 bash 电池用的就是 17） |
| 7 | **漏了世界洁净度整套**（★ 最隐蔽） | 见 §5 | 补 4 步：场景数据包 / 第三方认领 / `alice_*.dat` / 清空 mods |

## §5 ⭐⭐ 那条多出来的红：`decision_contract=FAIL reason=菜单含 lumber 候选`

**现象**：新设备 CORE = **42/44**，两条红 = `mine_regression`（**已登记预期红**，`EXPECTED_REDS.md` 有主）
＋ `decision_contract`（**未登记**）。而本机 1033 轮日志里 `decision_contract` 是 **503 PASS / 0 FAIL**。

**排除法实测**：

| 假设 | 实验 | 结论 |
|---|---|---|
| Java 21 的跨版本差异 | 用 **Java 17** 重跑整轮 CORE | ❌ **排除**：结果**完全相同**（42/44，同两条红，`ticks` 3767 vs 3782） |
| jar 版本 | jar 已 sha 对账（`dc286d5b`），且旧 jar 在本机历史上也 PASS 过 | ⚠️ 减弱但不排除 |
| **世界洁净度** | 读 `headless-battery.sh:246-295`：**四步我全漏了** | ✅ **根因** |

**为什么是认领**（脚本注释逐字）：夹具世界是**玩家存档的副本** ⇒ **继承玩家的 FTB Chunks 认领**，
而认领内的破坏/放置被 FTB **静默取消** ⇒ 夹具拿到"树砍不动"的世界、**却报成内核失败码**
（`lumber_job` **连红 35 轮**的真因；`D-409`/`D-413`）。而 `菜单含 lumber 候选` 正是这一族症状。

**修法**（补进驱动，与 bash 版逐步对齐）：
1. `datapacks/alice_test` **以仓库版为准** + 清同命名空间旧包 + **断言只剩 1 个提供者**（`D-412`，⛔ 旧包会**静默盖住**场景）；
2. **清 `world/ftbchunks/*.snbt`**（`D-409`/`D-413`）；
3. **清 `world/data/alice_*.dat`**（`D-235`：假人存档会让起服崩、跨轮残留污染判决）；
4. 装模组前**清空 `mods/*.jar`**。
