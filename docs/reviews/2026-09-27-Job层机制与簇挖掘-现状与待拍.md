# Job 层机制 与 簇级连续挖掘 —— 现状对照 + 待拍清单（2026-09-27 讨论产出）

> **性质**：**纯讨论产出，零裁定、零代码改动**。用户原话：「先处理断点，等我压缩完一个一个拍」。
> ⇒ 本文的作用 = **压缩后仍能逐条拍**（每条自带提案 / 推荐 / 代价 / 不到做的后果 / 出处）。

## §0 一句话

`LumberJob` 的**接口面**（8 件契约）基本齐，**编排面**（相位承载编排）与**簇机制**（无重扫、无统一循环器）是缺口；
本轮的结论是：**把这些缺口收敛成"step 化 + 有界循环器 + 前置两处可红"**，并把 `MineTask` 视作**该被抽干的壳**（依附 goal 化）。

### 1.6 `MineStep` 的宿主 = `MineTask`（编排器）

- `MineTask.step()` **惰性创建、同一实例贯穿**（`tryReplan` 在它上面重算）——`D-466` §五；
