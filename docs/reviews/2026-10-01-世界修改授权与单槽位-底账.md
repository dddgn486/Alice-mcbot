# §5 `A2` · 两个使用场景的判据形状（实测；2026-10-01 甲串轮 1）

### `Q2` 的三条证据：「非目标」**今天没有机械判据**

**证据 ①（文档 vs 代码）**：`TaskZoneRegistry:42-45` **逐字声称**判据是「**目标集**」：

## §6.2 ⭐ 病根：**"没权限"被算成"少了一棵树"**

`RegionLumberJob` 的三行（`:557-579`）**只数 `raw.viable()`**：
```java
int viableInRegion = 0;
for (Candidate candidate : raw.viable()) { … viableInRegion++; }     // ⛔ 只数许可过的
int standing = viableInRegion + mySaplings;
if (!state.baselineDerived(...)) { state.setBaselineTrees(uuid, standing); … }
int deficit = Math.max(0, state.baselineTrees(uuid) - standing);      // ⛔ 无权的树 ⇒ deficit 上升
```
⇒ 权限把树踢出 `viable` ⇒ `standing` 下降 ⇒ **`deficit` 虚高** ⇒ 触发**本不该触发**的「补种」「去扫地面」分支。

## §6.3 今天靠**两层下游补丁**把这个假原因挡回去（⛔ 结构没变）

| # | 补丁 | 位置 | 逐字理由（代码注释） |
|---|---|---|---|
| 1 | `D-341`：`inRegion.isEmpty()` 时去 `raw.rejected()` 里找 `permanentDenial` 码 ⇒ `no_permitted_candidate` **如实失败** | `RegionLumberJob.java:591-605` ＋ `permissionBlock():827-850` | 「**"无权" ≠ "没有"**……5 棵树全 `zone_break_not_allowed`」被当成"没树" ⇒ 每 ~2 s 一行、空转到 `maxTicks=24000`（20 分钟）」 |
| 2a | 该闸**必须放在补种之前** | `:595` | 「否则 `deficit>0` 会先跑去补种、把真正的阻塞原因（没权限）盖成假原因」 |
| 2b | 该闸**必须放在扫地面之前** | `:611` | 「否则"没权限"会被"欠树 ⇒ 去扫地面"盖成假原因」 |

⇒ ⭐ 两条补丁的注释**逐字承认了病根**：权限混进识别 ⇒ 下游必须靠**顺序**把假原因挡回去。
⇒ 症状（空转 20 分钟）消失了，⛔ **但 `deficit` 依然把"无权"算成"没有"**。

## §6.4 ⚠️ 同一族的两处不一致（顺手量到）

**① 同一个"区域里有几棵树"有**两份真相**。**
`tallestTreeTopY()`（`:985-990`）**直接**调 `TreeScanner.scan(...)`（**不过权限**），
而 `viableInRegion`/`standing`/`deficit` 走 `raw.viable()`（**过权限**）。
⇒ 一棵"没权限的高树"**仍会抬高 `effectiveTop`**，却**不计入 `standing`**。

**② 补种是唯一绕开区域授权放置闸门的世界写入。**
`RegionLumberJob.java:971` `level.setBlock(spot, placed, 3)` 是 `job/` ＋ `task/` 全仓**唯一**一处 `setBlock` 直写
（第二种口径：`grep -rn '\.setBlock(' job/ task/` ⇒ 仅此 1 处命中；`task/PlaceTask.java:30` 是 **javadoc 提及**）。
而 `ZoneAuthority` 的放置闸只挂在 `action/BlockInteraction.java:331` / `:670`；
⭐ `write/WriteBudget.java` 里 `ZoneAuthority` 引用数 = **0**（`consumePlace` **不做**区域授权）。
⇒ 补种**既不做识别的权限判定，也不做写世界的权限判定**。
⚠️ 它的 javadoc（`:942-944`）登记了"绕过 `placeAt`（快捷栏限制）"这条残留，⛔ **没提绕过授权闸门**这条。

**③ ⚠️ 目标棵数 baseline 是**持久化**的，而过滤它的权限是**进程内**的（未追到底，仅登记）。**

## §6.5 ⇒ 对 `A2` 的意义

⭐ 若按用户原则（**区域任务识别目标、权限不参与**），正确形状应是：
**目标识别只看"这一格是不是我要办的事"；权限在写入那一刻一次性消费。**
今天**恰好反过来**：**识别期过滤（砍树）、写入期反而漏（补种）**。
⇒ 这把 `A2` 裁点 2 从"要不要给内核自服务侧加位置范围"扩成一条更对称的话：
**两侧都要把「识别」与「授权」拆开 —— 识别不查权限，授权在写入唯一一次。**
