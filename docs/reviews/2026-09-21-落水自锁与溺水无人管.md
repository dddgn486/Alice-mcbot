## 2. 修法（`D-377`，两处 + 一个只读读数 + 一个夹具）

| # | 改动 | 位置 |
|---|---|---|
| 1 | `task == null` 不再直接返回，改调 `tickHazardWithoutTask(hazard)`：只做三档（有出口 ⇒ 起逃生；浮得上去 ⇒ 起自救；无出路 ⇒ 每个 episode 如实登记一次），**恒为纯通行判决**（无任务=没有写信封） | `BotManager.BotSession` |
| 2 | 新常量 `DROWN_PRECURSOR_AIR = 100` + **沉底提前自救档（只对无任务生效）**：分类还是 `WATER_CONTACT`（不是软危险）时，无任务 bot 也要先浮上去 | `SurvivalSystem` + `BotManager.tickHazardWithoutTask` |
| 3 | `BotManager.hasTask(bot)`：只读读数 —— 让"有没有任务"能被**断言**，而不是靠陈旧 `taskKind` 猜 | `BotManager` |
| 4 | 夹具 `SurvivalIdleDrownCheckTask`（电池步 `survival_idle_drown`，EXTRA）：**第二个假人**（天然无任务）+ 自建 1 格宽水井（规划不出"走出去"的路 ⇒ 判决必为 `FLOAT_UP`） | 新文件 |

## 3. 验证

  `watch=41 eyeOut=true y=-60.99` → 拆除时 `air=103`（≥`AIR_SAFE`）。

- 门禁 `[D-377·危险处理不挂任务]`：**10/10 注入变红且各命中专属条目**，恢复后 PASS。
- 回归：CORE **51/52（仅既有 `lumber_job`）**、`survival_exit=PASS`、`check-all` 19/1/0。

## 3.5 ⚠️ 第一版设计被 CORE 打回：阈值不能写进共享分类表

第一版把「眼在水里 + `air ≤ 100` ⇒ `LOW_AIR`」写进了 `SurvivalSystem.Monitor.classify` ⇒ **CORE 直接
`no_verdict`**：电池步 `survival_exit` 的「开阔水池」相位**本来就故意**把 bot 弄成 `air=5` + 眼睛在水里
（它要单独测上浮机制，夹具注释里写着"掉到 0 就变成真的 LOW_AIR 软危险 ⇒ 打死整轮电池"），
于是被当成真溺水 ⇒ `FLOAT_UP` 分支 `complete(..., SURVIVAL_INTERRUPTED)`
（`task_execution_terminal kind=RegressionBattery`）⇒ **电池任务本身被中断**、判决行永远不出现。

⇒ 收窄成「只对**无任务**生效」（放在 `tickHazardWithoutTask` 里，不动共享表）后 CORE 回到
**51/52（仅 `lumber_job`）**、`survival_exit=PASS`。门禁也加了一条反向断言：阈值不许出现在 `classify` 里。
- 夹具自身的两个坑（都当场修掉，记下来免得重犯）：
  ① 第一版在**宽限期内**（`SOFT_HAZARD_GRACE_TICKS=10`）断言 `verdict == FLOAT_UP` ⇒ 判据读的是
     夹具自己的时序，不是缺陷（改成用 `synthetic(LOW_AIR, grace+1)` 跳过宽限期）；
  ② 第一版把分类判据写在"刚设完空气"的**同一 tick** ⇒ 读到监视器**缓存**的旧分类（探针假人的会话
     可能已先 tick 过这一 game tick）⇒ 改成**观察期逐 tick 记录** `sawLowAir`；
  ③ 超平坦测试世界的地面只有 4 层 ⇒ 4 格深的水井会挖穿地板、红态下 bot 掉进虚空 ⇒ **井底自补一块实心**。

## 4. 未做（诚实边界）

- 自救成功后 bot 会**缓慢再次下沉**（空气掉回 <100 ⇒ 再触发一次自救）⇒ 观感是"浮一下、沉一下"，
  但**不会再淹死**。真正"维持浮力"要改 `SurvivalFloatTask` 语义，是单独一件事。
- `ABANDON_NO_EXIT` + **无任务**（封闭水牢、浮不上去）仍只能如实登记 —— 要真救出来需要
  "水中上浮 / 搭方块出水"的新能力（原 `B3`）。
- 原 `B3`（K-3 延后停止在**不安全时刻**落地，是本次链条的起点）**仍待用户裁定**：
  建议"有活动危险时不许把延后停止落地"，但它会改变 `/alice stop-task` 一类显式命令的响应语义。
