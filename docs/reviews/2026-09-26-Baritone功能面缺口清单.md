# Baritone 功能面 → Alice 实现状态清单（2026-09-26）

> **性质**：只读审计（不修改任何生产代码）。目的 = 回答「**到底还有哪些 Baritone 功能我们没实现**」，
> 而不是「差多少才像 Baritone」—— `D-036` 只要求**内核语义**对齐，**不要求功能面照抄**。
>
> **方法**：8 个区域并行审计（每区域逐类枚举 Baritone 侧，再在 Alice 侧 grep 找对应物）。
> **证据纪律**：每条「缺失/部分」都写明**搜过的词**与「0 命中」，可逐条复核；
> 「刻意不做」必须给 `D-编号`。**复核命令**见 §4。
>
> **状态词汇表**（四态，互斥）：
> `已实现` = Alice 有等价物（给路径）· `部分` = 有但不完整（写明缺什么）·
> `刻意不做` = 已有裁定（给 `D-编号`）· `缺失` = 没有实现且无裁定。
>
> **引用树**：审计时使用的是 `reference/baritone/`（MC **1.21.4**）；事后已把带行号的引用在
> `reference/baritone-1.20.1/`（MC **1.20.1**，与 Alice 同版本）上复核：**文件缺失 0 · 行号超界 0**。
> 两树行号差异 ≤2 行（唯一 api accessor 差异 = `ILootTable`）。要下钻请优先用 1.20.1 那棵树。
>
> **局限（必须先读）**：① 全轮是**静态审计**（grep + 逐行对照），**没有运行时验证**；
> ② 「有类/有方法」不等于「能用」，`部分` 那些条目的真实可用性以自检电池为准；
> ③ 区域之间对同一机制可能有重复视角（已折叠 1 条，见 §3 脚注）；**跨区域同题计数**：
> `BuilderProcess` / `Settings` / `PathExecutor` / `AStarPathFinder` / `CalculationContext` /
> `InventoryPauserProcess` / `WaypointBehavior` 这 7 个文件被两个区域各写了一条（**不同视角**，
> 如 `PathExecutor` 一个讲漂移/成本、一个讲执行期区块加载）⇒ §0 会各计一次，但 **§1 已去重**。
> 同理 `cache_selection` 里 9 条 `缺失` 多数是**同一个已裁定延后项**（`D-044`⑤ / `D-067`⑧ 的异步快照层）
