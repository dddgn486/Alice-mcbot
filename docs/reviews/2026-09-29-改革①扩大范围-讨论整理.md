## §1 已核实的事实（每条都可复核）

**F1 · Baritone 的三条挖掘到达形状是"两道工序"，不是"宽/严"**
`reference/baritone-1.20.1/src/main/java/baritone/process/MineProcess.java:260-268`（`coalesce` 默认分支）逐字：

```java
boolean assumeVerticalShaftMine = !(baritone.bsi.get0(loc.above()).getBlock() instanceof FallingBlock);
if (!forceInternalMining) {
    if (assumeVerticalShaftMine) return new GoalThreeBlocks(loc);   // 默认分支
    else                        return new GoalTwoBlocks(loc);      // 注释逐字：
}                                                                   //   "we need to get feet or head into the block"
```

| 目标 | 到达脚位 | 语义 | 到达时目标格 |
|---|---|---|---|
| `GoalTwoBlocks` | `y`、`y−1` | **feet or head <u>into</u> the block** | **必须已破坏** |
| `GoalThreeBlocks` | `y`、`y−1`、**`y−2`** | 「we can get **directly below** the block」= 垂直矿道仰挖 | 可以**未破坏** |

⇒ Baritone 的**默认**是 `GoalThreeBlocks`（站到下方仰挖）；`GoalTwoBlocks` 只在**上方压着重力方块**时用。

**F2 · 三种途径与 Baritone 形状是一对一的**
| 途径 | 语义 | Baritone 对应 |
|---|---|---|
| ① 原地挖 | 已经站在能挖的位置（不规划） | `MineProcess.java:117-137` 的 `shaft` 快路径 |
| ③ 找站位挖 | 枚举一个"能挖的位置"，**含正下方 `y−2`** | `GoalThreeBlocks` 的到达集 |
| ② goal 式 | **走进去**（到达 ⇔ 破坏） | `GoalTwoBlocks` |

**F3 · ③ 的候选集严格包含 Baritone `GoalThreeBlocks` 的到达集**
`src/main/java/com/dddgn/alice/reach/StandingPointSelector.java:56-59` 逐字：`belowDepth = Math.max(1 + BELOW_LEVELS, (int) Math.floor(reach + 1.54D))`，循环 `for (int k = 2; k <= belowDepth; k++) addCandidate(level, target, target.below(k), reach, result);`
⇒ `y−2` 一定在集内；且水平环（`dy∈{+1,0,−1}`）还多给 Baritone **没有**的侧面格。
⇒ **几何上「只取 `GoalTwoBlocks`」一格不丢。**

**F4 · ③ 的候选路径**不允许破坏世界**（`PathRequest` 只有两种能力集）**
`src/main/java/com/dddgn/alice/reach/StandingPlanSelector.java:157,168,170` 逐字：
`boolean placementAllowed = approach == ApproachCapability.PLACEMENT_ALLOWED;` … `placementAllowed ? PathRequest.withPlacement(…) : PathRequest.of(…)`
而 `src/main/java/com/dddgn/alice/reach/ApproachCapability.java` **只有两个取值**（`PURE_PASSAGE` / `PLACEMENT_ALLOWED`），二者的能力集都**不含 `BREAK_AND_*`**（`src/main/java/com/dddgn/alice/pathing/core/search/PathRequest.java:129-136` / `:75-80`）。
⇒ **③ 只能"走过去"或"搭过去"，不能"挖过去"。**

**F5 · ③ 的候选路径是"逐候选 top-K 全预算 A\*"，且排名有上限**
`src/main/java/com/dddgn/alice/reach/MiningTuning.java:67-68` 逐字：`exactTopK = 4` · `exactTopKMax = 10`。
`src/main/java/com/dddgn/alice/reach/StandingPlanSelector.java` 的 `selectBest`：K 从 4 起、每次 +2、**K 不得超 10**；只有 `best == null && k < exactTopKMax()` 才继续扩。

**F6 · `GoalAdjacent` 的到达集是"4 水平邻格 ＋ 正下方"，且**明确排除**「脚在目标格」**
`src/main/java/com/dddgn/alice/pathing/core/search/GoalAdjacent.java:115-129`（四条第①条 = `if (foot.equals(target)) return false;`）。
⇒ 与 `GoalTwoBlocks`（`{目标格, 正下方}`）**只共有 1 格**。

**F7 · Alice 已有「水位例外」，而且与 Baritone 的取值**正好相反**
- Alice：`src/main/java/com/dddgn/alice/pathing/MovementHelper.java:49-63` —— 下面那格是水时，`return isWater(level, footPos) && !isWater(level, footPos.above())`（**只认水面格**）；理由逐字：「假人靠按住跳跃浮在水面…**潜不到水里** ⇒ 合法位置集只放执行器真到得了的格子（K-4）」；已登记 `D-251`。
- Baritone：`reference/baritone-1.20.1/src/main/java/baritone/pathing/movement/MovementHelper.java:435-455`（`canWalkOnPosition`）—— `return isWater(upState) ^ Baritone.settings().assumeWalkOnWater.value;`（默认 `false` ⇒ **要求头位也是水** = 允许潜水）。
⇒ **两条规则的判据互为反面**；Alice 的窄化是**已登记的设计差异**，且由 K-4 驱动。

**F8 · Alice 缺 `avoidAdjacentBreaking`（真空白）**
Baritone `reference/baritone-1.20.1/src/main/java/baritone/pathing/movement/MovementHelper.java:68-100`：`avoidBreaking` = ① 世界边界 ② `blocksToDisallowBreaking` ③ **冰**（挖了变水）④ **`InfestedBlock`** ⑤ **四邻 ＋ 上方的 `avoidAdjacentBreaking`**（侧邻是流体 / 侧邻是**未支撑的重力方块** ⇒ 禁挖）。
Alice 已有：流体不可挖（`src/main/java/com/dddgn/alice/protection/BlockBreakSafety.java:54`，逐字对照 Baritone `getMiningDurationTicks:588-590`）· 清障不吃任务目标（`D-362`）· 写入预算（`D-106`）。
**缺**：③ ④ ⑤（②名单位于设置层，Alice 走 job 声明）。
⭐ ⑤ 的**一半载体已存在**：`src/main/java/com/dddgn/alice/pathing/core/AscendExecutionFactory.java:65-70` 已在用 `FallingBlock` ＋ 支撑判据（注释逐字对照 Baritone `MovementAscend:96-108`）。

**F9 · Alice 缺「正上方重力方块 ⇒ 计价」**
Baritone `reference/baritone-1.20.1/src/main/java/baritone/pathing/movement/MovementHelper.java:580-606`（`getMiningDurationTicks`）的 `includeFalling` 分支：`if (above.getBlock() instanceof FallingBlock) result += getMiningDurationTicks(context, x, y+1, z, above, true);`
Baritone 的**分工**逐字（`:89-95`）：正上方 = **计价**（注释「it is fine to mine a block that has a falling block directly above」）；**侧邻** = **禁止**（`avoidAdjacentBreaking`）。
⇒ Alice 两者都缺，但**分工**必须逐字照搬（一个计价、一个禁止）。

**F10 · 搜索侧已具备「破坏进入」的全部机制，缺的只是那个目标类**
- 边：`src/main/java/com/dddgn/alice/pathing/core/search/SurfaceMovementProvider.java:147` `BlockPos to = from.offset(dx, 0, dz);`（**水平**边）＋ `:189` `if (!MovementHelper.canWalkOn(level, to)) return;`（目的地最终可站）
- 代价：`:207-208` `cost = context.cost(TRAVERSE,…) + (breakTicks + CostModel.BREAK_PENALTY_TICKS) / WALK_ONE_BLOCK_TICKS`，而 `src/main/java/com/dddgn/alice/pathing/core/search/CostModel.java:43` `BREAK_PENALTY_TICKS = 2.0D` 与 Baritone `blockBreakAdditionalPenalty` **已逐字对齐**
- 授权豁免：`src/main/java/com/dddgn/alice/job/mine/MineJob.java:1009` 逐字 `if (pos == null || pos.equals(current)) return false;`，其 javadoc 逐字写「`ENTER_TARGET` 模式就是"破坏进入目标那一格"（路径自己把那格挖开），一刀切保护会把这条腿打断（`enter_target_unreachable`）」
⇒ `GoalTwoBlocks` 的两个到达值（`to = target` / `to = target.below()`）**都有现成边**。

**F11 · `GoalTwoBlocks` 可以被守卫正确覆盖（⇒ 该取 `exactFoot()==true`）**
两个到达脚位 `(tx,ty,tz)` / `(tx,ty−1,tz)` **同列**（Y 不影响区块）⇒ 唯一目标区块可预检 ⇒ `src/main/java/com/dddgn/alice/pathing/core/search/AStarMovementSearch.java:63,71` 的 `GOAL_NOT_LOADED` 前置守卫**能生效且语义正确**。
⇒ ⛔ **不需要**进 `tools/check-far-goal-usage.py` 的登记表（该表只收 `exactFoot()==false` 的实现）。

**F12 · `GOAL_NOT_LOADED` 不在「诚实读数」里（Alice 自有潜伏洞，不是 Baritone 差异）**
`src/main/java/com/dddgn/alice/pathing/core/search/SearchConclusion.java` 的 `inconclusive(status)` 逐字只认 `SEARCH_LIMIT` 与 `PARTIAL`。
⇒ 一旦某条腿取 `exactFoot()==true`，目标区块未加载 ⇒ `GOAL_NOT_LOADED` ⇒ `inconclusiveReason` 返回空串 ⇒ 调用方落到"不可达"分支 ⇒ **永久理由** —— 与 `P1-b`/`P1-d` 要修的那一类翻转**同形**。`GOAL_NOT_LOADED` 的语义就是"**根本没跑**"，与 `SEARCH_LIMIT` 同类。
⚠️ **今天就能撞**（`GoalFoot` 型目标都是 `exactFoot()==true`），不是本次引入。

**F13 · ② 的到达隐含破坏 ⇒ 与执行期写入形成新耦合**
`GoalTwoBlocks` 的到达前提是那条 `BREAK_AND_ENTER` 边被**执行期**真的完成；若执行期破坏被拒（写入预算用满 / 保护谓词 / 复检否），会出现"规划说到得了、实际到不了"。
Baritone 无此耦合：`GoalThreeBlocks` 到达**不要求**破坏，破坏是到达后由 `shaft` 快路径去做的。

**F14 · 异步 rescan 是 Baritone **自己**那个竞态的成因**
`reference/baritone-1.20.1/src/main/java/baritone/process/MineProcess.java:156` 注释逐字：「elaborate dance to avoid concurrentmodificationexcepption **since rescan thread reads this**」（配套 `:150-163` 的 `anticipatedDrops` copy-swap）。
⇒ Alice 不挂那个线程 ⇒ **不承担那个竞态**。

## §4 A / ② 的职责边界（本轮最重要的结构结论）

**从 U1＋U2＋U3 推出来的边界**（⚠️ 机制部分 = AI 的**推导**，见 §7 `Q1` 待你确认）：

| 腿 | 职责 | 到达集 | 路径能力集 |
|---|---|---|---|
| **③ (A)** | ⭐ **只选站位**（"这个站位对目标是暴露的"= 可站 ＋ 视线 ＋ 触及） | —— 不给到达 | `PURE_PASSAGE` / `PLACEMENT_ALLOWED`（**保持不扩权**） |
| **② (B 替代)** | (i) 「走进去挖掉」；(ii) **到 ③ 交出的站位的可挖穿路径** | `GoalTwoBlocks` / `GoalFoot(③ 的站位)` | **含 `BREAK_*`**（`MINING_APPROACH_MOVEMENTS`） |
| **①** | 已经站在能挖的位置 ⇒ 真眼位 ＋ LOS ＋ 触及，直接挖 | —— | —— |

**⭐ 关键的一处行为改动（丙组 C1）**：③ 今天把"**改世界才能到**"当成失败（`STANDING_NO_REACHABLE` / `no_reachable_candidate`，且是**永久理由**）。
按 U2/U3，这必须是：**站位有效但"不改世界到不了" ⇒ 不许报失败，要交出站位让 ② 接手。**
⇒ 这与既有红线 **`SEARCH_LIMIT ≠ UNREACHABLE` 同构**：**「需要改世界才能到」≠「不可达」**。

**为什么 §4 能同时满足 U3 与 `D-531`**：`D-531` 管的是「**走进去**」这个模式的到达集（`GoalTwoBlocks`）；
而"到 ③ 的站位"是**另一件事**——它的到达集是**一个具体脚位**（`GoalFoot`），**不在 `D-531` 的射程内**。
⇒ ② 因此有两种到达：**模式 (i) = `GoalTwoBlocks`**、**模式 (ii) = `GoalFoot(站位)`**。

## §5 与 Baritone 差异的分层（回应"怎么还有这么多差异"）

⚠️ AI 前一轮把三类东西混在一张表里，放大了焦虑。分层如下：

**第一层 · 已登记的设计差异（不是新差异，⛔ 不需要"修"）**

**第二层 · 真正**未登记**的对 Baritone 差异 —— **只有 2 条****
`F8`（缺 `avoidAdjacentBreaking`）· `F9`（缺正上方重力方块计价）。
⇒ 这两条**本来就属于"把 Baritone 挖掘搬过来"这一刀该补的东西**，不是"内核坏了要修"。

**第三层 · **不是** Baritone 差异的东西**
`F12`（`GOAL_NOT_LOADED` 不在诚实读数里）= **Alice 自有的潜伏洞**（`P1-b`/`P1-d` 那条红线的第三个形态）。
`R2`/`R3` = AI 的表述失误。
`F4` = **分工**（不是差异：按 U1/U3，A 不拥有路径 ⇒ "A 不能挖过去"不构成偏差）。

⇒ **结论**：内核**不需要"修复"**，需要 **1 个类（`GoalTwoBlocks`）＋ 1 行（`SearchConclusion.inconclusive`）**。
