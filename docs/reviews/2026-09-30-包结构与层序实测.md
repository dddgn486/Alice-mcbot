**它是权限内核，不是执行器** —— Alice **唯一**的世界写入凭证面（6 个类 / 2,158 行，`D-462` 从 `action/` 拆出）：

## §3 读数②：生产面是**一个结**，不是一条链

摘掉验证/入口侧后，生产面 **18 个包**里 **13 个互相可达**：

```
action · bot · compat · decision · job · ledger · pathing · protection · reach · road · survival · task · write
```

**层方向具体断在 7 对双向环**（括号 = 两方向的引用点数）：

| 🔁 环 | 处数 | 代表调用点 |
|---|---|---|
| `action ⇄ pathing` | 4 : 15 | `action/MineBlockRunner` → `pathing/MovementHelper` ／ `pathing/core/BreakAndEnterExecution` → `action/BlockBreakSession` |
| ⭐ `pathing ⇄ write` | **21** : 2 | `pathing/core/BreakAndEnterExecution` → `write/WriteReason` ／ `write/WritePolicyMatrix` → `pathing/core/MovementType` |
| `bot ⇄ task` | 5 : 29 | `bot/BotManager` → `task/MineTask` ／ `task/CollectDropsTask` → `bot/BotPlayer` |
| `bot ⇄ decision` | 1 : 21 | `bot/ManualTestLock` → `decision/BotEventLog` ／ `decision/BotEventLog` → `bot/BotPlayer` |
| `bot ⇄ pathing` | 1 : 12 | `bot/BotManager` → `pathing/MovementHelper` ／ `pathing/PathRetryRunner` → `bot/BotPlayer` |
| `bot ⇄ survival` | 2 : 1 | `bot/BotManager` → `survival/HazardState` ／ `survival/DamageLedger` → `bot/BotPlayer` |
| `decision ⇄ job` | 3 : 1 | `decision/CandidateMenu` → `job/lumber/LumberRegionState` ／ `job/craft/CraftJob` → `decision/MachineMap` |

**＋5 条更长的环**：`reach → pathing → action → reach` · `compat → bot → task → compat` ·
`ledger → action → bot → task → ledger` · `protection → compat → bot → task → protection` ·
`road → action → bot → task → road`

⚠️ **层次今天只以 3 条窄断言的形式存在**（`tools/check-layer-direction.py`）：
`reach/` ✗→`{task,action,job}` · `write/` ✗→`{task,action,job}` · `action/` ✗→`task`。
**其余方向没有判据** ⇒ 实际有 7 对双向环 ＋ 5 条长环，断言只覆盖 3 条边。

## §7 读数⑥：`Task` 的接口面（回答「**顶层单元是什么**」）

`BotSession` 上只有**一个槽**（`BotSession.task`），每个 bot 每一刻只被**那一个**东西驱动
⇒ **「顶层单元」= 那个东西**（`O66` §③(a) 早已点出「框架驱动的顶层单元**不止 job**」）。

`task/Task.java` 的接口面一共 **10 个成员**：

| 成员 | 该不该是"槽位合同" |
|---|---|
| `Status tick()` · `TaskTarget target()` · `default boolean safeToCancel()` · `default void onTerminated(...)` | ✅ 驱动的需要 |
| `failureReason()` · `taskName()` · `terminalReason()` · `failureReport()` | 🟡 **记账汇报**的需要 |
| ⚠️ `isSelfCheck()` · `looksLikeSelfCheck(String)` · `SELF_CHECK_MARKERS` 字段 | ❌ **3 个是"夹具/自检"专用** |

⇒ 「**收窄的顶层契约**」= 把后两行请出槽位合同。名字用户已批 = **「顶层单元」`TopUnit`**（`D-551` ③）。

## §22 编排器 `CheckHarness`（`fixture/check/CheckHarness.java`）

## §23 一步 = `CheckStep`（九个字段，这就是夹具的规格书）

```java
record CheckStep(String name, CheckProfile profile, List<String> scenes, Runnable provision,
                 Supplier<Task> factory, int budgetTicks,
                 Predicate<Task> doneWhen, Predicate<Task> skipWhen, boolean keepWorldState)
```
`profile`：`BASELINE`/`MAIN` 进 CORE、`EXTRA` 只在 FULL 跑 ·
`scenes`：数据包函数 `function alice_test:…` · ⭐ **`provision`：起任务前的一次性准备（传送／<u>发料</u>／清库存）** ·
`factory`：**每步一个可独立运行的任务** · `skipWhen`：环境不具备 ⇒ **skip（不是假绿）** 进 `DEGRADED` ·

## §24 编排器每一步的三相位时序（`tick()`，逐行核实）

```
phase 0  等空闲（isBusy=false；超 WATCHDOG ⇒ 红）
         ├─ ⭐ 先 openScope（账本作用域）
         ├─ stopMovement
         ├─ ⭐ step.provision().run()          ← 先发料/传送（把区块热起来）
         ├─ ⭐ 再跑 scenes 的 /function（rc<=0 ⇒ 响亮告警，D-251）
         └─ phase 1
phase 1  前提自证（关残留菜单 · 等落地，每 tick 复检，超时红）
         ├─ Driver.set(bot, Driver.FIXTURE)    ← 归因位
         ├─ task = step.factory().get()
         └─ beginSelfCheckTaskInOpenScope(bot, task)   ← 与玩家任务**同一条**入口
phase 2  等终态（doneWhen / 超时 / 任务终态）⇒ endStep
最后      verdict()
```

⭐ **两条顺序教训（真机踩出来的，注释逐字留着）**：
1. 「**先开作用域 → 再发料 → 再场景**」—— `provision` 里可能有 `mine_budget` 那种「把**本步作用域**的预算压到 0」的前提；
   作用域没开时它会挂到**孤儿作用域** ⇒ 前提**静默失效**、步骤以超时红。
2. 「**先发料/传送 → 再跑场景**」—— 旧电池是反的 ⇒ 区块冷时 `/fill` 不落地 ⇒ **判据在虚空里假绿**
   （`single:craft_table` 单跑必红就是这个坑）。

## §25 判决：三态 ＋ `SUMMARY` ＋ 一条"账活着"的结构判据

```
PASS ／ DEGRADED（有步被 skip ⇒ **不是绿**）／ FAIL
[Harness] SUMMARY module=<id> steps=<n> failures=<> skipped=<> → <verdict>
```
