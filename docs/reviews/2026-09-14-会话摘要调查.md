# 会话摘要调查：有没有必要"获取会话摘要"（2026-09-14）

> 触发：用户提问"有没有必要获取会话摘要，你可以看看第三方工具和插件"。
> 性质：**只读调查**，不改 Alice 代码、不装插件。所有数字为本机实测（会话日志在持续追加，
> 故数字是某一时刻的快照；文末给出复现命令）。

## 0. 结论（先说答案）

**不需要。** 三条事实合起来把这个问题关掉了：

1. **摘要已经原生存在、且已经自动注入模型上下文** —— 不需要任何插件或自建工具；
2. **摘要是极有损的**（一次压缩把 405,862 tokens 的历史压成 16,738 字符），所以"再要一份摘要"
   不解决任何事实问题：摘要不能当事实来源；
3. **压缩不改存储、只改上下文** —— 三次压缩遮蔽的 1078 个事件**全部仍在磁盘上**（745/745、207/207、126/126），
   可按 `seq` 原样取回。真正的缺口是"默认不可见"，解法是**按需取回原文**，而不是再造一份摘要。

第三方插件的三类卖点（把工作搬到新会话 / 自动压缩+溢出恢复 / 中断续跑）与我们已有的
原生 `/compact` + `docs/HANDOVER.md` + git 提交历史重叠；而本机 profile 已有两个第三方插件
因兼容性被 `disabled: true`（`dsh-ears`、`dsh-dafeiyu`）——第三方维护税在本机是**实测**，不是理论担忧。

## 1. 方法（可复现）

- 版本：`dsh --version` → `0.1.5-rc.1`；装配树：`dsh --profile web --dump-config`（554 行）。
- 会话存储：`~/.dsh/sessions/<escaped-cwd>/<session-id>/session.v3.jsonl.zstd`
  （本次会话文件 ≈3.6 MB）。
- 磁盘格式：**逐事件、带校验的 zstd 帧拼接**（`dsh-session-persistence-jsonl`：*checksummed Zstandard
  frames*）。Node 22.23.2 自带 `zlib.zstdDecompressSync`；本机**无 `zstd` CLI**；
  Node 的**流式**解码器解码完第一帧后报 `Unknown frame descriptor` ⇒ 必须按 zstd 魔数切帧、逐帧解压。
- 实测解码：候选切点 1662 → 解出 1662 帧 → **11.28 MB JSONL / 3053 行 / 0 行不可解析 / 0.17 秒**。
  假魔数（压缩载荷内部偶然出现 `28 B5 2F FD`）靠"能否解压成功"筛除，无需额外启发式。

## 2. 压缩取证（这是本次最有价值的一段）

| compactionId | 触发 | 事件 seq | 遮蔽区间 | 遮蔽事件数 | 遮蔽 token | 摘要字符数 |
|---|---|---|---|---|---|---|
| `03fe4db3` | 自动（turn 62） | 2287 | 8–1969 | 745 | 405,862 | 16,738 |
| `12c6919c` | 自动 | 2769 | 2288–2550 | 207 | 96,474 | 14,020 |
| `b90a110b` | **手动 `/compact`**（`sourceCommandId=cmd-7b8d2e34-1`） | 2913 | 2770–2905 | 126 | 71,088 | 12,526 |

**决定性事实：三行的"遮蔽事件数"与"仍在日志中的数量"完全相等**（745/745、207/207、126/126）。
⇒ 压缩是**上下文层的遮蔽**，不是存储层的删除；`seq` 是稳定寻址键，被遮蔽的原文随时可按序号取回。

`compaction/summary` 事件的载荷字段（实测）：
`compactionId, sourceCommandId, summary, rawOutput, llmStreamCall, shadowedRange, shadowedSeqs,
shadowedTokenCount, provider, model, maxTokens, usage`。
其中 `shadowedSeqs` 直接给出"摘要替代了哪些原文事件"——即**摘要自带一张指向原文的地图**。

压缩比参照：405,862 tokens → 16,738 字符（同量级 1%）。**摘要的用途是省上下文，不是留事实。**

## 3. 原生已经有什么（不装任何东西就有）

从 `dsh --profile web --dump-config` 实测已挂载：

| 能力 | 插件 | 面向谁 | 备注 |
|---|---|---|---|
| **压缩摘要**（自动 + 手动） | `compaction-basic` + `command-compact` | **模型 + 用户** | 摘要事件持久化；模型侧以"checkpoint"块注入（本轮顶部即是） |
| 崩溃持久性检查点 | `session-checkpoint-policy` | 部署 | 保证请求/工具副作用不丢；**与摘要无关**，别混淆 |
| 工具结果修剪 | `compaction-tool-result-pruner` | 模型 | 本次会话 `compaction/prune` 10 次，修剪的是长工具结果 |
| 会话标题 | `session-title` + `session-title-first-prompt-llm` | 用户 | LLM 起的短标题（本会话日志内 `session/title` 2 次） |
| 回合大纲 / 统计 | `session-turn-outline` / `session-stats` | 客户端 UI | 全日志回放定位与计数，非模型上下文 |
| 会话日志导出 | `session-log-export`（`/export` + UI 下载） | 用户 | **打包的仍是同一个 `session.vN.jsonl`（压缩帧）**，不是纯文本 ⇒ 到手仍需解码 |
| 跨会话引用 | `session-reference` | 模型 | `@label` → 有界只读快照，作为**不可信**背景上下文注入 |

要点：**"会话摘要"在原生层已经是默认行为**，本轮回答你的这条消息时上下文里就带着一份。

## 5. 判断

| 说法 | 判定 | 依据 |
|---|---|---|
| "需要插件才能拿到会话摘要" | ❌ 错 | 原生 `compaction-basic` 已产出并持久化摘要（§2、§3） |
| "再多拿一份摘要能补回丢失的细节" | ❌ 错 | 摘要 1% 量级有损；细节在原文里，不在摘要里（§2） |
| "压缩后原文就没了，所以要提前导出" | ❌ 错 | 1078/1078 个被遮蔽事件仍在磁盘（§2） |
| "需要一个工具把压缩后的原文取回来" | ✅ 对，但**按需**即可 | 0.17 秒全量解码，30 行脚本；只在"摘要吞掉了我要的细节"时用 |
| "第三方 handoff 插件值得装" | ⚠ 不建议 | 与 `HANDOVER.md` + git 历史重叠；本机已有 2 个第三方插件因兼容性被禁用 |

风险（必须写明）：日志是**带世代迁移**的格式（本机同时存在 `dsh-session-format-v0-to-v1` /
`v1-to-v2` / `v2-to-v3`）⇒ 自建解码器**有腐化风险**。缓解方式：只读、失败即报错（不可解析行数必须为 0）、
不进生产路径、不进固定动作。

## 6. 建议（含成本与替代）

- **不做**：装第三方摘要/handoff 插件；把摘要当事实来源；把 DSH 私有接口（`/api`、插件 hook）接进工作流。
- **可选 A（推荐，零依赖）**：把本次解码器落成 `tools/dsh-session-log.mjs`（≈40 行、只读、失败即报错），
  用途单一——"压缩吞掉了我要的细节"时按 `seq` 取回原文。成本约 15 分钟；腐化风险见 §5。
- **可选 B（零代码替代）**：UI Session Header → *Download session log*（或 `/export`）取整份日志；
  跨会话需要背景时用原生 `@` 引用。缺口：拿到的是压缩帧，仍需 A 的解码步骤。
- **固定动作（若采纳 A）**：仅在"压缩后需要引用被遮蔽的原文"时使用；**不得**变成每轮例行解码（无收益且放大腐化面）。

## 7. 顺带发现（非本调查主题，见 `HANDOVER.md` 断点）

1. `/alice authz` 在**无作用域**时把破坏/放置预算余量打成 `2147483647`（`Integer.MAX_VALUE`）——
   语义是"无作用域预算限制"，但显示成天文数字易被误读为"预算极大"。
2. 回归电池结束后自动决策选了 240 格外的 `region:saved` 做 `region_lumber`，401 tick 后
   `FAILED code=failed:outside_region`（`chopped=0 patrols=380`）。失败优雅且留痕（这是对的），
   但**菜单项没有可达性信息**，LLM 会据此挑到够不着的活。
3. `~/.dsh/profiles/web/cordis.patch.yml` 引用了不存在的条目 `dsh-voice-assistant-test`
   ⇒ `dsh --profile web --dump-config` 报 `patch: entry "dsh-voice-assistant-test" not found`（无害但每次出现）。

## 附录 A：本次调查所用解码器（只读、约 40 行，未落库）

```js
// usage: node decode-session.mjs ~/.dsh/sessions/<cwd>/<id>/session.v3.jsonl.zstd
import fs from 'node:fs'
import zlib from 'node:zlib'
const file = process.argv[2]
const buf = fs.readFileSync(file)
const MAGIC = Buffer.from([0x28, 0xb5, 0x2f, 0xfd])
const offs = []
for (let i = 0; i + 3 < buf.length; i++) {
  if (buf[i] === 0x28 && buf[i + 1] === 0xb5 && buf[i + 2] === 0x2f && buf[i + 3] === 0xfd) offs.push(i)
}
const parts = []
let idx = 0
while (idx < offs.length) {
  let ok = false
  for (let j = idx + 1; j <= offs.length; j++) {          // 切片从最小候选开始，解不开就延长
    const end = j < offs.length ? offs[j] : buf.length
    try { parts.push(zlib.zstdDecompressSync(buf.subarray(offs[idx], end))); idx = j; ok = true; break } catch {}
  }
  if (!ok) { console.error('STUCK at', offs[idx]); process.exit(1) }   // 失败即报错，不静默丢数据
}
const text = Buffer.concat(parts).toString('utf8')
const lines = text.split('\n').filter(Boolean)
const bad = lines.filter((l) => { try { JSON.parse(l); return false } catch { return true } }).length
console.log('lines:', lines.length, '| unparsable:', bad)
fs.writeFileSync('/tmp/session-full.jsonl', text)   // 之后用 grep 按需取回，勿整份读入上下文
```
