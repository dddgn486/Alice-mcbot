## B. T3 最小设计（可实施粒度）

### B1 `SiteKind` + 宿主类型

- 新增 `enum SiteKind { SINGLE, SHARED, MULTIBLOCK, INTERNAL, UNLOCATED }`；
- `Row` 增 `SiteKind siteKind` 与 `String hostTypeId`（`SHARED` 时指向宿主行）；
- 新增 `siteBlock()`：`SINGLE` → 本行 `blockIds` 的解析结果；`SHARED` → **宿主的** `blockFor`；
- **`noSite` 的 10 行重分类**：**6 → `SHARED`**（`thermal:smelter_catalyst`/`smelter_recycle` →
  `thermal:smelter`；`insolator_catalyst` → `insolator`；`pulverizer_catalyst`/`pulverizer_recycle` →
  `pulverizer`；`tree_extractor_boost` → 对应 device）、**1 → `MULTIBLOCK`**（`mekanism:evaporating`）、
  **3 → `UNLOCATED`**（`mekanism:energy_conversion` / `gas_conversion` / `infusion_conversion`）。

### B2 **不改索引**（推荐）

`BY_BLOCK` 继续 **1 方块 ↔ 1 宿主行**：`blockIds` 只装"本行拥有的方块"，共享用 `hostTypeId` 表达。
理由：`indexByBlock` 的重复方块是**类初始化期抛异常**，还有第二道静态门禁（A2）；改索引的爆炸半径
远大于收益，而 `hostTypeId` 已经足够表达"共享站点"。

### B3 读取器：**先 vanilla 接口兜底，再模组名族**

先试 `Recipe#getIngredients()` / `getResultItem(accessor)`（vanilla 语义），读不出再走现有名族。
**多输入/流体/化学品/每产出概率**：`outputs` 与 `chances` 改成**同一结构的配对**（每个产出自带
`chance`），并对**长度做断言**（现在的两个独立列表 + 空栈过滤 = 结构上无法配对，A5）。

### B4 判据改成**显式能力声明 + 响亮失败**

- 把 `MOD_ADAPTER_PROTOCOL.md:44-51` 的散文判据**要么变成断言、要么删掉**（尺子第 1 问）；
- Tier B 的类型集合：刮 `javap` 后被**形状过滤丢弃的候选必须出声**（现在静默，§0.1）。
