## 1. 施工前实测到的三条**新事实**（侦察文档里没有的）

### 1.1 MiningPlan 的不变量会**直接抛异常**

```
AStarMovementSearch.java:322   new PathPlan(REACHED, startFoot, goal.goalFoot(), …)   ← goalFoot 取 GoalSpec
GoalAdjacent.java:135-137      goalFoot() → return target;                            ← 返回「目标方块」
MiningPlan.java:48-50          if (!path.goalFoot().equals(standingFoot)) throw IAE
```
⇒ `GoalAdjacent` 规划出的路径，`goalFoot()` = 目标方块 ≠ 落点脚位 ⇒ **构造 MiningPlan 必抛 IAE**。
⇒ 解法（单一出处，纯派生、不新增字段）：
`PathPlan.projectedFootPath()` 的最后一项 = **真正落点**
（`AStarMovementSearch.projectedFootPath:310-318` 逐字：`projected.add(startFoot)` + 每条边 `movement.toFoot()`）。
新增 `PathPlan.finalFoot()`（`movements` 为空 ⇒ `null`），`MiningPlan` 不变量改写成**比原来更强**的形态：
`standingFoot` 必须等于**路径实际落点**。

### 1.2 同族静默失效**已经存在于 A 腿**（不是将来时）

```
MiningPlanner:420-425   approach == PLACEMENT_ALLOWED ⇒ PathRequest.withPlacement(…)   ← 规划期
MineBlockRunner:207-212 mode 非 TUNNEL/ENTER_TARGET ⇒ PathRequest.of(…)                ← 执行期
```
⇒ 鱼骨（`A14` 授权"补一块再走"）规划出的 A 腿计划，执行期被**换成纯通行**走一遍
⇒ 正是 `D-443` 裁定 1a 要治的"同一 tick 两个组件给相反答案"，**只治了规划侧、没治执行侧**。
⇒ 新的 `Arrival` 显式字段**顺带修掉它**（同一个 bug 类，隔一个字段）。

### 1.3 带牙的门禁必须同刀改

`tools/kernel-predicates.py:2281 rule_approach_plans_bounded` 钉死
`MAX_APPROACH_PLANS` + `selectBestApproach` 的形状 + `MineMenuCheckTask.runSearchBudgetChecks()` 里的 `issued == 3`。
⇒ 删掉 `selectBestApproach` 后这条规则**必须整体替换**（不是删掉不补 —— 那会丢掉 A2 的牙）。

## 3. `MiningPlan.Arrival` 的形状（②丙 的落地）

```java
public enum Arrival {
    IN_PLACE,                   // 当前站位即可挖（原 Mode.CURRENT）→ PathRequest.of
    DIRECT_PURE_PASSAGE,        // A 腿 · 纯通行（原 Mode.DIRECT + PURE_PASSAGE）→ PathRequest.of
    DIRECT_PLACEMENT_ALLOWED,   // A 腿 · 只放不拆（原 Mode.DIRECT + PLACEMENT_ALLOWED）→ withPlacement
    MINING_APPROACH             // 目标级一次搜索（GoalAdjacent）→ PathRequest.miningApproach
}
```

**为什么合并成一个枚举而不是两个字段**：`CURRENT` 与 `DIRECT` 的差别**只有诊断价值**，
而"授权形状"与"是不是当前站位"在这 4 个取值上是**无损合并**的（`IN_PLACE` 恒纯通行，实测
`planDirect` 的 CURRENT 分支写死 `PathRequest.of`）⇒ 一个字段 = 一处出处，不产生两份可漂移的名单。

**命名刻意避开 `Approach`**：`MiningProfile.Approach` 已存在，而
`tools/check-duplicate-class-names.py` 是**有牙的门禁** ⇒ 不许造同名两物（`GoalSpec` 的教训，`§12.1.2`）。

## 4. 新判据（替代 `rule_approach_plans_bounded`，形态照 `J5-P1` 同族）

三条断言，全部**可红**（每条都能用一次注入变红）：

1. **`Arrival` 每个取值必须有生产点** —— `reach/MiningPlan.java` 里 `Arrival` 的每个枚举常量，
   必须在 `task/mining/MiningPlanner.java` 里作为 `Arrival.<常数>` 出现过
   （证书：**半接线会让某个取值永远不被生产 = 本轮那条静默失效陷阱的形状**）；
2. **执行期分派不许由别的值反推** —— `action/MineBlockRunner.java` 里必须出现按 `plan.arrival()`
   的 `switch`，且 **`MineBlockRunner` 里不许再出现任何 `MiningPlan.Mode`**（旧载体不许回流）；
3. **A2 结构性消失** —— `MiningPlanner` 里不许再出现"对候选集合逐个跑全预算搜索"的形状
   （`selectBestApproach` 不再存在 + 规划调用内 `planPath(` 的调用点数量有界）。
