## §2 差异的**实质**（不是措辞）

`GoalTwoBlocks.isInGoal` 逐字：`x == this.x && (y == this.y || y == this.y - 1) && z == this.z`

- `y == this.y` = **脚在目标格**。目标格若是实心方块，脚进不去 ⇒ **到达**这件事**必然**经过"目标已被破坏"
  ⇒ ⭐ 这正是 `D-500` `IV` 的理由文字：「"破坏"不再是某个请求口径的特权，而是**目标形状的必然结果**」。
- `GoalAdjacent.isInGoal`（实测 `:93-107`）**第①条就是** `if (foot.equals(target)) return false;`（⛔ 不许站进目标格）
  ⇒ 到达**不含**"目标已破坏"这一信息 ⇒ "破坏"回到**单独授权的动作**（`BlockBreakSession`）
  ⇒ ⚠️ `D-500` `IV` 的**理由文字**在 `GoalAdjacent` 下**不成立**。

⚠️ **但 `D-500` 两条裁定的<u>结论</u>都仍成立**（与形状无关）：
`IV` 的结论 = 授权来源（作业级声明）＋ 预算闸门保留 ✅；`V` 的结论 = `exactFoot()==false` 必须登记 ✅
（实测 `GoalAdjacent` **已登记**，`check-far-goal-usage.py:79`）。

⭐ **所以本条不是"红线出了问题"，是"方向与落地不是同一个形状"。**
