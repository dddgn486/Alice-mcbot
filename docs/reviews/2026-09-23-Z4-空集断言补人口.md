## §1 结论（一句话）

`Z1` 让账本**在区外不记账** ⇒ 一族「用账本证明我没写世界 / 没残留」的断言在野外**恒真**（空集）。
本轮给这些站点补上**与区无关**的人口读数（闸门计数的真实写入次数），使"空"不再冒充"干净"；
并顺手补齐 `Z2` **没扫完的义务读数**（`BotManager` 4 处 + `DecisionSnapshot` 仍在用跨 scope 的
owner 口径，其中一处会**拿着区外条目去起恢复任务**）。

## §2 钥匙：一个与区无关的权威读数

```
WriteBudget.writeCount(bot)   → 本作用域闸门计数的真实写入次数（breaks + places + containers）
WriteBudget.population(bot)   → "writes[scope=… breaks=N places=N containers=N refused=a/b]"
```

**为什么它有效**：每一次真实写入都必须过闸门（`consumeBreak`/`consumePlace`/`consumeContainerWrite`），
所以它是**与区无关**的 —— 账本在野外是空集，它不是。因此：
- 「**零写入**」类断言改成判它 ⇒ 比"账本空"**更强**且**有人口**；
- 「**无残留**」类断言补上它 ⇒ 读数带上**覆盖度**（`writes > ledgerEntries` 的差额落在区外，
  本判据覆盖不到 —— 那是 `D-398` R1/R2 的设计，不是缺陷）。

## §4 ⭐ 顺带发现的真缺口：`Z2` 没扫完的**义务读数**

`Z2` 收窄了 6 处闭合点，但**同一族**还有 5 处用**跨 scope 的 owner 口径**（`pendingForOwner`）：

| 站点 | 症状（收窄前） |
|---|---|
| `BotManager.teardownRecoveryDecision` | 「我们欠不欠拆除」的决策会把**区外 / 旧存档遗留**算成欠着 ⇒ 可能去动一片**本来没有义务**的地方（`D-398` R2） |
| `BotManager.tryRecoverUnfinishedTeardown` | ⭐ **拿 `pending.get(0)` 去起 `RestoreScopeTask`** —— 若首条是区外条目，就是"**说去恢复、到了什么都不做**"（`Z2` 判据里点名的那个症状） |
| `BotManager.pendingTemporaryCount` | `/alice region stop` 回执的"未闭合条数"会把区外条目数进来 ⇒ 玩家以为有一堆待收 |
| `BotManager` 取消路径的 `residue` | 进**事件环**给决策层看 ⇒ 口径必须是义务；另补人口 |
| `DecisionSnapshot.worldMod.pendingTemporaryBlocks` | ⭐ **喂给 LLM 的世界事实**：`0` 会被读成"bot 没改过世界"，而它可能在野外刚垫了一摞圆石（只是不入账） |

处置：前四处收成 `pendingTemporaryProtected(...)`；`DecisionSnapshot` 除收窄外**新增**
`writesThisScope` + `writePopulation` + 一句 `note`（明写"区外修改不入账也不恢复 ⇒ 判断写没写看
`writesThisScope`"）。

## §5 门禁与**四条注入臂**（每条实测变红，基线绿）

规则 `rule_vacuous_assertions_carry_population`（标签 `[Z4·空集断言要带人口]`）：
① 4 个"零写入"站点必须含 `writeCount(`；② 6 个"无残留"站点必须含 `population(`；
③ 义务读数（`teardownRecoveryDecision` / `DecisionSnapshot`）必须含 `pendingTemporaryProtected(`，
且 `DecisionSnapshot` 必须**真的发出** `addProperty("writesThisScope"`。

| 臂 | 注入 | 结果 |
|---|---|---|
| ① | `craft_table` 丢掉 `writeCount` | 红（点名"野外是空集、恒真、不报错"） |
| ② | 残留续做决策退回 `pendingForOwner` | 红（点名"会把区外条目算成欠着"） |
| ③ | `DecisionSnapshot` 丢掉 `writesThisScope` | ⚠️ **第一版没红** —— 判据被我自己写的 `note` 文案里那个词满足了（**第 8 次"判据太弱"**）⇒ 改成钉 `addProperty("writesThisScope"` 后红 |
| ④ | `CleanupWrappedTask` 丢掉人口 | 红 |

### §6.2 新读数长什么样

```
[CraftTableCheck] no_world_write=PASS writes=0 ledgerInZone=0 writes[scope=…#2:Regression:craft_table breaks=0 places=0 containers=0]
```
—— 同一步在 `Z2` 那轮是 `temporaryBlocks=0`（空集）。现在这句话是**真的**（该步确实零写入）。

⭐ 更有说服力的一条（`module:craft` 实测）：
```
[ProvisionCheck] no_block_writes=true writes=2 ledgerEntries=0 writes[scope=…#10:Harness:craft:craft_station_provision breaks=0 places=0 containers=2 refused=0/0]
[  CraftStation] no_block_writes=true writes=2 ledgerEntries=0 writes[scope=…#11:Harness:craft:craft_station_craft     breaks=0 places=0 containers=2 refused=0/0]
```
这两步**真的写了 2 次**（`containers=2`：与工作站交互），而账本**一条都没记** ⇒ 改动前那句
`no_block_writes=true` 是**空集真**（它看不见这 2 次）。现在覆盖度就摆在读数里：
`breaks=0 places=0 containers=2` ⇒ 读的人能看出"是容器写入、不是摆方块"，判决仍然正确。

⭐ 第三条（`single:pathing` / CORE 的 `pathing` 步）——**这条把残余也量化了**：
```
[Regression] scene=… cleanup=ledger 回收我方临时方块=0 非我方=0 销账=0 剩余=0｜
             writes[scope=…#2:Regression:pathing breaks=0 places=2 containers=0]
             （`Z4`：区外写入不入账 ⇒ 本清理**覆盖不到**它们）
```
读法：该步在野外**放了 2 格**（PILLAR 垫脚），清理**拆到 0 格**、账本"剩余=0" —— 改动前这一行
会被读成"没留东西"；现在差额（`places=2` vs `回收=0`）**自证**了 `§7` 那条残余。
