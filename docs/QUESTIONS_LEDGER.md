# 开发者问题账（Q-###）

> ⛔ **这不是规则、不是裁定、不是排期。** 它是一本**账**：把**开发者提出过的每一个问题**记下来。
>
> ## ⭐ 为什么有这本账
>
> 开发者逐字：「**实际上这里面最值钱的东西，就是我作为开发者和设计者观察出的向你提出的问题**」。
>
> ⇒ **问题承载着文档与代码里没有的设计意图**。一个问题一旦提出，就是**不可再生的资产**；
> **丢了它 = 丢了意图**，而意图丢了之后，后面所有工作都会朝错误方向"正确地"推进。
> ⇒ 本项目实测过的后果：**AI 自己的理解被当成裁定引用了几轮**（`D-568` §五：「这个理解**完全错误**」）。
>
> ## ⚠️ 用法（三条硬规则）
>
> 1. ⛔ **原话与我的解读必须分栏** —— ⛔ 不许把我的解读写进"原话"栏。
> 2. ⛔ **"我的解读"栏永远不等于你的意思** —— 要升格成规则，必须**你明说**。
> 3. ⭐ 每次大任务的**起点** = 重读本账里 `状态 = 待答 / ⛔ 答不了` 的那些。
>
> ## ⚠️ 本账的完整性声明（⛔ 别把它当全量）
>
> **本轮只补了 2026-10-02 这一场的主体**。更早会话的问题**未回溯**（我的上下文已被压缩过两次）。
> ⇒ ⛔ **这是一份"开始"，不是"全集"**。回溯要另起一刀。

---

## 一、总目

| 类 | 含义 | 出口 |
|---|---|---|
| **意图型** | "我想要 X 变成什么样" | → 设计文档（标 `构想`） |
| **判断型** | "X 该不该 Y" | → 裁定点（⛔ 必须你拍） |
| **边界型** | "X 和 Y 的界线在哪" | → 设计文档 ＋ `GLOSSARY` 词条 |
| **担忧型** | "我怕 X 会出问题" | → ⭐ 风险登记（＝将来要复算的一条判据） |

```
① 每次大任务开工前：读「二、逼出设计体系的问题」+「五、答不了的」

```
