## 二、怎么跑（零参数，不许输坐标）
```
/alice mine here
```
默认参数（写在 `BotCommand` 里，改它就等于改口径）：中心 = **bot 当前位**、半径 24、**配额 64**、`maxTicks` 12000、目标 **`#forge:ores`**（多目标种类 ⇒ 会走成本模型 + 价值表，此时 `valueWeight` 默认 0）。
⚠️ 配额 64 **大于**带内候选（第一轮实测 55）⇒ 正常会看到「先把带内挖光 → 选不出候选 → 扫描继续往下推进 → 又找到矿」这段过程；`maxTicks` 只是上限，跑完即止。
⚠️ **X 光材质包已撤**（`[client]/resourcepacks-disabled/AliceXray`，`options.txt` 已清空）：用户裁定改用**旁观者模式**观察 —— 透明包会把"看不见的部分"也一并透掉，反而看不出"哪些是暴露面"。

### 二b、种类分配（`D-361`，要"一组煤 + 一组铁"就改这里）
`config/alice-mine.json`（客户端同目录；改完**重启**客户端生效，无需重编 mod）：
```json
{
  "valueWeight": 0.0,
  "kindQuotas": {
    "forge:ores/coal": 64,
    "minecraft:iron_ore": 32
  }
}
```
- **键 = 标签或方块 id 都行**（`forge:ores/coal` 是标签、`minecraft:iron_ore` 是 id）；**声明顺序 = 优先级**。
- 非空 ⇒ 总配额 = 各条之和（`64+32=96`），**满足的种类不再选它**（日志 `[Job] KIND …`、`[MineSurvey] 种类分配 …`）；
  空对象 `{}` ⇒ 回到"单一总配额"的老行为。
- 坏条目（漏数量 / 0 / 负数 / 非数字 / 未知键 / 重复键）⇒ 日志 `[MineKind] 种类分配条目无效，已忽略：…`，**不猜**。

## 五、判读口径（先写在前面，免得事后凑结论）
- **向下占比**的分母 = **被选中的目标数**（`attempts`），不是"破坏的方块数"（后者另有 `TaskMetrics`/`WriteAudit` 账）。
  逐字口径见 `MineSurveyStats`：`Δy = 目标 y − 起点 y`（起点 = 起任务时 bot 的脚位）。
- **只看一次样本不足以定论**：本工具是为"真实数据"服务的，但一次运行只是一个样本；要不要形成"偏置结论"，
  要看多次 + 与合成场景（生成器场景）对照 ⇒ 这一层**尚未定论**（`MINE_TASK_DESIGN.md` §3.1 已挂账）。
- ⚠️ **不许**用本工具的单次结果声称"向下偏置已消除/已确认"；它只回答"这一次，任务选了什么、挖到了什么"。
- **失败码的读法**：`world_refused` = 世界侧拒绝（保护层/认领/事件取消，换站位无用）；`tool_missing` = 缺工具；
  `stale_target` = 决策后目标被改动；`write_budget_exhausted` = 写预算耗尽；`search_incomplete` = **没扫完**
  （≠ 没矿）；`partial_quota` = 有产出但不够；`no_reachable_candidate` = 扫完了确实没有。
