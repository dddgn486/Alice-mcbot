## §0 一句话与定位

> **鱼骨挖矿 = 把"我算不出怎么去的深处矿"换成"我脚下/眼前这一格"**：玩家给**起点 + 方向 + 尺寸**，
> bot 按**模板**开主巷与支巷，全程**不需要"搜索如何去某个矿"** ⇒ 深层搜索被**取消**，而不是被优化。

- **定位（`survey/25 §3.4`）**：它是**玩家发布任务的形态**（模板），**不是 bot 的自主能力**；
  与"陪伴性/自主探索"是两条路。⇒ 参数是玩家的输入，bot 不猜策略、不挑目标。
- **区域口径（`survey/25 §0.2`，勘测侧已更正）**：鱼骨在**采集区（保护区外）**
  ⇒ **世界修改账本/格数预算不适用**（`D-372`：区外不记账、不限格数，**只限时间防空转**）。
  ⚠️ 但**保护区/不可破坏/流体三条闸门照旧生效**（`BlockBreakSafety`），鱼骨不绕任何闸门。
- **`D-359` 边界**：鱼骨 **≠ 连锁挖掘**（`oreexcavation` 那种"挖一格连锁 N 格"）。鱼骨挖的是
  **模板几何列出的格**，逐格、可数、可与 `WriteAudit` 对账 ⇒ 不污染 `D-359` 关心的两件事
  （破坏数/配额对账、簇判定不被模组代劳）。

## §2 模板：参数就是唯一真值（bot 不猜）

```java
public record FishboneTemplate(
        BlockPos startFoot,   // 起点（脚位格；玩家给）
        Direction dir,        // 主巷方向（N/S/E/W，四向水平；玩家给）
        int mainLength,       // 主巷长度（格）
        int spurSpacing,      // 支巷间距（每多少格开一条；0 = 不开支巷）
        int spurLength,       // 支巷长度（格）
        SpurSide side,        // LEFT / RIGHT / ALTERNATE / BOTH
        int height,           // 巷道净高（脚位 + 上方的可通行格数；默认 2 —— 2026-09-21 用户裁定）
        int maxGapLength,     // ⭐ 单段连续悬空上限（= 也是"大矿洞"前瞻距离；默认 4 —— §10.3）
        int bridgeBlockBudget,// ⭐ 本次作业累计搭路上限（格；默认 16 —— §10.3）
        int oreQuota,         // ⭐ 目标额度（矿的格数；追簇的上限 —— 2026-09-21 用户裁定，§10.1）
        MineCandidateSource.Target oreTarget)  // ⭐ "是不是矿"的**唯一来源**（默认 = 矿物标签族；§10.1）
```

- **合法域（构造时校验，非法即拒绝而不是夹取）**：`mainLength ≥ 1`；`spurSpacing` ∈ {0} ∪ [2, ∞)
  （< 2 会把相邻支巷塌成大厅）；`spurLength ≥ 1`；`height ∈ {2, 3}`。
- **净高**：默认 **2**（脚位 + 头位 = 玩家能走的通道）；`3` 只在玩家要求"通行更舒服"时用（破坏数 +50%）。
- **模板格序列**（纯几何、**不读世界**、确定性、可复算 —— 判据 C1 的基准）：
  ```
  主巷：  for i in 1..mainLength:  foot_i = startFoot + dir·i        （净高 2 ⇒ 每格 2 个方块）
  支巷：  每 spurSpacing 格（i = spurSpacing, 2·spurSpacing, …）在 foot_i 处向 side 方向开
          for j in 1..spurLength: spur_foot = foot_i + orthogonal(dir, s)·j
  ⇒ 序列 = 主巷按序 + 每条支巷插在对应位置（"开出去 → 挖到端点 → 原路退回主巷"）
  ```

## §3 预期任务逻辑流程（状态机 + 逐格动作）

```
FishboneJob（L3；唯一持有模板；子任务只跑 L2：MineTask / CollectDropsTask）
│
├─ PREPARE ──── ① 起点合法性：`MovementHelper.canStandCentered(level, startFoot)`
│               且 **从 bot 当前位置纯通行可达**（1 次有界规划，`PathRequest.of`）
│               ✗ ⇒ `start_unreachable`（**零世界改动**、如实失败）
│               ② 生成模板格序列（§2；纯几何）
│               ③ 记 origin = startFoot（收集作用域基准）；写前快照（mined / 产物 / 位置）
│
├─ EXCAVATE ─── 取序列里下一个"待挖单元"（一个单元 = 一个脚位格 + 其上 height−1 格）：
│               ├─ 单元内所有格**已是可通行** ⇒ 跳过（计数 `skipped`，不重复挖）
│               ├─ 逐格挖：`MineTask(bot, cell, scope, MiningBudget.forTarget(...), profile, grant)`
│               │    ⚠️ 每次规划距离恒为 **1 格**（站位就在身后/身旁）⇒ 搜索规模 O(1)
│               └─ 挖完该单元后：① `MineBlockRunner.mineInPlace()` 口径做**露头矿顺手挖**检查
│                              （站在这里能看见、够得着、且是矿 ⇒ 进顺手挖队列，不打断推进）
│                              ② 推进 = **下一个单元的规划天然把 bot 带到下一格**（无需单独"走路"段）
│
├─ SPUR ─────── 支巷 = 与主巷正交的 `spurLength` 格，挖法同 EXCAVATE；
│               到端点后沿支巷**原路退回主巷**（纯通行 1 格步进）⇒ 回到主巷继续
│
├─ IN_PLACE ─── 顺手挖队列非空且当前无推进压力 ⇒ 逐个就地开采（`D-365`：站位/视线/破坏）
│
├─ COLLECT ──── 模板挖完 ⇒ `CollectDropsTask(bot, origin, scope, List.of(), true)`
│               ⚠️ **收集半径必须从模板推导**（`D-346` 的教训：追取上限 < 作业直径 ⇒ 判据永不成立）：
│               `radius ≥ mainLength + spurLength + 2`（包围盒对角），**不许沿用默认 32**
│
├─ RETURN ───── 沿主巷**纯通行**返回起点（主巷 = 自己挖出来的返回通道，天然可返回）
│               ✗ ⇒ `return_failed`（如实失败，不静默留在洞里）
│
└─ DONE ─────── 终态理由（§6.2c 同一套词表风格）：
                `template_complete` / `start_unreachable` / `main_blocked`（前方不可破坏：
                基岩/保护区/流体/黑名单；`WRITE-REFUSED` 已在破坏会话归因） /
                `main_floor_missing`（前方脚位下方是空气/水，见 §9 待拍板①） /
                `inventory_full` / `no_progress`（N tick 未推进一格） / `goal_timeout` / `return_failed`
```

**每格动作的精确顺序**（避免"把自己埋了自己"的经典坑）：

1. **先挖前方脚位格**（`MineTask` 的 `DIRECT` 模式：站位 = 身后那格，目标 = 前方脚位格）；
2. **再挖前方头位格**（同上，目标 = 脚位格上方；`height=3` 时再多一格）；
3. **然后规划"走进刚挖出来的那格"**（1 格纯通行）—— 这一步由**下一个单元的 `MineTask`** 承担
   （它的站位候选恰好包含"我现在站的格"⇒ 规划距离 1）；
4. **脚位格下方不动**（不挖地板）⇒ 不会把自己挖穿；若前方脚位**下方本来就是空气/水**
   ⇒ **搭一格地板过去**（2026-09-21 用户裁定：允许用一次性方块补一格地板），并受 §10.3 的三条上限约束。

> ⭐ **三个主要问题（暴露矿的定义/扫描/挖掘时机、液体与不可挖处的处置、大矿洞与悬空搭路上限）
> 的设计见 §10** —— 那是本方案最需要你过目的一段。

## §5 两个实现方案的取舍（**推荐 A**）

| | **A：模板 + 逐格 `MineTask`（推荐）** | B：模板 + 自写确定性推进器 |
|---|---|---|
| 破坏/站位/视线/超时/预算 | 全部走**已验收**的 L2 链路（`MineTask`→`MineBlockRunner`→`BlockBreakSession`） | 自己写逐格 `BlockBreakSession` + 自行处理站位/视线/重试 ⇒ 等于**又造一套执行器**（本项目反复吃过的亏） |
| 规划 | 每格 1 次、**距离恒 1 格**（节点数 O(1)，可测） | 零规划 |
| 风险 | 每格一次小规划的开销（可实测；`D-373` 的病灶是"13 次**全预算**"而不是"多次极廉价"） | 绕开 K-4「可规划即可执行」契约 ⇒ 与全部既有护栏脱钩 |
| 代码量 | 小（模板 + 驱动 + 少量判据） | 大（重复实现动作层） |

**⇒ 选 A**；B 只在"实测每格规划开销不可接受"时再考虑，且那时应先补读数（节点数/毫秒）而不是直接重写。

| # | 判据 | 反例臂（必须能红） |
|---|---|---|

| **C2** | **露头矿进包**：沿模板布 N 个矿石 ⇒ `inventoryDelta ≥ N`（`D-346/347` 产物对账口径） | 禁掉顺手挖 ⇒ 红 |

| **C4** | **可返回**：结束时脚位 == 起点（或 XZ ≤ 1），返回段**零破坏**（纯通行） | 去掉 RETURN 相位 ⇒ 红 |
| **C5** | **不越界/不连锁**：`WriteAudit` 里每次破坏都属于「模板格 ∪ 露头矿格」（白名单）；无第三方连锁模组时**破坏数 == 目标数** | 允许"顺手挖掉非矿的阻挡" ⇒ 红 |
| **C6** | **诚实失败**：前方基岩/保护区 ⇒ `main_blocked` 且**该格零改动**；起点不可达 ⇒ `start_unreachable` 且**零改动** | 把失败改成"绕过去" ⇒ 红 |
| **C7** | **液体/不可挖的归因与分级**（§10.2）：支巷遇 ⇒ `spur_abandoned:<码>` 且**该格零改动**、主巷继续；主巷遇 ⇒ `main_blocked:<码>` + 终态 FAILED + **沿主巷返回起点**；归因码取自 `BlockBreakSafety`（`fluid_block`/`unbreakable_block`/`protected_*`），且**源 vs 流**、**水 vs 岩浆**在日志里必须可分 | 把"放弃子巷"改成"静默跳过继续挖" ⇒ 红；把主巷失败改成继续 ⇒ 红 |
| **C8** | **大矿洞三条上限**（§10.3）：单段悬空 > `maxGapLength`、或累计搭路 > `bridgeBlockBudget`、或前瞻看不到地板 ⇒ **必须** 子巷放弃/主巷失败；搭路消耗的方块数 == 对账数；方块不足 ⇒ `no_throwaway_blocks` | 把上限调成"无限搭" ⇒ 在"大矿洞"场景里立刻红（这条正是用户要求防的） |
| **C10** | **满包处置**（§10.4）：默认全拾取；满包 ⇒ 按 `JunkPolicy`（优先级 + 每类 `minRetain`）丢**超出最低保留量**的最低优先级物品、**整栈丢**；`minRetain` 内与**未登记物品一件不丢**；搭路材料保留 ≥ `bridgeReserveBlocks`；**丢弃物绝不进收集白名单**；无可丢 ⇒ `DONE inventory_full`。**另有一条设计期断言**：任务最高优先级 + 各类 `minRetain` 之和 ≤ 容量（违反 ⇒ `inventory_capacity_insufficient`） | 允许"丢 `minRetain` 内的物品" ⇒ 红；丢弃物被收集器捡回 ⇒ 红；必保集超容量却不报错 ⇒ 红 |
| **C9** | **扫描与追簇的次数/范围对账**（§10.1）：`scannedCells == 单元数`（每单元只扫一次）；追簇格**逐格登记**且 `oresMined ≤ oreQuota`；追簇起点必须**与模板单元相邻**（簇是通道带出来的，不是凭空找的） | 把扫描改成"每 tick 全区域扫" ⇒ 红；把追簇改成"扫全世界找矿" ⇒ 红 |

⚠️ 判据要用**几何复算**（模板格 vs 世界实际空气格）而不是"任务自报完成" —— 这是 `JobKindContract`
（`D-349`）的口径：**成功必须能用世界事实对账**。

## §8 真机取样怎么给你（按你的口径：不建景）

- **入口**：游戏内物品 `alice:fishbone_job`（右键）⇒ 模板 = **bot 自己的脚位 + 你的朝向**（⭐ `D-441`：切片 3 原本是「你当前位置」，真机实测 bot 挤不动你 ⇒ 改掉），
  尺寸在 `config/alice-fishbone.toml`（默认 主巷 20 / 中心距 3 / 支巷 32 / 左右对称 / 净高 2）；发一把镐（照 `MineJobItem`）。
- **日志键**（固定形状，便于你贴片段）：
  ```
  [Fishbone] start template=dir=N main=20 spacing=5 spur=5 side=ALTERNATE height=2 start=…
  [Fishbone] advance=10/20 cell=… mined=… spurs=1 ores=… searchNodes=… products=…
  [Fishbone] SUMMARY dir=… main=20/20 spurs=4/4 mined=… skipped=… ores=… collected=…/…
             searchNodes=… searchLimit=0 return=ok worldChangesInside=… outside=0 → PASS/FAIL
  ```
- **你要看什么**（随机取样即可）：① `main=20/20 spurs=4/4`（模板=事实）；② `outside=0`（没乱挖）；

## §10 三个主要问题：设计（2026-09-21 用户提出）

### 10.1 暴露矿：定义 / 什么时候扫 / 什么时候挖

**定义（三个条件同时成立，缺一不算）：**

| # | 条件 | 判据（**复用生产谓词，不新写**） |
|---|---|---|
| ① | **是矿** | `MineCandidateSource.Target` 匹配（默认 = 矿物标签族）—— **不新增第二份矿物清单**；产物对账另用 `MineProductFilter`（`forge:ores/*` + `raw_materials/*`） |
| ② | **是本次鱼骨挖出来的暴露面** | 该格 6 邻域里至少有**一格属于本次作业挖空的模板单元** ⇒ 范围锁死在"我们自己的作业面"，不会变成"看到矿就去挖" |
| ③ | **顺手**（= 不必移动） | 从 bot **当前站位**：`LineOfSightChecker` 视线通 **且** `BlockInteraction.reachable` 触及 —— **与 `D-365` 就地挖同一对谓词**（`MineBlockRunner.mineInPlace` 的前置就是这两条） |

**什么时候扫（扫描时机）**：
- **只在「每个模板单元挖完的那一 tick」扫该单元自己的 6 邻域**（O(6)/单元）。
- **不全局扫、不周期扫、不重复扫**：已扫过的格进 `scannedCells` ⇒ **扫描次数 == 单元数**，可断言（判据 C9）。
- 理由：① 成本 O(格数)；② 时间点确定（挖穿那一格时带出来的新暴露面才是真的）；③ 不需要 `D-371` 的全覆盖扫描（那是**选目标**用的，鱼骨不选目标）。

**什么时候挖（挖掘时机）**：
- 扫到就进**顺手挖队列**，**在下一个推进动作之前**逐个消费（矿就在身旁，挖掉不打断推进）；
- 每个单元**最多消费 `oreBudgetPerUnit`（默认 8）个**，超出 ⇒ 记 `ore_budget_exhausted` 并停止该处（**不停任务**）；
- 队列里"当前站位够不到"的（站位变了/视线被挡）⇒ 记 `ore_deferred`，**只在下一次单元挖完后重评一次**；**不许"走去挖"**（那是 ①跟随/②探洞 的事，不是鱼骨）；
- ⭐ **追踪整个矿簇，上限 = 目标额度**（**2026-09-21 用户裁定**，推翻本方案 v0.1 的"只挖贴壁那一层"）：
  - 聚合复用 `job/mine/TargetClusters`（既有簇口径），**沿簇逐格挖干净**，直到 **`quota`（目标额度）达成**；
  - 额度是模板字段（默认 = 「主巷+支巷格数 × 0.15」的量级，或玩家显式给；`GoalSpec.mineBlocks` 同口径）；
  - ⚠️ **追簇会偏离模板** ⇒ 判据 C1 从"模板外零改动"改为「**模板外改动 ⊆ 簇游走区域**」（游走格同样逐格登记、可对账）；
  - ⚠️ **游走段按"支巷"级处置**（遇液体/不可挖/大矿洞 ⇒ **放弃这一簇**、原路退回主巷继续），**主巷仍严格**（§10.2/§10.3）；
  - ⚠️ **追簇途中也要周期收集**（掉落物可能落在簇洞里 ⇒ §10.4 的半径规则要覆盖游走范围）；
- ⚠️ **周期性收集**（否则产物会丢）：vanilla 掉落物 **5 分钟消失**，主巷长/支巷多时一次跑完再收集必然丢 ⇒ **每 `collectEveryUnits`（默认 20）个单元 或 产物 ≥ 32 个时，插一次局部 `CollectDropsTask`**（以当前区域为中心，半径按 §3 的模板推导规则缩到"已挖范围"）。

### 10.2 不可挖掘处与液体：**子巷放弃 / 主巷如实失败**（2026-09-21 用户裁定）

**判断口径（不新写一份液体判断）**：直接读生产谓词
`BlockBreakSafety.explicitTargetRefusal(bot, target, reason)` 的返回码 —— 它已经统一给出：

| 返回码 | 含义 | 鱼骨行为 |
|---|---|---|
| `fluid_block` | **任何流体**（水/岩浆、源或流）—— 与 `estimateBreakTicks` 的 `+∞` 同一口径 | 子巷 ⇒ 放弃该子巷；主巷 ⇒ 报告 + 如实失败 |
| `unbreakable_block` | 基岩 / 不可破坏 | 同上（归因码分开，便于真机区分"地形"vs"权限"） |
| `protected_area` / `protected_block` / `protected_tag` | 保护区 / 认领区 / 黑名单 | 同上（**权限问题不是地形问题**，报告里必须分清） |

**补一条"邻接流体"判据**（挖开会**被灌**，与"这一格本身是流体"不同）：
目标格的 6 邻域里有流体 ⇒ 视为**开在流体上**，归因 `fluid_adjacent:<water|lava>:<source|flow>`
（`FluidState.isSource()` ⇒ **源 vs 流必须分开记**：流 = 附近还有活水/洞，风险更高，真机归因要用）。

**行为（逐字落地用户裁定）**：
- **支巷**遇不可挖/液体 ⇒ **放弃这条子巷**（`spur_abandoned reason=<码>`），**沿支巷原路退回主巷继续**；
- **主巷**遇不可挖/液体 ⇒ **报告 + 如实失败**（终态 `FAILED`，`terminalReason=main_blocked:<码>`），
  ⚠️ 且**优先沿已挖通的主巷返回起点**（`D-327` 安全返回的思想：先回家再失败，不许把 bot 留在洞里）；
- **不做绕过**：不拐弯、不搭桥越水越岩浆、不填回；
- **岩浆 vs 水**：行为**同一档**（放弃/失败），但**归因与日志分级**（岩浆是硬危险，`SurvivalSystem` 可能同时接管）；
- **水下鱼骨**（玩家想让 bot 在水下挖）⇒ **明确不做**，登记为后续（需要单独授权面 + `D-385` 成本已就位）；
- ⚠️ 报告通道**复用既有失败可见性链路**（`Job` 终态 + 决策层提示 + `mine_failure_visible` 那套），**不新造报告通道**。

### 10.3 大矿洞与悬空搭路：三条上限（2026-09-21 用户建议"设格数限制"）

**允许搭路**（用户裁定），但**三条上限**同时生效 —— 任一触发 ⇒ **子巷放弃 / 主巷 `main_cave` 失败**：

| # | 上限 | 默认 | 为什么 |
|---|---|---|---|
| 1 | **单段连续悬空长度** `maxGapLength` | **4 格** | 4 格是"能看见对岸、搭得过去"的量级；再长就不该靠搭 |
| 2 | **本次作业累计搭路** `bridgeBlockBudget` | **16 格** | 防"很多个 3~4 格小洞累积成大工程"（单段不超、总量失控） |
| 3 | **前瞻判据**（复用同一个 `maxGapLength` 作视距） | —— | 搭路前先看**前方 `maxGapLength` 格内有没有可站地板**；**看不到 ⇒ 直接判大矿洞**，不逐格试（省时间、省方块、避免"搭到一半没方块"） |

- **方块来源**：玩家提供的**一次性方块**（`D-099` 标签，如圆石）；**不够 ⇒ 如实失败 `no_throwaway_blocks`**
  （照 `BlockInteraction.findPlaceableSlot` 的既有口径）。⚠️ **诚实边界**：「必然成功」的**前提是玩家带了方块**。
- **阈值可调**：`maxGapLength` / `bridgeBlockBudget` 是模板字段（玩家表单里可改），默认值如上。
- **大矿洞里的其它危险**：岩浆湖/水 ⇒ 走 §10.2；**怪物 ⇒ 切片 1/2 不做战斗**（如实记录，交给维生/风险系统）。

### 10.4 产物与背包：**默认全拾取**，满包按**丢弃优先级**管理（2026-09-21 用户要求）

> **用户原话**：「矿道挖掘本身会掉很多石头，**默认挖掘的方块都会拾取**，按之前的**背包丢弃优先级**管理」。

**⚠️ 先说实话（可核）**：我**没有在仓库里找到**"丢弃优先级"这条实现或口径 ——
全仓**没有** `player.drop(...)` 调用；现有的满包口径是 **`DONE inventory_full`（诚实收工、未动世界）**
（`job/lumber/LumberJob.java:314`、`job/mine/MineJob.java:290`、`D-1xx` 的 `inventory_full` 场景）；
唯一的"值不值钱"出处是 `MineValueTable`（`tier1/2/3`，**未登记 = 0**）。
⇒ **结论（2026-09-21 已澄清）**：口径由用户在**本轮对话**给出（下面那段原话），仓库里**没有**旧实现
⇒ `JunkPolicy` 由本方案**新建一份**（唯一来源），并把这条口径写进 `D-38x` 决策与门禁。

**默认全拾取**（不改现有归属判定）：鱼骨挖出的**全部方块掉落**都走 `CollectDropsTask`
（归属 `OURS_DIRECT` ✓，`D-138`/`DropPolicy` 口径），**矿物与石头/泥土一样都捡**
—— 额外好处：**石头掉的就是圆石 = 搭路材料**（§10.3），捡了就地可用。

**满包处置（`JunkPolicy`，新类，**唯一来源**；口径 = 用户 2026-09-21 原话）**：

> 「按物品**保留优先级**，优先丢弃优先级低的，但**每一种或者每一个类可以设定最低保留量**，
> **最低保留量内的相当于最高优先级**，任务安排的**最高优先级物品理论不可超过最大容量**。」

⇒ 数据模型（表放**标签/配置**，与 `MineValueTable` 的"表放标签、权重放配置"同一口径 ⇒ 整合包可加）：

```java
record Retention(String id, int priority, int minRetain)   // priority 越小越先被丢；minRetain = 至少留几个
```

| 规则 | 落法 |
|---|---|
| **最低保留量内 = 最高优先级** | 只要 `count ≤ minRetain` ⇒ **永不可丢**（与 priority 无关） |
| **超出部分按优先级丢** | 只有"`count > minRetain`"的物品才进候选；候选里挑 **priority 最小**的，丢掉 `count − minRetain` 个（**整栈丢，否则不腾格子**） |
| **同类内**（同 priority） | 先丢**数量最多**的（腾格子最快） |
| **未登记物品** | **默认不丢**（= 最高保留优先级）并在日志报 `unknown_kept` —— 与"未知模组能力默认只读、不猜、不动"同一底线（**丢玩家的未知模组物品是不可逆事故**） |
| **默认表来源** | 矿物优先级**引用 `MineValueTable.tier`**（tier3 必保 / tier1–2 高保留 / tier0 低）⇒ **不新建第二份矿物清单**；再叠加「任务必保」+「搭路材料 `alice:throwaway` 最低保留量 ≥ `bridgeReserveBlocks`(64)」 |
| ⭐ **容量不变式（任务设计期断言）** | 「任务最高优先级物品 + 各类 `minRetain` 之和」**必须 ≤ 容量**（36 格）；**运行期一旦违反 ⇒ 如实失败 `inventory_capacity_insufficient`，绝不丢必保物**（用户原话"理论不可超过最大容量"= 这是**设计期**约束，不是运行期兜底） |

**流程**：满包 ⇒ ① 按上表丢（腾出格子）继续作业；② **没有可丢的**（所有物品都在最低保留量内）⇒ **诚实收工**（保留既有口径 `DONE inventory_full`）。

**三条硬纪律**（否则会出真事故）：
1. **丢-捡死循环防护**：丢出去的物品必须登记为**故意丢弃**（`ScopeBuffer` 里标 `dropped_by_us`）
   并**排除出收集白名单**；否则 `CollectDropsTask` 会把它捡回来 ⇒ **丢-捡无限循环**（判据 C10）。
2. **丢失位置**：丢在**作业通道内最近的已挖空格**（不许丢进保护区/玩家脚下/液体里）；
   丢弃是**写世界动作** ⇒ 需要 `WriteReason`（建议新增 `DISCARD_ITEM`，登记进
   `check-policy-matrix`/`check-authz-registry`）+ `WriteAudit` 留痕。
3. **没有可丢的**（满包全是必保物）⇒ **保留既有口径**：诚实收工 `DONE inventory_full`，
   **不许**丢矿物/工具去硬撑。
