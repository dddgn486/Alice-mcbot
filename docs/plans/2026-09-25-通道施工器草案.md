## §3 抽象边界（三层，`MineTask` 一行不改）

| 层 | 是什么 | 拥有什么 | 现状 |
|---|---|---|---|
| **L1 `MineTask`**（`task/MineTask.java:38`） | **单格挖掘原语**：目标一格 + 消费者给的 `MiningProfile`/`MiningBudget`/`WriteGrant` | 破坏那一格、收集它的掉落物、如实报失败理由 | **保持不动**；找矿/矿簇继续用它（散矿用模式 A 本来就对） |
| **L2 `PassageShape`**（新，纯数据） | **形状 + 不变式**：有序单元（脚位/头位格）、行走层 Y、**必须存在的支撑格**、**受保护格集合** | 只描述"要变成什么" | 鱼骨模板是第一个实现；将来的探洞/主巷/房间是同一接口的新数据 |
| **L3 `PassageExecutor`**（新，施工） | **施工顺序 + 站位策略 + 地板维护 + 失败升档** | "挖哪一格、按什么顺序、站在哪、缺什么补什么、失败怎么退" | 鱼骨今天把这些散在 `FishboneJob` 里（`excavate`/`finishUnit`/`abandonSpur`） |

**数据流**：`PassageShape` →（L3 逐单元）→ 跳过判据 → **走到能挖它的地方**（内核走位，`withPlacement`）
→ 调 L1 挖那一格 → 地板缺了就补 → 单元完成记账 → 下一个单元。

⚠️ **红线（防"第二内核"，`D-036`）**：L3 **只做顺序/跳过/维护/升档**；
**不做搜索、不做移动、不做成本、不做完成判定** —— 那四件事一律调内核现成实现。

⚠️ **已知未决（要勘测侧评，见 §9.4）**：Alice 没有 Baritone 那种 `GoalAdjacent` 目标类型，
所以"走到能挖它的地方"今天仍要枚举候选格（`StandingPointSelector`）。
**最小做法**（我推荐，也是 S1）：**保留**这套候选枚举（它是"几何"），只把**请求集**换成满权限；
**不新造目标类型**（那才是内核改动，需要单独一片 + 单独裁定）。

## §4 不变式：「路」的定义（施工层的责任，与 Movement 无关）

| # | 不变式 | 为什么 |
|---|---|---|
| **I1** | 每个单元的**行走层格 + 净空格**在终态可通行 | 这是"通道"的语义本体 |
| **I2** | 行走层的**支撑格（地板）存在**（缺了必须补） | 没有地板 ⇒ 不是路，是洞（本轮 A1 的直接教训） |
| **I3** | **不留半成品格**（如"空气 + 头位实心"）—— 要么合格、要么如实记为未完成 | A1 的教训：半成品格会以"还要挖"的身份毒死整个单元 |
| **I4** | 与入口/既有通道**连通**，且 ⭐ **纯通行可从起点走到最远端** | 把"能不能反复通行"变成**判据**，而不是靠人眼看（见 §5） |
| **I5** | 施工期间**别的写入者不许破坏 I1/I2 的格** | A1 的元凶就是 `fishbone` 自己的追簇 + `collect-drops` 的 `PATH_ACCESS` |
| **I6** | 每格世界改动**进 `WriteAudit` 且与形状对账**（采集区不记账的既有口径照旧） | 可计数、可复核；`D-372` 的边界不变 |
