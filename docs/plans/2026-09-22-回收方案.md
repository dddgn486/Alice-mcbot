- 日期：2026-09-22 · 触发：用户 2026-09-22「我需要一套**完整的回收方案**，应对各种回收状况，
  指清楚**现在能怎么回收**，要设计**以后怎么回收**，有没有**冗余设计**」
- 口径基线：`D-398`（责任边界，决定性断言）+ `D-397`（三件套作用域不一致）+ `D-399`/`D-400`（守卫与判据）

## §0 一页结论

1. **今天能回收的只有一种东西**：**我方放置的、被判为 `TEMP` 的方块**（脚手架/垫脚/支撑/工作站），
   且必须满足"作用域还没关、区块加载着、bot 到得了、现场还是我方那块、拆了不会把 bot 摔下去"。
2. **今天根本不做、也不该做的**：我方**挖掉的地形**（账本**只记放置**，破坏**不进账本** ⇒ 无 `previous` 可还原）、
   容器里拿走的物品、流体/光照等副作用。
3. **最大的结构缺口**：回收义务**没有唯一真相** —— 义务由 `WritePolicyMatrix` 的行决定、
   记录在 `WorldModLedger`、额度记在 `WriteBudget`、触发散在 5 处（任务/作业/夹具包装/电池/启动读），
   而**"作用域关闭"这件事本身不强制回收**（电池 `endStep` 只关账、只 warn）。
4. **冗余确实存在 6 处**（§3），其中 3 处应当合并或降级为遥测。
5. **以后怎么回收**（§4）：把"义务"收敛到**一个模型**（三分类 × 五个触发器 × 四条不变量），
   并把 `D-398` 的保护区区外无义务作为**第一刀**（= 队列 `Z1/Z2/Z3`）。

## §1 今天的回收能力（实测清单）

### 1.1 义务从哪来 —— **集中策略表**（不在各处 `if` 里）

| 事实 | 出处 |

| 退休（销账）三条路 | `dropStale(level)`（现场已不是我方 ⇒ 批量销、**带日志**）、`forget(level,pos)`（单条销）、`RestoreScopeTask` 内的 `not_ours` 判定（**绝不拆不是自己放的**） |

### 1.3 谁来执行 —— `task/RestoreScopeTask`

流程（已实测）：`dropStale` → 逐条 `at(pos)` → **复检 `nowId.equals(entry.placed())`**（不符 ⇒ `forget`+`skipped`+`not_ours` 归因）

→ 收尾收集掉落物 + 终态 `restore_done`/`restore_partial`。

### 1.5 今天**做不到**的（≠ 缺陷，多数是设计边界）

1. **挖掉的地形**：账本无 `previous` ⇒ 不可还原（且按 `D-398` 区外本来也无义务）；
2. **容器物品**：`WriteBudget` 有 `containerWrites` **计数**，但**没有逐 item 账** ⇒ 还不了原；
3. **流体 / 光照 / 方块实体副作用**：完全未记录；
4. **未加载区块**：`pendingTemporary` 里若有，回收走到那格时无法读世界 ⇒ 只能跳过/延后（今天**没有**延后机制）；
5. **重启后**：条目在存档里活着，但**没有"启动补收"**（只有 `BotManager` 读一眼）；
6. **死亡后**：义务是否随 `death_persistence`（`D-276`）延续 —— **未核实**（§6）。

## §3 冗余设计盘点（6 处，逐条给处置建议）

| # | 冗余 | 现状 | 建议 |
|---|---|---|---|
| 1 | **`WriteBudget`（计数） vs `WorldModLedger`（逐块）** | 同一件事（"我方改了多少世界"）两份账 | **账本为主真相**；`WriteBudget` **降级为遥测/闸门**（只做"要不要拦"，不再做"改了多少"）—— 呼应 `D-387 P1-a`（两份不同源曾静默失效） |
| 2 | **`countThrowaway()`（背包里的一次性方块数） vs 账本位置** | 两种"知道该收什么"的方式 | 保留背包计数**仅用于收集阶段**（掉落物/材料）；**回收义务只认账本位置** |
| 3 | **销账三条路**（`dropStale` / `forget` / `not_ours`） | 三种语义相近的退休 | **合并到一处函数**（`retire(reason)`），保证都带日志与归因码 |
| 4 | **触发者五处**（MineTask / LumberJob / CleanupWrappedTask / 电池 / BotManager 读） | 每个新任务都要记得接 | **收敛为两条**：① 任务/作业收尾（统一在作业层）② **作用域关闭钩子**（关账即登记"待收"）；夹具包装器降为"兜底" |
| 5 | **`implicit` 桶** | 无任务时的兜底 scope | `D-398` 之后：**区外不再需要它**；保护区内**不该**出现 implicit（出现即 bug，应可断言） |
| 6 | **"建拆同权"（`D-081`）在电池里只是 warn** | 不变量靠人记得 | 做成**门禁**（关账时该 scope 的 `TEMP` 条目必须为空，否则红） = 队列 `Z2` |

## §4 以后的回收方案（目标模型）

### 4.1 义务三分类（**禁止**与**必须**同等重要）

| 类 | 内容 | 必须 / 禁止 | 判据 |
|---|---|---|---|
| **A. MUST_RECLAIM** | 我方放置且 `TEMP`（脚手架/垫脚/支撑/工作站） | **必须**回收；失败必须**带理由** | 账本 `pendingTemporary` 回 0 或每条都有归因码 |
| **B. NEVER_RECLAIM** | `KEEP`（道路/补种）、**我方挖掉的地形**、区外（`D-398`）的一切 | **禁止**回收（"恢复无主区域没有意义"） | 区外 `pending` 不进账本；KEEP 条目不出现在待收队列 |
| **C. CANNOT_RECLAIM** | 容器物品、流体/光照/方块实体副作用 | **明确不做**，但必须**如实记账**（可查，不许假装可逆） | 有计数/日志；文档与 UI 不承诺"可逆" |

### 4.2 触发器集（5 → 2 条主路 + 2 条补收）

| 触发器 | 说明 |
|---|---|
| **T1 任务/作业收尾** | 统一在作业层：成功、失败、超时、取消**四条路径都要走**（今天只有部分） |
| **T2 作用域关闭钩子** | `closeScope` 时把该 scope 的 `TEMP` 条目登记为"待收"（**关账 ≠ 已收**，但**不许静默**） |
| **T3 启动补收** | ⛔ **用户 2026-09-22 否决**：不做启动补收（"不自动发起回收重试"） |
| **T4 未加载区块的处理** | ✅ **用户 2026-09-22 同意**：**不许为回收强制加载区块**。⚠️ 我的理解（请纠正）：T4 是**显式发起的回收任务内部**对"区块没加载"的处理准则（如实报告/留待下次），**不是**自动触发器 —— 与"不自动发起回收重试"一致 |
| **T5 显式入口** | ⭐ **回收的唯一发起方式**（用户 2026-09-22 裁定）：**玩家显式授权**，或**显式发布回收任务**（命令/物品） |

**幂等 + 断点续做**：条目在存档里 ⇒ 每次只处理"还没到位"的；`dropStale`/`not_ours` 保证重复执行安全。

⭐ **回收的发起边界（用户 2026-09-22 裁定，必须逐字遵守）**：
1. **只有两种显式入口**：① 玩家**显式授权** ② **显式发布回收任务**；
2. **失败保留账本**：回收没做完的条目**留在账本里**（账本是**持久待办**），只能被"显式动作"关闭；
3. **不自动发起回收重试**（含启动补收 T3 已否决）；
4. ⚠️ **边界说明（待用户确认）**：任务**内建**的"用完即拆"（`MineTask`/`LumberJob` 收尾拆自己的脚手架）
   属于**任务本身的一部分**，不是"自动重试"；`T2 作用域关闭登记待收` 只是**登记**、不执行 ⇒ 二者与本裁定不冲突。
5. `dropStale` 的语义**收窄**：它只销"现场已不是我方方块"的**空义务**条目（带日志），
   **不许**用来清掉"没做完"的义务 —— 后者必须留在账本里等显式动作。

### 4.2b ⭐ **自动回收的条件门**（用户 2026-09-22：「需要给自动回收设定条件，不是无脑自动或者全部手动」）

**判定顺序（逐个条件走，任何一条不满足 ⇒ "本轮不自动"，而**不是**"失败"、更**不是**"丢弃"）**：

| 组 | 条件 | 不满足时 |
|---|---|---|
| **必要条件 N** | **N1 作用域仍在飞行**（有活跃 task/scope） | ⇒ 进**账本待办**（等显式入口） |
| | **N2 区块已加载**（不强制加载，T4） | ⇒ 留待办（**绝不**为回收加载区块） |
| | **N3 安全性**：拆完 bot 有落脚面（`I-1`/`D-399`） | ⇒ 延后/留待办 + `underfoot_unsafe` 归因 |
| | **N4 归属确定**：现场仍 = 账本记录（`not_ours` 反例） | ⇒ **销空义务**（带日志，不算回收） |
| **有界条件 B** | **B1 不越界绕路**：待收方块须落在**本任务自身路径/声明半径**内 | ⇒ 留待办 |
| | **B2 有界**：单次收尾的块数 ≤ `X`、且不破 tick 预算（挂 `P4` 尺子） | ⇒ 分批，余量留待办 |
| | ⭐ **B3 回收不许产生新债**：回收动作本身**不许**再放临时方块（搭桥/垫脚） | ⇒ 留待办（否则"回收产生新回收"会套娃） |
| **触发点（自动的三个）** | **A1 任务内原位**（顺手拆）· **A2 任务收尾**（同 scope 一次清） | 二者都要过 N1–N4 + B1–B3 |
| | **A3 任务外的保护区内待办** | ⛔ **不自动**（`D-398` R3：一定记账，**不要求立即恢复**）⇒ 账本 + 显式入口 |

**明确"永不自动"的清单**：`KEEP`（道路/补种）· 我方挖掉的地形（无 `previous`）· 容器物品 · 流体/光照/方块实体副作用 ·
**保护区外一切**（`D-398`）· 未加载区块（T4）· 会摔 bot 的（N3）· 越界绕远的（B1）· 会产生新债的（B3）。

**待用户定的三个阈值/口径**：
1. **B1 的半径**：默认「不超出任务声明半径 + 8 格」？
2. **B2 的块数 `X`**：默认 32？（与旧 `DEFAULT_MAX_PLACES=32` 同量级，但只作"分批"不作用"拒绝"）
3. **A3**：确认"保护区内、任务外的待办**一律不自动**"（我按 `D-398` R3 这样记）。

### 4.3 四条不变量（全部要能"注入即变红"）

- **I-1 安全**：任何移除前，移除后 bot 必须有落脚面（`canWalkOn`）——`D-399` 已落地（判据为其弱形态 + 台账，`D-400`）。
- **I-2 归因不静默**：没拆成的每一条都必须带码（`not_ours` / `underfoot_unsafe` / `side_break_failed` / `chunk_unloaded`…）——`C2` 夹具已在钉。
- **I-3 只拆自己的**：现场 ≠ 账本 ⇒ `forget` + `not_ours`（已有 ✓，保留）。
- **I-4 区外无义务**（`D-398`）：区外不记账、不回收、无限修改；**保护区内一定记账**。

### 4.4 ✅ 已裁定（用户 2026-09-22）

1. **T3 启动补收**：⛔ **否决**（不自动发起回收重试）。
2. **T4**：✅ **同意** —— 不许为回收强制加载区块。
3. **失败保留账本**；**回收需玩家显式授权或显式发布回收任务**；**不自动重试**。
