# 决策层最终形态：**任务队列 + 持久终态 + 历史落盘**

> **状态**：**设计定稿 · 未实现 · 未验收**（2026-09-19 记录）
> **来源**：用户 2026-09-19 提案（口述完整流程）+ 采纳的 AI 建议（三条）
> **摘要版**：`docs/DECISION_LAYER_DESIGN.md` §7；**本文是完整形态**，可独立阅读
> **与主线关系**：**弱耦合、不阻塞任何当前主线**；但它是 `AI_PROJECT_STATE.md`
> 「当前目标」里**差异②「多层任务失败向上传递（任务层 → LLM 决策层处理接口）」的成熟形态**，
> 也是**模组机器线**未来做「bot 自己维持某台机器持续生产」的落点 ⇒ **是目的地，不是当前路径**。

---

## §1 问题面（为什么需要它）

今天这套决策—执行框架的**接缝**都在"任务之间"，而不是任务之内：

| # | 现状事实（代码级） | 后果 |
|---|---|---|
| 1 | `BotSession` 只有**一个 `Task task;` 槽位**，**没有队列**；新任务 = `replaceTaskIfRunning`（旧的标 `CANCELLED_REPLACED`） | 目标一旦比"一条任务"大，就没人接续 |
| 2 | 跨任务边界的自动接续**只有 LLM**（终态触发）+ 玩家 + 只管安全的返程兜底 | 长线目标的连续性**依赖 LLM 可用性**；被节流/在飞时触发**被丢弃且不排队** |
| 3 | 触发时机**隐含**在"终态事件"里 | 无法回答"它到底什么时候该被叫"；也不能规划"什么时候不该叫" |
| 4 | LLM 的"记忆"= 事件环 + `lastTerminal` + trace 文件 | 它能看见事实，但**看不见"我原本打算做什么"** ⇒ 计划无从延续 |
| 5 | 没有"同一目标失败 N 次就升级"的规则 | 出现**跨任务换路重试循环**（实测两轮：`lumber` 被拒 → 4 秒后自起 `region_lumber` 接着干） |

---

## §2 目标 / 非目标

**目标**：让 bot 有**持久的最终状态**与**可续的任务队列**，使长线目标在**不依赖 LLM 常驻可用**的前提下推进；
让 LLM 只在"需要队列变更"时被叫；让它**不遗忘**做过什么。

**非目标（沿用 `DECISION_LAYER_DESIGN.md` §1，不得越界）**：每 tick 的移动/挖掘决策、预算与授权裁定、
安全边界、当"真相来源"、把 LLM 当唯一安全网。**队列不改变这些边界**。

## §3 数据模型（契约）

### 3.1 `GoalRecord`（每只 bot 一份，持久化）

```
GoalRecord {
  botId, createdAt, updatedAt,
  finalState: FinalState,          // 见 §3.3：REACH_STATE | MAINTAIN
  current:   TaskSpec | null,      // 正在跑的那一条
  queue:     [TaskSpec],           // 后续任务列（有序；可为空）
  history:   [HistoryEntry],       // 实际做过什么、什么顺序、结果码
  budget:    { totalTicks, totalCalls, spentTicks, spentCalls },
  escalation:{ count, lastReason, lastTick },
  state:     QueueState            // 见 §4
}
```

### 3.2 `TaskSpec`（**类型化，不接受自由文本**）

```
TaskSpec {
  kind,                  // 必须是确定性枚举（今天的 JobRequest kind 表）
  params,                // 只能取自菜单/世界事实（复用 CandidateMenu + JobLauncher 校验器）
  precondition,          // **可判定**（容器已注册？材料在？工具在？区域在？区块已加载？）
  successCriterion,      // **可判定**（砍够 N 棵 / 拿到工具 / 背包里有 X）
  limit: { maxTicks, maxAttempts },
  onFail: SKIP | ESCALATE | END_QUEUE,
  note                   // 人话说明，供计划卡显示（不参与判定）
}
```

**硬规则**：`precondition` 或 `successCriterion` 不可判定的条目 **不许入队**（否则队列就是给循环发牌照）。

### 3.3 `FinalState`（**两型必须分开**）

| 型 | 语义 | 判定 | 例子 |
|---|---|---|---|
| `REACH_STATE(predicate)` | **一次性**：达到即待机 | `predicate` 可判定 | "把这棵树砍完并补种" / "把 64 个铁锭放进容器" |
| `MAINTAIN(invariant, remediation[])` | **维持态**：稳态不变量 + 补救规则；**队列可为空且不触发 LLM** | `invariant` 可判定；破裂时才走 `remediation` | "区域伐木持续进行" / "这台机器一直有料" |

### 3.4 `HistoryEntry`

```
HistoryEntry { tick, kind, paramsDigest, resultCode, outcome, durationTicks, by(trigger) }
```
落盘：**JSONL 追加**（与 `DecisionTrace` 同一套路，`<config>/alice-decisions.jsonl` 家族）+
`GoalRecord.history` 保留最近 N 条（有界）。**这是"LLM 不遗忘"的载体。**

## §4 状态机与生命周期

```
        ┌──────────────┐  队列非空/不变量正常 ⇒ 正常推进（**零 LLM 调用**）
        │   RUNNING    │──────────────────────────────────────────────┐
        └──────┬───────┘                                              │
               │ 条目终态 / 不变量破裂 / 升级条件                      │
               ▼                                                      │
        ┌──────────────┐  需要新条目 ⇒ **触发一次 LLM**（§5）          │
        │ NEED_DECISION│──────────────────────────────────────────────┘
        └──────┬───────┘
               ├─ 队列有下一步 ⇒ 回到 RUNNING
               ├─ REACH_STATE 达成 ⇒ IDLE_AT_HOME
               └─ 不可达 / 请示被拒 / 超预算 ⇒ 收尾（可配置：卸货 / 未完成收尾）⇒ IDLE_AT_HOME
                                                            ⇒ **此后不再触发 LLM**（除非 §5 四条之一）
```

`QueueState ∈ {RUNNING, NEED_DECISION, STEADY(MAINTAIN 正常), ESCALATED, IDLE_AT_HOME, UNREACHABLE}`

## §5 触发点（回答用户的关键问题）—— **只在需要"队列变更"时叫 LLM**

| # | 触发 | 说明 | 冷却 |
|---|---|---|---|
| 1 | **队列空且终态未达成** | 当前条目结束/失败且无下一步 | 无（即时） |
| 2 | **不变量破裂** | 复用 `EventThresholds`：`TOOL_LOW` / `NO_PROGRESS` / `STUCK` / `DANGER`；新增：背包满 / 容器未注册 / 区域条件不满足 | **每类一条冷却**（不刷屏） |
| 3 | **升级** | 同一条目失败 ≥N / 超预算 / 请示超时 | 指数退避 |
| 4 | **玩家指令** | 自然语言目标 / 手动触发 / `instruct` | 无 |

⭐ **推论**：任务正常推进 ⇒ **零调用**；`MAINTAIN` 稳态一切正常 ⇒ **可以几小时不叫它**（用户要的正是这个）。
与今天的差别：今天只有触发 1（终态）与部分 2，且**没有队列** ⇒ 触发后只能"起一个任务"。

## §6 用户场景逐帧走查（砍树 / 用户原例）

1. **初始**：`finalState = MAINTAIN(区域 x17..37 z203..231 持续伐木)`，`queue = []`，`current = RegionLumberJob`。
2. 正常砍 → **零 LLM 调用**（今天的 `event:PROGRESS` 那条低频事件仍可保留，但**不是决策**）。
3. `TOOL_LOW`（斧耐久见底）⇒ **触发 LLM 一次**，它依手册/提示词/知识库**插入 `GET_TOOL`**，
   同时**发起请示**：「是否允许去指定的 bot 任务资源容器取斧？」
4. **玩家拒绝** ⇒ `MAINTAIN` 不变量无法维持 ⇒ **结束队列**；若没有其它默认终态任务 ⇒
   **收尾**（可配置：卸货 / 未完成任务收尾）⇒ **回归位点待机** ⇒ 不再触发。
5. **玩家允许** ⇒ `GET_TOOL` 执行：走到容器 → 取斧。
   - **取到** ⇒ 回队列继续 `MAINTAIN`（零 LLM 调用）；
   - **取不到**（容器没有/路不通）⇒ 再请示：「是否允许搜索材料自制？」**允许** ⇒ 插入
     `GATHER_MATERIALS` + `CRAFT_TOOL`（**由 LLM 依认知编排**）；**不允许** ⇒ 同 §6.4。
6. **终态达成** ⇒ 待机；**终态不可达** ⇒ 按 §6.4 收尾并待机。

## §7 三条防乱派/防空转的机制（**这是"能保证"的全部来源**）

| 机制 | 规则 | 防的是 |
|---|---|---|
| **准入校验** | 条目必须类型化 + `precondition` 可判定；**不满足就地拒绝并回读原因**（复用 `JobLauncher.refusalReason`） | "先干了再说"、参数不存在 |
| **进展契约** | 每条目必须有 `successCriterion` + `limit`；超限 ⇒ 按 `onFail`（不许无限重试） | 空转、静默挂死 |
| **循环检测 + 升级** | 同一 `(kind, 参数摘要)` 在窗口内失败 ≥N ⇒ **禁止再入队** + 升级请示 | **跨任务换路重试**（实测两次） |
| **陈旧队列复验** | 条目执行前**重验 `precondition`**（世界变了 ⇒ 作废/重规划，不硬跑） | 队列与世界脱节（同 `CapabilityGate` 的执行期复验哲学） |

## §8 玩家交互（不是"任务表单"）

1. **计划卡**：聊天一行 `[alice] 队列：… → 终态：… ｜ 下一步：… （因为…）`；`/alice goals` 查全文。
2. **请示**：复用 `PermissionGate`（`options[] + deadline + default`，**超时=拒绝**，LLM **只能请求不能批准**）；
   选项由**确定性层**生成 ⇒ 玩家点选项而不是自由文本。
3. **历史**：`/alice goals history`（最近 N 条 + 结果码）；JSONL 可离线分析。
4. **默认策略**：按**不变量类别**设 `AUTO / NOTIFY / ASK`（玩家可改、可 `always` 记住）
   ⇒ 避免"每次不变量破裂都来问"（`DECISION_LAYER_DESIGN.md` §6.4 反模式）。

---

## §9 权限与安全（**队列不得绕过**）

- 等级阶梯与区域授权**照旧**由确定性层裁定（`WritePolicyMatrix` + `ZoneAuthority`）；
  **队列条目不带来任何新权限**；
- **安全兜底优先级最高**：维生中断 / 返程（`SafeReturnTask`）/ 站定 **不受队列影响**，
  发生时队列**挂起**而不是被覆盖；
- **LLM 不得批准权限**（只可请求）；**保护区/容器/销毁**类动作须走请示或玩家显式。

## §10 失败与兜底矩阵

| 情形 | 行为 |
|---|---|
| LLM 不可用（未配置/超时/网络失败） | 队列**继续执行**已定条目；需要新条目时 ⇒ 按 `onFail` 收尾 ⇒ 待机 + 告知创建者 |
| 触发被节流/限流/在飞丢弃 | ⭐ **合并补一次**（只保留最近一条，用最新事实重发），并在快照里如实标"丢弃 N 条"；**不排队 N 条** |
| 请示超时 | = 拒绝（既有规则）⇒ 走 §6.4 收尾路径 |
| 容器未注册 | 不进菜单/不生成条目；只可"请示是否登记容器" |
| 材料不足 / 工具坏且无料 | 升级请示；被拒 ⇒ 收尾待机 |
| 终态不可达 | `UNREACHABLE` ⇒ 收尾 ⇒ 待机 ⇒ 不再触发 |
| 世界变化（区块卸载/方块被改） | 执行前复验 → 作废/重规划（§7） |

## §11 验收判据（**将来实现时照这个验**）

**离线门禁（新增步 `goal_queue`，判据示例）**：
1. `TaskSpec` 缺 `successCriterion` ⇒ **拒绝入队**；
2. `precondition` 不满足 ⇒ 执行前拒绝 + 回读原因；
3. 同一条目失败 N 次 ⇒ **禁止再入队 + 升级**（反向对照：去掉检测 ⇒ 变红）；
4. 正常推进 N 千 tick ⇒ **LLM 调用次数 = 0**（这条是提案的**核心收益**，必须有判据）；
5. `history` 落盘 + 重启后仍在（NBT/JSONL 往返）；
6. `MAINTAIN` 不变量破裂 ⇒ 触发一次；恢复后 ⇒ 不再触发；
7. 请示被拒 ⇒ 结束队列 + 收尾 + 待机（世界事实：bot 在归位点且无任务）。

**客户端**：砍树场景全走查（§6）—— 斧坏 → 请示 → 拒绝/允许两条路都能走到"待机且不再触发"。

## §13 明确不做

- ❌ 不让队列携带执行细节（走/挖/放）或新权限；
- ❌ 不做多 Bot 并行调度（`AI_PROJECT_STATE.md`「当前不要做」）；
- ❌ 不让 LLM 用自由文本填队列（必须类型化）；
- ❌ 不用"成功率"评价 LLM（沿用 §6.5：用"玩家少下多少命令 / 请示批准率 / 超时率 / 异常升级率"）。

## §14 待办与临时缺口（**与本文档解耦**，可先做）

| # | 缺口 | 临时方案 | 优先级 |
|---|---|---|---|
| 1 | **保护区里 LLM 自起任务能拿 `L2`** | 等级授予绑定"玩家显式"：保护区内非玩家发起的任务封顶 `L1`（能清障垫脚、拆不了家） | ⭐ 高（实测咬到两次） |
| 2 | 事件环不完整（玩家 stop、启动前拒绝、静默丢弃） | `immediateStop` 补记事件环；启动前拒绝补记；`maybeTrigger` 静默分支留痕 + 快照标丢弃 | ⭐ 高（低成本、根因深） |
| 3 | 跨任务换路重试 | 最小版循环检测（同一区域窗口内失败 ≥N ⇒ 禁止再起 + 升级） | 中 |
| 4 | 可观测性 | （已做）决策层起/停任务通知创建者 + 触发原因；请示/拒绝也补聊天摘要 | 中 |
