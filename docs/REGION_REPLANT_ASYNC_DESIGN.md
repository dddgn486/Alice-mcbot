# 区域补种异步化 + 可配置拾取清单：**设计方案**

> **状态**：**设计已定 · 未实现 · 待实现**（5 项裁定见 §8，用户 2026-09-19 逐项拍定）
> **来源**：用户 2026-09-19 需求 —— **细则原文在台账 `§5.12` 第 13 项**（**以它为准**），
> `D-338` 附注十·补 是同一需求的早期要点版。
> **与主线关系**：**不动权限阶梯、不动 `ZoneAuthority`、不动受理闸**；只扩 `RegionLumberJob` 的
> **巡查状态机（窗口内）** + 一份**区域级配置**。⇒ 风险面小，但有一处**权限放宽**必须用户拍板（§8-①）。

## §1 需求（**细则逐条**，台账第 13 项原文口径）

| # | 细则 | 直译成可验收的行为 |
|---|---|---|
| ① | 砍完**立刻捡原木** | 砍完树 → 走到树基收掉落物 |
| ② | **等待窗口** = **现在的巡查退避/等生长**（**不新开窗口**） | 复用既有 `patrolCooldown`/退避机制，不引入第三种等待 |
| ③ | 窗口内**主动扫区域内地上的东西**：**一次不设上限、扫到区域内捡完为止**，可**反复扫描等待** | 进 sweep 后**清空区域**（不设目标数上限）；清完回到巡查等待，下一轮可再扫 |
| ④ | ⚠️ **补种与扫描不许撞车**（**串行互斥**：扫的时候不补、补的时候不扫） | 同一时刻只处于两者之一（状态机保证） |
| ⑤ | 「该补的种」先记账（已有 `pendingReplant`），**捡够再补** | 记账已有；**攒够**苗再补种，不是"捡到一个就跑去补一个" |
| ⑥ | 身上有苗 ⇒ 砍完**立刻补**（现行为保持） | 有苗不走 sweep，直接补 |
| ⑦ | **不许硬编码树苗** ⇒ **可配置清单**（例：树苗 / 树枝 / 苹果…） | 清单为配置项，默认值不得写死只认橡树苗 |

## §3 缺口

- **① 补种不"立刻"**：`patrolCooldown` 起步 `patrolIntervalTicks`（默认 40），空转时**退避翻倍**
  （40→80→160→320→600）到 `MAX_PATROL_INTERVAL_TICKS = 600`（`RegionLumberJob.java:83`、`:488-496`）
  ⇒ 退避到顶时"砍完立刻补"最坏被推迟 **600 tick = 30 秒**。
  （⚠️ 本方案初稿写"推迟数分钟"，是**错的**：退避有上限 600 tick ⇒ 已按实测常数改正。）
  **缺口 = 补种/扫描这类"有明确待办"的动作不该吃退避间隔**（细则②的"窗口"是**等待**，不是"有活也等"）。
- **③ 缺"按物品类型扫区域"的拾取器** + **缺"区内落物的归属"**（`FOREIGN` 被拦）。
- **⑤ 缺"捡够"的判据**：今天只判"背包有没有苗"（`:634-648`），没有"够不够补完 deficit"的概念。

## §4 设计

### §4.1 巡查状态机（**串行互斥**，细则④）

```
patrol()
  ├─ 对账 mySaplings                     （不变）
  ├─ 扫描 candidates / 算 deficit        （不变）
  ├─ 【D-341】区域内树全被永久拒绝 ⇒ 如实失败（不变，必须仍排在最前）
  ├─ 身上有苗（够 deficit）⇒ tryPlant()   ← 细则⑥，保持
  ├─ 欠树 && 无苗 && 区内地面上有清单内落物 ⇒ RETURN sweep()   ← 细则③（唯一新增阶段）
  ├─ 待机 / 退避                          （细则②：这就是"等待窗口"）
  └─ 选目标 ⇒ harvest()
```

- **互斥**（细则④）：`sweep()` 与 `tryPlant()` 由**同一个 if/else 链**分流，**不会同时进行**；
  sweep 是**独立阶段**，期间不选树、不补种（`current == null` 时才会走到这里）。
- **窗口不新开**（细则②）：sweep 结束后**回到既有巡查/退避**，不引入新的等待类型。

### §4.2 扫描实现：**复用 `CollectDropsTask`**，不新写拾取器

- 目标 = 区域内（`region.containsHorizontal` + `baseY-2 … effectiveTop`）所有 `ItemEntity`，
  且 `stack.is(清单内物品)`。
- 执行 = `new CollectDropsTask(bot, 最近落物, scope, 该簇实体 id 列表, /*allowWorldModification=*/false)`
  ⇒ **只走"走过去 + 原版拾取"**，不挖不垫（不引入新写入面；`D-076` 寻路红线不受影响）。
- **一次不设上限**（细则③）：**不清点、不封顶**，反复取"最近的簇"直到**区域内没有清单内落物**为止
  ⇒ 终止条件是**自然终止**（区域被扫空），不是人为预算。
- **归属问题（本节关键决策）**：区外的历史落物是 `FOREIGN`（默认 `ASK`）⇒ 走过去也捡不起来。
  - **(A) 给区域 mint 一个 `CollectGrant`** ⇒ 区内落物成为 `GRANTED_AREA`（`DropPolicy.java:74-75`）⇒ 可捡。
    几何 = 玩家自己划的区域，随任务生灭。签名与既有用法**已查实**：
    `CollectGrants.add(server, minX, minZ, maxX, maxZ, PermissionGate.Scope.SESSION, "region_lumber", 20*600)`
    —— `Scope` 只有 `ONCE/SESSION/ALWAYS`（`PermissionGate.java:47-49`）；玩家划区用 `SESSION` +
    `20*600`、永久用 `ALWAYS` + `-1`（`CollectGrantItem.java:83-87`、`BotCommand.java:1239-1241`）
    ⇒ 本场景取 **`SESSION` + 任务时长并续期**，任务结束撤销。
  - **(B) 改全局策略** `drop.foreign` ⇒ ❌ **否决**：全世界放宽，与"只在玩家显式划的区里"口径相反。
  ⇒ **推荐 (A)**；但它**确实是"区内拾取权限的放宽"** ⇒ §8-① 请用户拍板。

### §4.3 "捡够再补"（细则⑤）

- `tryPlant` 今天的门槛是"背包里有 ≥1 个"（`RegionLumberJob.java:634-648`）。
- 改为**串行 + 攒够**：sweep 阶段**只捡不补**；sweep 结束（区域扫空）后**回到补种阶段**，
  按 `deficit` 用**已捡到的苗**补 —— 手里有多少补多少（**不要求一次补齐 deficit**：
  区域里能捡到的苗数不一定等于 deficit，凑不齐就如实记着下轮再见）。
- ⚠️ 这**不改**"补种失败即如实失败"的口径：**苗数为 0 且区域里也没有可捡的** ⇒ 仍走
  `tool_missing` **如实失败**（不是静默等待）。

### §4.4 可配置拾取清单（细则⑦）

- **数据**：`LumberRegionState.Entry.pickupItems: Set<String>`（物品注册名），复用**现有 NBT 读写**
  （与 `saplingItem` 同族，跨会话有效）。
- **默认值**：`{ 选定的树苗物品 }` ⇒ 不配置也能"捡回自己砍下的树苗"。
  ⚠️ **不**默认加原木/木棍：原木已由内层 `COLLECT` 收（细则①），重复加只会扩大权限面。
  ⚠️ 细则⑦「**不许硬编码树苗**」：默认值取的是**用户选定的**树苗（`saplingItem`），不是写死
  `minecraft:oak_sapling`；未选定时的兜底也必须**在配置里可见**，不能藏在代码里。
- **用户接口（零参数优先 —— 照 `AGENTS.md` 测试入口纪律）**：

| 命令 | 行为 |
|---|---|
| `/alice region pickup add` | **读主手物品**加入清单（**不要求输 id**）⇒ 符合"禁止长参数串" |
| `/alice region pickup remove` | 读主手物品移出清单 |
| `/alice region pickup list` | 显示清单 + 每项来源（默认值 / 手动加） |
| `/alice region sapling <item>` | **保留**（既有），行为改为**同时**把该物品加入清单 |

## §5 边界与守恒（**先写死，再实现**）

| # | 边界 | 做法 |
|---|---|---|
| 1 | **扫空即止**（细则③，**不设人为上限**） | 终止 = 区域内**没有**清单内落物；不是"捡够 N 个就停" |
| 2 | ⚠️ **但不许"扫不动还一直扫"**（`D-341` 口径：「任务要如实失败，不能继续跑」） | 细则说"扫到捡完为止" ⇒ **做不到就该如实说**：连续 `N` 轮巡查**一无所获且区域落物数未减少** ⇒ `tool_missing`/如实上报（**不是无限重试**）。`N` 待定，建议 **3** |

## §8 裁定结果（**用户 2026-09-19 逐项拍定，5/5 = 设计已定**）

| # | 问题 | **裁定** |
|---|---|---|
| ① | 区内落物归属 | ✅ **A2：只在扫地面期间自动 mint 短 TTL 授权** —— 进 `sweep()` 时对本区域 `CollectGrants.add(..., Scope.SESSION, "region_lumber", 20*120)`，**sweep 结束/离开即自然过期**；不持久化、不新增权限概念、玩家无需每次操作。⚠️ 已知代价（**物理不可避**）：授权期内**旁边**的 `FOREIGN` 物品会被**范围吸附顺手捡走** —— 清单只能决定"走向谁"，决定不了"只捡谁" |
| ② | 缺口①（补种/扫描不吃退避） | ✅ **修**，且 ⚠️ **必须与 ③ 配套**（否则"有活但干不成"会变成 40-tick 高频扫描） |
| ③ | 扫不动的收场 | ✅ **`N = 3`**（与既有 `IDLE_PATROLS = 3` 语义一致，约 120 tick ≈ 6 s）+ ⭐ **新终态码 `sweep_no_progress`**，**带分类后缀**（`(foreign=N)` / `(unreachable=N)`）。**不复用 `tool_missing`** —— 后者语义是"缺执行这件事的东西"，真实原因是"够不着/没授权"时用它就是**撒谎**（与 `D-341 no_permitted_candidate` 同族） |
| ④ | 清单默认值 | ✅ **`{选定树苗}`**（取用户选定的 `saplingItem`，**不硬编码**）；不加树枝/苹果 —— 那属**产出偏好**，由用户 `pickup add` 显式加。⚠️ 已知代价：区域地上会**长期留着**迟到的树枝/苹果/原木（不消失、也不被捡） |
| ⑤ | 接口形态 | ✅ **`/alice region pickup add|remove|list`，读主手物品**（零参数、不输 id）；GUI 归**第 9 件**（区域设置面板），**届时命令保留**（GUI 是便利层，不是唯一入口） |
