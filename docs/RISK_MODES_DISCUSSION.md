# 风险模式讨论（H / G / S）

- 日期：2026-09-09

- 前置阅读：D-024 补充（局部可回收性不变式）、D-045（legacy 任务禁用）、`docs/ALIGNMENT_OPEN_QUESTIONS.md` Q1

---

## 1. 先把"可回收性"分成两层（术语纠偏）

| 概念 | 定义 | 谁来保证 |
|---|---|---|
| **局部可回收性** | 执行一步后，**逆边就在允许集合里**（D-024 不变式） | 落差 ≤1 + 成对的垂直 Movement |
| **全局可回收性** | 从当前状态出发，**存在一条规划**回到已知好状态或继续到目标 | 全局重规划 + 地形 |
| **自我救援能力** | bot 能自己造出退路（挖/放），取决于**背包与权限** | 任务前置 + 资源 |

**关键结论**：Baritone 式做法 = **高风险、局部可回收性较低**（不是"不可回收"）。
它的恢复能力来自另外三条腿：① 全局重规划（`PathingBehavior` 重算）；② 玩家/任务给的资源；
③ 挖掘/放置带来的自我救援。**只要这三条腿在，放宽局部可回收性的实际风险就有限。**

---

## 2. 风险到底由什么决定

风险 = **Movement 语义** × **任务前置** × **世界状态** × **权限**。逐项：

| 风险源 | 局部可回收 | 会被什么抵消 |
|---|---|---|
| 落差 >1（FALL） | ✗ | 有方块（搭出来）、有工具（挖出来）、目标从落点仍可达、玩家在旁 |
| 挖脚下（DOWNWARD） | 需 DOWNWARD 的逆或侧向爬出 | 有方块/工具；脚下不是承重沙砾/流体 |
| 垂直上升（PILLAR） | ✗（单独存在时） | 有 DOWNWARD 成对；有方块 |
| 破坏（BREAK） | ✓（可走回，但方块已毁） | 保护区域/权限、资源回收 |
| 放置（PLACE） | ✓ | 一次性方块白名单、数量 |
| 进入流体 | 部分 | 水深/岩浆、逃生路线 |

**你的论点（成立）**：任务启动本就有前置——挖矿必须准备工具与方块（玩家给或从标记箱子取）。
在这些前置满足的前提下，套用 Baritone 模式的**增量风险**并不大：bot 掉进坑里可以自己挖出来/搭出来。

所以正确做法不是"全局一刀切保守"，而是：**把风险开关绑到任务前置上**。

## 3. 三种模式

### H 模式 —— Baritone 式（高风险 / 较低局部可回收性）
- 允许：落差 ≤3（`maxFallHeightNoWater=3`）、挖脚下、PILLAR、破坏/放置、对角切角、疾跑。
- 局部可回收性不保证；恢复依赖全局重规划 + 前置资源 + 自我救援。
- 适用：**前置明确的任务**——挖矿（有镐+方块）、野外推进、玩家在旁跟随。
- 代价：需要 Alice 版 `PathExecutor` 下落特例（下落中改水平距离判定）+ `MovementFall` 的落点列。

### G 模式 —— 守卫式（较低风险 / 高可回收性）
- 允许：落差 ≤1、垂直下 1 格（DOWNWARD，**纯下落不挖脚下**）、PILLAR **仅在与 DOWNWARD 成对时**、
  破坏/放置（带保护区域门禁）。
- 每个放宽都带**守卫**：
  - 落差守卫：落点旁存在可站格（或落点能用 ≤1 格移动回到原层）；
  - 挖脚下守卫：脚下方块非承重沙砾/流体、且存在侧向逃生；
  - 资源守卫：背包方块/工具不足时拒绝"需要自我救援"的动作。
- 适用：**前置不明确或高风险场景**——未知地形探索、城市/建筑附近、玩家旁、无资源。
- 代价：地形覆盖小，某些目标会判 `UNREACHABLE`（这是**诚实**的，不是缺陷）。

### S 模式 —— 智能模式（推荐默认）
- 以 G 模式为基线，**按动作、按前置、按世界状态逐条提升**：
  - 若 `落点有逃生路线` **或** `bot 有 ≥N 方块 + 工具（自我救援能力）` **或** `从落点可达目标` → 该条 FALL 放行；
  - 若 `脚下方块非承重/无流体` **且** `存在侧向逃生 或 DOWNWARD+PILLAR 成对` → 挖脚下放行；
  - 若 `有 DOWNWARD 且方块 ≥1` → PILLAR 放行；
  - 若 `任务声明已备好工具/方块`（前置满足）→ 直接提升到 H 的子集。
- 每次提升都**记录原因**（日志 `[Risk] promote fall>1 reason=resource_backed blocks=8`），
  让"为什么这次冒险"可审计。
- 适用：绝大多数情况。**默认模式**。

## 4. 风险开关（可自选）

| 开关 | 取值 | 说明 |
|---|---|---|
| `maxFallHeight` | 0 / 1 / 2 / 3 | 0=禁止任何下落；3=Baritone 上限；>3 永不（摔伤） |
| `fallGuard` | NONE / ESCAPE_ROUTE / RESOURCE_BACKED / PROVABLY_REACHABLE | 下落守卫级别 |
| `allowDigUnderFeet` | 关/开 | 挖脚下方块（DOWNWARD 的挖掘变体） |
| `digUnderFeetGuard` | NONE / NON_LOAD_BEARING / NON_LOAD_BEARING_AND_ESCAPE | 承重/流体/逃生检查 |
| `allowPillar` | 关/开（仅 DOWNWARD 可用时） | 垂直上升 |
| `allowBreak` | 关/开 | 破坏（保护区域门禁始终生效） |
| `allowPlace` | 关/开 | 放置（白名单 + 数量） |
| `allowFluidEntry` | 关/开 | 进入流体 |
| `allowDiagonalCornerCut` | 关/开 | 单侧绕角（Baritone optionA/optionB 语义） |
| `allowSprint` | 关/开 | 疾跑（对齐 Baritone 的速度前提） |

**模式 = 开关的预设**；任务层（未来 LLM）可逐项覆盖。
选择入口建议：**任务声明前置 → 内核推导默认开关 → LLM/玩家可覆盖**。

## 5. 不可协商的安全底线（任何模式都不开）

1. 落点即死（熔岩/火/岩浆块/仙人掌/虚空）——永不；
2. 落差 >3（摔伤）——永不；
3. 保护区域内的破坏/放置——永不；
4. `SEARCH_LIMIT` ≠ `UNREACHABLE`；未知模组能力只读；
5. 落点上方有即将掉落的 `FallingBlock`（窒息）——永不（已有 Ascend 检查）。

## 6. 实际应用分析（按任务类型）

| 任务 | 前置 | 建议模式 | 理由 |
|---|---|---|---|
| **挖矿 MineTask（HARD_PATH）** | 镐 + 方块（玩家给或箱子取） | **H**（或 S 提升） | 挖脚下/落差/竖井是任务本身；有工具即能自我救援 |
| **跟随 FollowTask** | 玩家在旁 | **S** | 玩家可能跳下 3 格；bot 无资源时要守卫，玩家在旁可救援 |
| **搬运/取物 TransferTask** | 标记箱子、建筑内 | **G**（破坏/放置关闭） | 保护区域、不能改建筑 |
| **WalkTo（玩家指定坐标）** | 未知 | **G** | 无前置承诺，安全优先 |
| **探索/未知地形（LLM）** | 无 | **G** | 不知道有什么；先侦察再冒险 |
| **建路 RoadBuilder** | 方块充足 | **H 的子集**（放置开、破坏开、落差 ≤1） | 有资源，但目标是铺路而非穿越 |

**结论**：模式不是一个全局常量，而是**任务前置的函数**。这也是 Alice 相对 Baritone 的优势——
Baritone 是"一个玩家 + 一套设置"，Alice 是"任务声明前置 + 内核按声明选风险"。

## 7. 数据采集（决定默认值的依据）

在 `PathingStats` 基础上加计数（只读）：

- `fall_taken_1/2/3`：实际发生的落差分布；
- `fall_refused_gt1`：因落差被拒的次数（= S1 的代价）；
- `dig_under_feet_used/refused`；
- `pillar_used`；
- `stuck_events`：任务最终因"局部卡死且全局不可达"失败；
- `promote_*`：S 模式提升次数与原因。

有了这些，才能回答"G 模式让多少目标变成 UNREACHABLE、H 模式换来多少成功率"。
