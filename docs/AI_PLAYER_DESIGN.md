## 1. 目标与定位

### 1.1 愿景

为 Minecraft **复杂整合包玩家**打造一个由服务端事实与确定性执行器约束的游戏内 AI 助手，覆盖三条产品主线：

1. 通用玩家助手：采集、战斗、跟随、安全区、巡逻和其他跨整合包常见任务；
2. 无 AE 自动合成阶段：执行玩家定义的流水线搬运与生产订单，不自动猜测或搭建流水线；
3. AE 自动化阶段：通过 AE2 适配器完成网络观察、存取、样板编写与管理。

LLM 用于理解目标、选择已注册工具与处理异常；它不能替代移动、库存事务、机器语义适配器或服务端验收。

### 1.2 为什么现有方案做不到（一句话摘要）

| 现有方案 | 致命短板 |
|---|---|
| Voyager / Mindcraft（协议 bot） | 感知走协议（慢）、任务逐格指挥（低效）、看不见模组 GUI |
| mc_aiplayer / numen（游戏内模组） | 执行层漏洞多（站位/搜索/拾取）、任务写死、点不了 GUI |
| Cradle（视觉 GUI） | 慢、脆、无 MC 模组 grounding 数据 |

### 1.3 本项目的差异化支柱

1. **目标级智能 + 确定性执行**：LLM 负责目标、约束、候选路线与异常重规划，执行器负责动作、资源、权限和完成验收。
2. **服务端语义接口**：不依赖视觉点击 GUI；从服务端 capability、模组 API 和适配器暴露可读、可验证的语义操作。
3. **玩家/整合包可注入规则**：任务参数、流水线端点、机器角色和生产偏好由预设、整合包档案和世界档案结构化提供。
4. **本地知识优先**：将教程和官方说明精炼为版本化指导手册，外部 RAG 只在缺失或冲突时按需使用。

通用 capability 主要提高只读发现覆盖率；复杂机器的槽位、模式、催化剂、副产物和写操作仍需要配置或版本化代码适配器。项目不承诺“读接口 + 教程即可安全操作任何模组方块”。

### 1.4 明确不做的事

- ❌ 不做"视觉点击 GUI"路线
- ❌ 不追求让模型从原始世界数据自主推理一切
- ❌ 不逐格指挥挖掘/建造

## 2. 系统架构总览

```text
玩家自然语言 / 参数面板 / 预设方案
              |
              v
      决策层（异步 LLM）
  目标解析 / 候选选择 / 异常重规划
              |
        ToolCall / PlanDraft
              v
      Policy Gate / Plan Validator
 schema / 权限 / 预算 / 资源 / 版本 / 风险
              |
              v
  Task / Production / AE Orchestrator
   事务状态 / 作用域 / 恢复点 / 熔断
              |
              v
 确定性执行器 + 版本化模组适配器
移动 / 挖掘 / 攻击 / 搬运 / 机器 / 样板
              |
              v
 Server World / Capability / Mod API / Events
              |
 Observation / Inventory Delta / Execution Record
              +---------------------> 决策反馈
```

**核心原则**：
- 感知/执行全部在**服务端**（权威数据）；客户端仅作为 GUI 信息展示（可选）
- AI 调用异步，游戏主线程永不等待网络
- 事实由代码验证，不由模型声称

## 3. 感知层设计

### 3.1 数据源

- 服务端 `Level`/`ServerLevel` 直接读取：`getBlockState` / `getEntities` / `getBlockEntity`
- capability 读取：`IItemHandler` / `IEnergyStorage` / `IFluidHandler`

### 3.2 任务作用域缓冲区（Task Scope Buffer）

- 任务启动时注册**局部订阅区域**（BoundingBox）：
  - BlockChange 事件（外部扰动/自挖进度）
  - EntitySpawn 事件（掉落物坐标实时追踪）
  - BlockEntity 数据变化（机器 IO / 完成信号）
- 用途：掉落物精准拾取、垫脚石事后清理、机器完成信号、抗外部扰动
- 全局保持**低频宏观快照**（供 LLM 决策），任务内用**高频事件流**（供执行器微调），避免全量扫描卡 tick

### 3.3 上下文压缩：分类聚合 + 任务视角 Profile

- **只推任务相关局部窗口（N×N×N），符号化压缩**；差异推送：只发变化部分，稳定前缀命中 prompt cache（省钱）
- **分类聚合**（已落地）：把原始方块流按语义归类成四类摘要，而不是逐格列表——
  ① 目标（任务在乎的方块，列坐标）② 危险/障碍（岩浆/水/黑曜石等，列坐标）
  ③ 意外收获（刷怪笼/宝箱/贵重方块，列坐标）④ 普通（仅聚合计数）。
  上千个方块 → 几十行结构化文本
- **任务视角 Profile**（已落地）：换任务 = 换 Profile（目标标签集合 + 范围），
  分类与摘要逻辑不变——这是「按任务自动调整感知权重」的落点。
  当前预置 `MINING`（原版 8 类矿石标签）与 `GENERAL`；建造/探索视角后续补
- **分类规则可扩展**（待做）：危险/收获集合当前硬编码，后续下沉为可注册规则，供模组适配器
  注入本整合包特有的关注方块（如「格雷科技矿脉」「AE2 控制器」）

## 4. 执行层设计

### 4.1 借鉴与教训来源

- mc_aiplayer 精读（已定位 4 类执行缺陷，详见笔记 §3）
- Baritone 的寻路/方块空间分析思路（可参考，不照搬）
- Carpet 假人的"服务端模拟真实玩家"范式

### 4.2 四条验收标准（所有执行器必须满足）

| # | 标准 | 对应缺陷 |
|---|---|---|
| 1 | 任何目标方块先有「可达站位点」才开工，挖掘前做视线无遮挡检查 | 隔空挖、站位卡死 |
| 2 | 目标搜索必有排序（距离/暴露/可达性），暴露方块优先 | 随机乱逛、挖泥开路 |
| 3 | 任务完成 = 产物入包（掉落物追踪到账），非"动作发生过" | 掉落物丢失 |
| 4 | 多 tick 动作前做环境前置检查（流体中/悬空/位移） | 水中沉浮打断 |

### 4.3 动作执行

- 服务端直接发协议包/调世界 API（参考 mc_aiplayer 的 `ActionPack` 模式）
- 动作进队列，主线程按 tick 消费，不阻塞
- 失败回传审计（成功/失败/耗时），失败即重规划，成功沉淀技能

## 5. 服务端接口序列化（核心 spec 草案）

### 5.1 接口来源分两类

| 类型 | 生成方式 | 覆盖能力 |
|---|---|---|
| **只读事实接口** | 扫描标准/模组 capability，生成 `read_inventory` / `read_energy` / `read_fluid` 等 | 广泛发现基础事实，但不推断槽位业务语义 |
| **配置驱动接口** | 整合包/玩家定义端点、槽位角色、完成条件和流水线 contract | 覆盖玩家已定义的半自动流水线 |
| **模组原生操作接口** | 版本化适配器注册（可镜像成熟 Computer API 或官方 API） | 提取、配置模式、样板等可验证操作 |

### 5.2 接口 JSON 格式（v0.1）

```json
{
  "id": "tango_mod:crystal_fusioner/extract_output",
  "display_name": "取出输出产物",
  "gui_hint": "相当于打开晶体融合器界面后,左键点击输出槽取出产物",
  "input_schema": { "type": "object", "properties": { "max_count": { "type": "integer" } } },
  "output_schema": { "items": [ { "id": "tango_mod:intelligent_ingot", "count": 1 } ] },
  "side": "server",
  "permission": "owner"
}
```

- `gui_hint`：**本接口在 GUI 上对应玩家什么操作**——AI 学习的关键语义标注
- `permission`：操作需玩家授权/白名单

### 5.3 ⚠️ 待决策点

1. **拦截层位置**：在 `AbstractContainerMenu` 层做通用代理，还是下沉到 capability 层？（前者覆盖容器操作，后者更通用）
2. **接口发现协议**：AI 如何拉取"这个方块有哪些接口"？（建议：方块旁静态扫描 → 返回 JSON 清单，作为工具 `list_block_interfaces`）
3. **权限模型**：默认只读开放 + 操作需确认？还是玩家可设信任等级？

### 5.4 已定决策（2026-08-16）

1. **拦截层**：以 **capability 层为主**（更通用，覆盖非容器机器；Menu 层代理作为容器类操作的补充拦截点）。
2. **接口发现协议**：方块旁静态扫描 → 返回 JSON 清单，暴露为工具 `list_block_interfaces`。
3. **权限模型**：玩家**信任等级制**——只读接口默认开放；操作接口按等级：owner 自动 / 好友确认 / 其他拒绝。

## 6. 决策层设计（AI 行为）

### 6.1 工具接口（function calling）

- 模型默认只看到目标级任务（如 `mine_resource` / `produce_item`）、查询（如 `list_interfaces` / `get_task_status`）和已验证的生产/AE 工具。
- `move_to`、`mine_block` 等动作原语属于编排器内部能力，不作为常规 LLM 工具暴露；诊断或受控恢复如需暴露，必须有独立权限、预算和工作包。
- ToolCall 先经过 `Policy Gate / Plan Validator`，再进入任务编排器。模型选择工具和参数，代码验证 schema、权限、资源、世界版本和后置条件。

### 6.2 模型路由（已定：本地高频 + 云端低频；配比后续实测调优）

- 高频微决策（挖哪格/往哪走）：本地小模型或规则引擎，毫秒级
- 目标规划/异常/人设回复：大模型，低频异步
- 候选：Ollama + Qwen 系列本地推理；云端沿用 DeepSeek/中转均可（配置化）
- 参考：Mindcraft 的 Ollama 支持；Roblox 云端异步模式

### 6.3 记忆三层

1. 知识库：合成表/方块属性/接口清单 → 本地结构化库（不进 prompt，检索注入）
2. 技能库：成功动作存成带参宏（Voyager 思路）
3. 情节记忆：任务历史摘要 + 反思

### 6.4 回复风格（两段式）

- 任务完成汇报：**固定词块**（信息准确）
- 语气包装：按人设二次调用模型生成完整回复（情感层）

## 7. 知识层设计（指导决策，不替代适配器）

### 7.1 本地版本化知识

- **事实库**：注册表、标签、配方、接口 schema 和世界标记，由代码读取并可验证；
- **指导手册**：从官方说明、目标网站教程和已验实践精炼出的短文档，记录来源、版本、前置、风险和可调用工具；
- **运行经验**：特定世界任务的成功/失败与玩家修正，用于路线评分，不自动获得执行权限。

AI 遇到未知机器时可以调用 `list_block_interfaces` 并检索指导手册，但 `gui_hint` 与教程只能帮助选择已注册工具。若缺少对应 handler、权限或后置验收，系统只能只读报告或请求适配，不能由模型临时生成写操作。

### 7.2 外部知识检索（RAG，按需触发）

| 数据源 | 用途 |
|---|---|
| MC 百科（MCMOD.cn） | 中文整合包/模组教程、流程指引（用户偏好） |
| 模组更新日志 | 版本变更、配方移除（时效性陷阱） |
| 官方 Wiki | 机制细节（GT 电压/超导/AE2 频道） |

- 按需触发 + 结果清洗 + 本地缓存；稳定内容进一步精炼为带来源和版本边界的本地指导手册。
- 外部结果默认是未验证知识。服务端实时事实 > 注册适配器契约 > 本地版本化知识 > 外部 RAG > LLM 推断。

## 8. 流水线应用：手搓期「模拟 AE」+ AE 期「三件套」

> 功能计划（2026-08-16）：针对科技/魔法整合包的**两大阶段**分别设计 bot 的核心应用。

### 8.1 背景：整合包的两大阶段

1. **手搓阶段**（无 AE 自动化）：半自动流水线、被动生产线，结构不定、复杂多样，AI 难以自动读懂；
2. **AE 自动化阶段**：全套 AE2 网络，机器人可用的操作高度标准化。

### 8.2 手搓阶段：「模拟 AE」（玩家定义，AI 规划，执行器验收）

- **核心原则：Alice 不自动理解或搭建流水线**。玩家/整合包档案把现有流水线登记为版本化 `PipelineProfile`；LLM 只在已登记工艺中选择路线和批量。
- `PipelineProfile` 不只是输入/输出坐标，还必须引用 `ProcessContract`：输入端点、输出/缓存端点、机器模式、固定/可替代输入、催化剂、容器返还、概率消耗、主/副/概率产物、容量、能源、完成条件、超时和人工接管条件。
- 物品搬运使用事务状态：`reserved -> extracted -> in_transit -> inserted -> verified`。任何阶段失败都必须知道物品当前归属，不能靠重复操作处理吞物、复制或混料。
- 多条生产路线由确定性规划器从已登记 contract 生成候选并按库存、时间、能源、稀缺资源、概率风险和玩家偏好排序；LLM 可以选择或解释候选，不能发明槽位、机器模式或配方。
- 对随机工艺，执行器根据实际库存和机器状态重复批次直至满足目标，同时受最大投入、最大批次、时间和保留库存约束；平均概率不能作为完成证明。
- **效果**：bot 像一个受审计的“模拟 AE”搬运与订单执行器，不搭线、不猜结构、不静默改变机器配置。

### 8.3 AE 阶段：AE 网络助理

- **目标**：通过固定版本 AE2 适配器完成重复但规则复杂的工作：
  1. **网络观察与存取**：识别明确网络和权限，读取库存/合成状态，按事务执行存取；不能仅因某 handler 可访问就认为可安全抽取。
  2. **撰写样板**：JEI/配方管理器只提供候选。玩家规则或适配包必须定义精确/可替代输入、crafting/processing 类型、数量、容器返还、催化剂、概率消耗/产出和优先路线；写入前生成预览和验证结果。
  3. **管理与放置样板**：读取网络拓扑、频道、机器连接、端点能力、锁槽和玩家标记的机器角色；不能只看样板供应器名字。无法证明匹配时只给建议，不直接放置。
- **定位修正**：这些能力属于 Alice 的产品主线，但必须依赖 AE2 专用、版本化、可降级的 `ModAdapterPack`，不能由通用 capability 或教程自动获得。

### 8.4 与「酒狐 agent」的对照

- 酒狐（B站 AI agent，演示机械动力配方自动合成）**无公开开源仓库**，机器结构定位机制不可核实——推测同为"人工标记/蓝图式"路线（机械动力多方块动力网络自动识别难度极高）。
- **本项目结论**：与其赌"自动识别复杂结构"，不如走**玩家标记 + 严格定义**（8.2），把不确定性关进笼子里；识别能力留给"单方块机器 + capability 扫描"（§5）这种可标准化的场景。

### 8.5 扫描效率与记忆存储（回应性能担忧）

**关于"机器密度高、扫描接口慢"**：
- 方块数据读取本身是 O(1) 纳秒级（`getBlockEntity` + capability 是哈希查找），**密度不拖慢单点读取**；
- 慢的是"全区域逐方块扫描 + 逐方块识别"。规避方案：
  1. **按需扫描**：只在任务需要时扫描，绝不全图后台轮询；
  2. **事件失效缓存**：扫描结果进本地缓存，`BlockChange` 事件使相关条目失效，不重复扫；
  3. **玩家标记优先**（8.2）：标记过的机器直接命中，跳过发现环节。

**关于"关键性方块记忆存储"**：
- 分层存储，不塞 prompt：
  | 层 | 内容 | 介质 |
  |---|---|---|
  | 世界常驻知识 | 玩家标记的流水线/机器、接口清单、坐标 | 本地 SQLite（随世界存档） |
  | 扫描缓存 | 近期扫描结果（含失效机制） | 内存 + 磁盘缓存 |
  | 任务上下文 | 当前任务涉及的方块数据 | 任务作用域缓冲区（§3.2） |
- 原则：**关键方块（标记过的）持久化记忆，普通方块按需缓存**；检索注入而非全量塞入。

## 9. 产品驱动的阶段路线

完整路线和进入条件见 `PRODUCT_ARCHITECTURE_ROADMAP.md`。里程碑不再只按技术层排列，而按可用闭环推进：

| 阶段 | 主要产出 | 验收重点 |
|---|---|---|
| **A 可靠执行内核** | 任务请求/策略/结果、移动能力、站位、库存事务、安全与回收 | 服务端事实闭环，无隐式权限扩大 |
| **B 通用玩家助手** | 挖矿/木材、动物食物、作物、跟随、安全区、巡逻、保护、钓鱼等独立任务 | 每项逐场景验收，不共享未验证移动能力 |
| **C 语义接口与搬运** | 结构化只读 snapshot、权限、端点 descriptor、物品转移事务 | 物品守恒、失败可定位、接口只读/写入边界明确 |
| **D 玩家定义流水线** | `WorldProfile`、`PipelineProfile`、`ProcessContract`、订单执行 | 固定工艺先行；催化剂/副产物/随机工艺分阶段加入 |
| **E 目标模组适配包** | 按固定版本提供机器语义与确定性 handler | 每个模组声明 C0-C5 兼容等级和降级策略 |
| **F AE 网络助理** | 网络观察、存取、样板预览/写入、拓扑感知管理 | JEI 非真值；样板和放置均可审计、可失效 |
| **G LLM 与本地知识闭环** | 异步目标规划、参数面板、指导手册、按需 RAG | 模型只调用已注册工具，事实与权限由代码验证 |

阶段可有限并行，但共享移动、库存事务、权限和结果契约必须先稳定。知识/RAG 可以早做只读原型，不得早于适配器获得机器写权限。
