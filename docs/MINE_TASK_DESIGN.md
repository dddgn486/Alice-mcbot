## §2 扫描契约（阶段 1.1/1.2 的**硬要求**，先写死再实现）

| # | 契约 | 判据（**可失败**） |
|---|---|---|
| S1 | **未加载 ≠ 没有**：扫描器内部逐格 `level.hasChunkAt(pos)` 守卫；未加载的格子记 **「未扫」**，**不许**记成"无矿" | 夹具：目标列落在未加载区块 ⇒ 结果里出现 `未扫` 计数 > 0 **且** `没矿` 计数 == 0；反向对照（去掉守卫）⇒ 出现"没矿"或区块被加载 |
| S2 | **不加载区块**（`D-132`：内核从不加载区块） | 扫描前后 `hasChunkAt` 对**先前未加载**的坐标为 `false`（与 `WalkToTask` 修法同一判据） |
| S3 | **`SEARCH_LIMIT ≠ UNREACHABLE`** | 搜索预算耗尽 ⇒ 归因码只能是"搜索受限"，**不得**触发任何"那就挖过去"的路径（门禁/夹具断言无 `TUNNEL_*` 授权） |
| S4 | **分片扫描**：大范围扫描必须能"边扫边记"（时间上分片），单 tick 不做 `(2r+1)³` 全量 | 单 tick 读格数 ≤ 上限（夹具逐 tick 取计数）；跨 tick 结果**幂等合并**且去重 |
| S5 | **记忆载体**：跨 tick/跨任务的"已扫过"必须**可持久化且有界**（`D-329` ①「大范围靠时间 + 记忆累积」） | 落盘往返后"已扫过"集合不变；超过上限时按**确定性顺序**淘汰（不许随机） |

## §3 作业区 / 意图（阶段 1.5，解 `Q2/Q3`）

- **为什么需要**（`D-329` ④）：向下偏置**不来自加载策略**，来自 ① 成本函数形状（向下最近、挖一格就自我扩张候选）、
  ② `GoalSpec.center` 固定（候选吃干即 `no_reachable_candidate`，**不会自己换地方**）、③ 可见性偏差（只扫"已存在"的方块）。
  ⇒ 需要**作业区/方向/层位意图**来消偏；**没有通道能力时**，水平探索只能沿**已有可通行地形**走 ⇒ 与 §4 配对。
- **形状**：`GoalSpec` 扩 `作业区（中心/半径/形状）· 方向 · 层位/Y 范围 · 时长预算`；
  **意图层与执行层分离**（意图层回答"在哪挖、挖到什么程度"，执行层回答"怎么过去、怎么挖"）。
- **骨架可抄** `RegionLumberJob`（区域 + 漂移检测 + 巡逻 + `/alice region` 的玩家入口形态）——**不新造**。
- **判据**：同一场景、同一预算下，带作业区意图 vs 不带 ⇒ **水平位移分布**可区分（夹具统计目标格的 X/Z 分布），
  且**向下格占比**下降（数值判据，不靠观察）。

## §4 通道能力（阶段 2.5）—— **不是授权问题**（`Q1` 定案）

`D-329` ③ 的三条硬理由：① 清障语义 = 为**已规划站位/视线/立柱**腾位置（`D-115`），深度上限
`maxDepth = floor(reach+1.54) ≈ 6` 是**结构性**的；② 授权面上"边走边挖"**早有生产用户**（`P-03` = 掉落物收集）
⇒ 缺的是**授权 + 承诺**，不是额度；③ ⚠️ **与直觉相反**：`MineJob:280` 用 `TUNNEL_ALLOWED.withRestore()`
且**没有 `withClear(...)`** ⇒ **挖矿今天清障预算 = 0**；伐木才是 `MAX_CLEAR_PER_TREE = 8`。

⇒ 正确形状 = **`D-327`**：**成本模型 + 一个 movement 信封 + 回程兜底**。
**三种承诺**（同一动作的三种世界承诺，**不是同一预算的三个档**）：**清障** `PATH_ACCESS`（挖掉**要还原**，TEMP + `RestoreScope`）·
**通道**（**不还原 + 必须能自己走回来**）· **修路**（**要保留**，路就是产物）⇒ 表达位置 = `WritePolicyMatrix.Obligation`。
**可回收性**（`D-024/D-151–153`）天生是给**通道挖掘**准备的 —— 它今天像孤岛，是因为它的消费者**还没出生**。

**判据**：① 通道挖掘的任务终态必须能证明"**走得回来**"（回程兜底的夹具：挖进去后强制折返）；
② 三种承诺的账本义务不同（`TEMP` 可回收 / 通道不还原 / 路保留）**逐条断言**；
③ 反向对照：把承诺错标 ⇒ 账本义务判据变红。

## §5 收集与对账（防"挖了没拿到"）

- **授权**：掉落物归属只由 `DropPolicy.effectiveProvenance`（我方 / `GRANTED_AREA` / `FOREIGN`）决定（`D-138`）；
  **不许**因为"是我挖的"就跳过授权面。
- **对账**：`JobKindContract` 的 `MINE` 行已经是**运行时受理闸 + 门禁核对**的形态（`D-349`）——
  `successCriterion` = 「目标方块真的被破坏 ∧ **目标物品进背包** ≥ 已破坏数」⇔ `MineJob#countTargetItems`；
  不一致 ⇒ `FAILED product_not_collected`（挖了没拿到 = **没成功**）。
- ⭐ **教训（必须写进实现）**：`D-348` 证明"事件当刻实体不在查找表里"**不等于**"它不存在"——
  掉落物**登记会被推迟 1~19 tick**。任何"以查找表/代理判据下结论"的新代码都会重犯这个错。
- **判据**：`mine_run_metrics`（`D-347`，24 条判据）已覆盖"到达率 / 平均 tick / 世界改动对账"；
  新增大范围模式时必须**扩它的场景**，不许新写一套口径。

## §6 失败归因（`M4` 先于 `M3`）

- **`M4` 结构化失败归因**：失败码是**枚举/常量 + 结构化字段**，**禁止** `contains("...")` 自由文本匹配；
  顶层归因只在"全失败同因"时上抛（沿用 `deriveTopLevelReason` 的**语义**，不沿用它的**实现**）。
- **`M3` 转向/中止收尾**在 `M4` 之后（否则转向就建在脆弱判据上）。
- **判据**：门禁断言"没有新的 `contains(` 归因"；夹具断言每个失败码都能**逐条归因到世界事实**（不是字符串）。

## §8 红线与边界（**不许夹带**）

| 红线 | 对本设计的要求 |
|---|---|
| `D-076` 寻路默认**纯通行** | 破坏/放置只能由上层任务显式授权 + 受预算闸门约束；禁止寻路器自行挖穿、禁止把 `SEARCH_LIMIT` 当授权 |
| `D-076` 挖掘站位例外 | `PathRequest.miningApproach` 允许 `BREAK_AND_TRAVERSE/BREAK_AND_ENTER/PLACE_STEP_AND_TRAVERSE`，**禁用 `PILLAR/FALL/DOWNWARD`**；超预算 ⇒ `found_but_unminable`（如实失败） |
| `D-333` 守卫线**冻结** | ❌ 不动守卫形态、不做任务预设、不暴露可调试接口 ⇒ **挖矿路线图里不许夹带** |
| `D-329` ① 两个口径 | 扫描边界 = **不加载**；价值/优先模型 = **用户给**（可配置 + 结构性默认） |
| `D-219` 需求驱动 | 不为"覆盖率"适配模组；模组矿物靠 `MineProductFilter` 的**目标驱动 + 标签族兜底**，不硬编码清单 |
| `D-336`/`D-341` 权限与"无权≠没有" | 候选全被**永久拒绝** ⇒ 如实失败（`no_permitted_candidate`），**不许**当成"没矿"空转 |
